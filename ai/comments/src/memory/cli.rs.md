# cli.rs

- `Runtime`: how commands reach the compactor's model, stdin and stdout. Default: Claude Code (`ClaudeCode::compactor`), spec options, `summarise_on_note` unless `AI_MEMORY_SUMMARISE=0`, `terminal` false. `exec` sets `terminal` from stdout. Tests pass a fake backend and turn the trigger off; the binary tests set `AI_MEMORY_SUMMARISE=0` in the sandbox (one test turns it on with a fake `claude` script on `PATH`).
- `view [--part N] [--at <commit>]`: `view_text` renders `cover(t, VIEW_LINES)` (OptMem's tiling, `cover.rs`) under date headers, then "You are awake. Zoom the marked lines that touch your task before you act." (an empty memory: how to record the first note, then "You are awake."). Printed by `page::print` (page.rs.md): whole on a terminal, else in parts ending `Next: ai memory view --part <k> --at <commit>` with the `Meta` flags repeated. `--at` reads the snapshot of that commit (`Store::snapshot_at`, store.rs `Mark`), so a note or summary landing between parts cannot shift the cut; later notes show on the next read. Never refuses: an unbuilt block shows its halves instead (`view_lines`), down to messages; empty (tool) lines are skipped. The incremental fold (`Mem`, `VIEW`) is not used here: it is OptChat's 64k-token chat view, far too big for every session start.
- `view --whole` (hidden plumbing, `Cli::view_whole(mark)`): the whole view of one state, for `ai view` (src/view.rs.md), which does its own paging. Logged as `view` with `--at <commit> --whole`.
- `note`: one line, ≤ `ENTRY_CHARS` bytes (cap `NOTE_MAX` = `NODE` = 512, the leaf being the bare note), so a note is always its own (free) leaf. A longer one is refused with the byte count and the ways out: compress it, or split it into separate notes. The setup block prints the configured limit. After saving, if a node is due, spawns a detached `ai memory build` (own process group, stdin and stdout null, stderr appended to `<memory>/summarise.log` so panics are kept; the summariser writes its own structured events there) and returns. Prints no summarise prompt. The setup block tells agents to keep dates, repos and sessions out of notes: the header records them.
- `build`: runs the compactor until nothing is due on the latest snapshot. Only one compactor per memory (`compact.lock`, see compact.rs): a summariser that cannot take the lock exits at once ("exit", not "wait", so note-spawned summarisers never pile up). Each round ends by releasing the lock (`drop(c)`), then re-checking `pending` on the latest snapshot and try-locking again if anything is due. No note is ever left unbuilt: a note's commit happens before its summariser's try-lock; if that try-lock fails, the holder releases later, so its re-check sees the commit and either builds it or loses the lock to a summariser that took it after the commit and loads a snapshot containing it. `Runtime::before_release` is the test seam for this interleaving (`a_note_whose_nap_finds_the_lock_taken_still_gets_built`). A fresh backend per round: dropping a compactor stops its backend for good (`Live::kill_all` closes it), so a second round must not reuse it. Created only when something is due. Failures: printed once per node ("Retrying up to N times, waiting longer each time"), retried with backoff (compact.rs.md, Retries). When a node runs out of retries the compactor returns `GaveUp`; `summarise` logs one ERROR `gave up` (node, tries, error), prints "Gave up on … It stays pending; the summariser after the next note tries again.", and exits 1 (`ExitCode::FAILURE`, not an `Err`, so `main` prints nothing more). The compactor is dropped on the way out of `rounds`, releasing the lock. A hand-run summarise has the same bound: no infinite mode, since the next note (or another `summarise`) retries anyway and a person at the terminal gains nothing from endless retries.
- `zoom`/`show` take a line id as printed: `id+n`, or a bare `id` for one message (`Coord::parse`; `id+1` reads the same). `line_id` validates against `T`; a bad one is refused as "No line <as typed>.". `zoom` output follows spec §7.1.
- `zoom <id>`: printed by `page::print` as `view` is: whole on a terminal, else in parts ending `Next: ai memory zoom <id> --part <k> --at <commit>`.
- `note` prints "Saved as <id>.", `import` "Imported N notes, <first> to <last>.": bare ids, as the view prints them.
- `import`: `YYYY-MM-DD <text>` lines → `note` messages at UTC midnight, any length; dates must not go back within the file (checked here, with the line number). Against the store the order is the store's own check (store.rs.md, Time order), so an import dated the same day as a note already logged after midnight is refused: it would break time order.
- `Cli::exec` / `broken_pipe`: a closed stdout is not an error.
- `build` logging: `log::init` once at its start (events to `summarise.log`, also for a hand-run `build`, whose stdout messages are unchanged), a `summarise` span with pid, model (`claude::model()`, so a test fake backend still shows the configured model) and dir; INFO `start`, `busy` (lock held, exiting), `end` (built, secs); ERROR `failed` if a round errors otherwise; ERROR `gave up` instead of `end` when retries run out. `rounds` is the old loop, returning the count built.
- Metadata in lines (`view`, `zoom`, `grep`): lines grouped under date headers, each `id|text` or `id+n|text` with an inline `..MM-DD` when it runs past its header's day, and `--time` and `-o FIELD,...` from one flattened `Meta` (meta.rs.md has the format). Every next-part command repeats the flags (`Meta::flags`), so a multi-part read keeps its format.
- Budget: `view`'s budget is `VIEW_LINES`, a line count (OptMem's cover), not bytes, so the prefix changes no line's place in the cover; it only adds bytes that paging counts as it counts everything. Default prefix: nothing on a line within its header's day, 8 bytes (`..MM-DD|`) on one past it, plus an 11-byte header per day. The byte-budget fold (`Mem`, `VIEW`) gets no metadata: `Mem::lines` and `zoom(.., None)` print `id+n|text` (a bare `id` for one message, as everywhere: `Coord`'s `Display`), without headers. The compactor never sees the prefix: summaries hold text only, and dates come from the log on every read, so they are exact and never compressed away.
- `show` is unchanged: it already prints every stored field of a message or node as `key value` lines; `-o` would duplicate it.
- Setup block: starts the agent on `ai view`, then describes the date headers, `id|text` and `id+n|text`, the inline `..MM-DD`, that a long view's parts each end with the command for the next, `zoom <id>` for one message, that notes are bare and chat lines tagged by speaker, and the `--time`/`-o` flags. `view` prints no format text of its own (only its footers), so the block is the one description.
- Usage log (usage.rs.md): `run_with` opens the store, computes provenance once (`prov::place` of the cwd, default if it cannot be read, and `prov::env_who`), runs the command through a `Tally` writer, then appends one `Use` whatever the outcome. `note` takes that provenance instead of computing its own, so an unreadable cwd no longer refuses a note. `init` is not logged: there is no store before it, and logging before `Store::open` succeeds could drop a file into a directory that is not a memory. `Command::typed` rebuilds the arguments from the parsed command (tests drive `run_with` without an argv); a note's text is left out.
- `stats`: stats.rs.md.
- `hook`: hook.rs.md. `run_with` runs it in place of `Command::run`: it reads `Runtime::stdin` (default: all of stdin; tests pass a string), passes the memory dir (for the usage log) and `who` (whose session it may replace with the input's), appends `reminded` and the rule (`long` or `periodic`) to the logged args when it printed the reminder, logs its error like any command, then exits 0 whatever happened.
- `spawn_summariser(tool, var, dir, log_dir)` and `store_dir(var, name)` are shared with `ai notes` (`ai notes build`, `AI_NOTES_DIR`, `~/.ai/notes`).
