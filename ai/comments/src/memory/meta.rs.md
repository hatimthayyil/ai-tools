# meta.rs

The metadata a line shows between its id and its text, and the date headers above it, shared by `view`, `zoom` and `grep` (one `#[command(flatten)]` `Meta`, so the flags and help are identical everywhere).

- Format: lines grouped under date headers. A header (`2026-10-11`, UTC) precedes the first line and every line whose start day differs from the line before; under it, `id|text` or `id+n|text`, with optional columns between: `id+n|range|f1|f2|...|text`. One `|` per column, the text last, so a `|` in the text is harmless and the layout reads like `git log --format='%h|%ad|%s'`. Headers carry the start date once per day instead of on every line.
- Range (`range`): from the messages the line covers, not the node's build time (`show` has that). Absent within the header's day; `..10-12` when the line runs past it (the end keeps the year only when it differs: `..2027-01-02`). With `--time`, always present: `09:12`, `09:12..17:40`, or `09:12..10-12 17:40`. `..` is git's range notation, and it marks the column apart from an `-o` field. Second-resolution times are cut to minutes: enough to order events, 3 bytes cheaper.
- `Line`: a printed line with its `Coord` and start day. `dated` inserts the headers. `view`, `zoom` and `grep` print through `dated` (grep counts a header per unit in its page budget, an upper bound).
- `--time`: a flag rather than a `--date=FORMAT` (git) or a `time` field: there is one useful variation.
- `-o FIELD,...` (`ps -o`): origin, repo, root, head, branch, agent, model, session, kind, in the order given. An empty value shows as `-` (`dash`, shared with `show`, stats and the usage log). A line over many messages shows one value: the commonest (a real value before `-`, ties to the earliest), then `(+k)` for the k other distinct values (`acme/widget(+2)`). Listing all values would grow without bound on old lines; a bare count would hide the main one. The agent zooms or `show`s for the rest.
- Cost: dates read only the first and last message (the log is in time order: store.rs.md); fields read every message the line covers. Plain `view` reads 2 blobs per line; `view -o` reads the whole log once. Simple per-message reads; a single scan would be faster on a large log, not needed yet.

`Meta::args` gives the flags as separate arguments for the usage log; `flags` joins them for the printed continuation commands. `date` is shared with stats' per-day rows; `stamp` (date and minute) with the store's time-order refusal.
