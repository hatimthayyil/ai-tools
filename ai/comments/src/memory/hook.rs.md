# hook.rs

- `ai memory prompt-hook` (plumbing, hidden from help): the UserPromptSubmit hook harnesses call, so the reminder text and its threshold ship with the product, not in each user's harness config.
- Input: the harness's hook JSON on stdin. Claude Code and Codex send an object with `prompt` (plus `session_id`, `cwd`, `hook_event_name`, ...); pi's extension sends `{"prompt": ..., "session_id": ...}`. `prompt` and `session_id` are read; serde ignores the rest.
- Long prompt (`LONG_PROMPT` = 150 chars, counted as `char`s, not bytes): prints `{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":REMINDER}}`, the shape Claude Code and Codex both accept. Short prompt: prints nothing, unless the periodic rule fires (below). serde_json sorts the keys; order does not matter to the harness.
- `REMINDER` is `prompts/reminder.txt`, trailing whitespace trimmed at compile time (`trim_ascii_end` is const). No config knob.
- Never blocks: malformed input (not JSON, no string `prompt`, unreadable stdin) prints nothing and exits 0. The error is kept in the usage log (`ok: false`, `error`). A missing store still fails like every other command (exit 1, which Claude Code and Codex treat as non-blocking): the hook is only installed beside a memory, and logging before `Store::open` could drop `usage.jsonl` into a non-memory dir (cli.rs.md, Usage log).
- `REMINDED`: the usage log's argument for a call that printed the reminder, so stats can relate reminders to recall, followed by the rule that fired: `long` or `PERIODIC` (`periodic`). Shared by cli.rs (writes) and stats.rs (reads).
- Periodic rule: a short prompt still reminds when this session's last `REMIND_EVERY - 1` (= 4) hook calls all went without a reminder, so a run of short prompts gets one every `REMIND_EVERY` (= 5) prompts. A long prompt resets the count (it is logged as reminded). No config knob.
- Session: the input's `session_id` when present and non-empty (Claude Code, Codex, pi), else the provenance session (`prov::env_who`). The hook sets it on `who`, so the logged line carries the same id the count reads. No session at all: length rule only, else every unidentified caller would share one count.
- State is the usage log itself, no extra file: `usage::last` reads only the log's last 1 MiB (a few thousand calls, days of use), newest line first, and stops at the 4 newest successful `hook` lines of the session. Fewer than 4 found (a new session, or one whose hooks scrolled out of the tail) means no periodic reminder: the first prompts of a session follow `view`, so they are not forced. Failed hook calls (malformed input) are not counted.
- An unreadable log (any read error) falls back to the length rule; the hook never fails on it.
