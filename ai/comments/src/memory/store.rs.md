# store.rs

Spec: `ai/research/20261004T194110---ai-chat.md` (storage layout). Bare repo per user (`~/.ai/memory`, `AI_MEMORY_DIR`), all data under `REF`.

- Layout (format 2): `format` at the tree root holds the format number (upgrade/mod.rs.md). Message `i` is its own blob at `log/{i>>8:04x}/{i&255:02x}` (named header, blank line, text verbatim: record.rs.md). Nodes of level `l` live in line segments `tree/<l>/{s>>8:04x}/{s&255:02x}`, segment `s` = nodes `[256s, 256s+256)`: a column row (`ts origin agent model session text`), then one line per node (text flattened), empty line = not built. Messages are variable size (echoes up to 30k, pastes larger), so each gets its own blob: a tail segment of big messages would be rewritten on every append. Nodes are small and read all at once at load (refold), so they are segmented; levels are sparse (free nodes and parallel merges land out of order), hence empty lines rather than a dense prefix.
- `log_len`: `Snap::count` of `log`: the last entry's number + 1, from two tree reads. Ids are positions and permanent: single machine, append-only.
- Git plumbing (`Ref`, `Snap`, `Changes`, `fan_path`, `edit_config`) is shared with `ai chat` in `src/git.rs`; `Store` wraps a `Ref` on `REF`, `Snapshot` a `Snap` plus the store (origin, config).
- `mutate`: `Ref::mutate`, checked by `at`: one commit per mutation, CAS on the ref; a lost race redoes from the new head. Multi-writer safe (notes from many sessions, one compactor).
- `Edit`: one mutation's new messages and nodes over a snapshot. Every node write cascades: the parent is built in the same commit when both children exist and `a + " " + b` fits `NODE` (free node). `push` builds the free leaf (`kind: text` ≤ `NODE`). So after any commit every free node whose sources exist is built, and no compactor needs a free-node pass.
- `put_node`: first write wins (a built node never changes); refuses a node beyond the log.
- Free nodes record empty agent, model and session; every node records the store's origin.
- Origin: `ai.memory.origin` in the repo's git config, 6 Crockford base-32 characters from `getrandom`. `find` reads it and creates it under the config lock when absent, so `init` (`create` → `open`) makes it. `append` stamps it on messages without one; `set_origin` replaces it (one word, no whitespace: it is a header field). Public so a rebuild can append old messages with their own `ts`, origin and provenance, then set the store's origin.
- `Store::open` refuses a missing/non-repo dir (only `init` creates); committer falls back to `ai memory <ai@localhost>`.
- Time order: the log is in `ts` order, an invariant `Edit::push` keeps. An unstamped message (`Message::new`) gets `max(now, last ts)` when it is pushed, and the push re-runs on every `mutate` retry, so a writer that loses the CAS restamps on the new head. Before, `Message::new` stamped the time at creation: of 16 parallel `note`s, one could stamp at second k, lose the race to one stamped at k+1, and land after it (the flaky `parallel_processes_lose_nothing`). Stamping inside the mutation is not enough alone: a stamp taken after reading a head whose last message was stamped by a clock that later stepped back would still go backwards, hence the `max`. A message given a `ts` (import, a rebuild) keeps it but must not precede the last message: the store refuses it ("cannot follow ... the log is in time order") rather than move it, since a moved date would be a false record. The lock-free CAS stays: serialising appends with a file lock would also fix it, but CAS + restamp needs no lock file, no stale-lock handling and keeps notes from blocking on a summariser's commit. The order lets a line's date range be read from its first and last messages only (meta.rs).
- `seg`: a node segment (`record::Seg`, shared). Lines stay raw strings; a node is decoded and encoded against the segment's own column row, so a column added by a later ai of the same format is kept when this one rewrites the segment (it writes an empty value there). The row must end in `text` and hold `ts`. An absent segment is an empty one under `COLUMNS`.
- Format check: `find` runs `upgrade` before anything else touches the store; `at` (every snapshot, so every `mutate` retry too) refuses a tree whose `format` is not `FORMAT`, so a process that opened the store before a newer ai upgraded it stops at its next snapshot. `raw` is the unchecked snapshot the upgraders read. The empty memory (no commit) is of `FORMAT`; `commit` writes the `format` blob into the first commit.
- `Mark`: a snapshot's commit, printed for `view --at` (`0` for the empty memory); `snapshot_at` reads it back through `at`, so a commit of another format, or none of this memory's, is refused as not a state of it.
- `upgrade`: older format → under the compactor's lock (blocking; one stderr line while a summariser holds it), reread the head, run `upgrade::step` from its format to `FORMAT` (each step's tree written, uncommitted, for the next to read), commit the result on the head (`upgrade format N -> M`), CAS. A lost CAS (an old ai's note landing first) rereads and upgrades again, the new message included; a head already at `FORMAT` (another process won) proceeds. On success one stderr line names the previous commit, so stdout (view output) stays clean. Rollback: move `REF` back to that commit.
- Why the lock: an old-format compactor (ai ≤ 0.7.0 `nap`, `ai chat`) holds it for its whole run. Waiting for it means no old compactor has a snapshot from before the upgrade when the upgrade lands, so none can retry a lost `put_node` CAS onto the new tree (an old `put_node` reads no message, so nothing else would stop it from writing a format-1 line into a format-2 segment).
- `try_lock` (the compactor's) and the upgrade's wait (`file::lock`) share `LOCK` here. `edit_config` (git.rs) is a free function so prov.rs can cache `ai.root` in a work repo's config.
