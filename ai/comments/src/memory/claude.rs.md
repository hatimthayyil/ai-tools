# claude.rs

Claude Code as the compactor's backend, flags from `ai/research/20261004T172045---shitty-optchat.md` §1/§4: `claude -p --model sonnet --effort medium`, stream-json in/out with `--verbose --include-partial-messages`, `--no-session-persistence --setting-sources "" --strict-mcp-config` (no hooks, plugins, CLAUDE.md, memory or user MCP leak into the request), `--system-prompt-file`, `--tools "" --safe-mode`; env `CLAUDE_CODE_PROMPT_CACHE_TTL=5m` (a 5 m mark after a 1 h one is a 400) and `DISABLE_PROMPT_CACHING=1` (our marks only).

- `compactor` resolves `claude` on `PATH` up front, so a machine without Claude Code fails at once instead of retrying forever. `compactor_at` takes the program (tests).
- System prompts are written once per text into a temp dir owned by the backend.
- One process per conversation: stdout lines go through a reader thread into a channel; the first `result` event ends a `say`. Any event's `session_id` becomes the conversation's session (claude assigns one even with `--no-session-persistence`); the backend's agent is `claude-code`, as `prov` records for Claude Code sessions. `is_error`, `stop_reason: refusal`, no result within 5 min, or an early exit (with stderr's tail) are errors. Drop kills the child.
- `send` enqueues FIFO input on a dedicated writer thread, so a child that does not read stdin cannot block cancellation. Conversations keep their process for size retries.
- Linux: own process group and PDEATHSIG SIGKILL. Drop sends group TERM, allows at most 200 ms, then kills the group and reaps the child synchronously. A stdout EOF from a living child cannot block `failure`. `Live::kill_all` atomically closes the registry against further spawns. Normal shutdown covers descendants in the group; parent SIGKILL guarantees the direct Claude child only.
- `model()`: `$AI_MEMORY_MODEL` or `sonnet`; shared by `compactor` and the summarise log span.
- Nothing `claude -p` gives is discarded. Each conversation is a `Record`, `<calls>/<session>.jsonl` in the store the backend was made for (`CALLS`: a chat thread's `threads/<name>/calls`, the memory dir's or the notes git dir's `calls`): an `ai.call` line (program, args, env, system prompt), an `ai.sent` line wrapping each stdin line as written, and every stdout line copied raw by the reader thread before parsing (invalid UTF-8 included; the sink gets it lossily). `--session-id` with our `uuid()` names the file before claude prints anything. `--no-session-persistence` stays: it keeps these calls out of `~/.claude/projects` and Claude Code's session list. A failed record write fails the next `say`.
- `used()`: a `result` event's `usage` is that request's; its `total_cost_usd` (and `modelUsage`) count the whole process, so a request's cost is the growth since the last result (`usage()`, checked against claude 2.1.304).
