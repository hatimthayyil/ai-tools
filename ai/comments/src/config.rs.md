# config.rs

`ai.toml`: every setting `ai` reads, one table per tool (`[chat]`, `[memory]`, `[summariser]`) and one per agent (`[agents.<name>]`), keys kebab-case as Cargo's. Each table is its tool's own type (`chat::Config`, `memory::Config`, `summariser::Config`), so a tool owns its keys, defaults and checks. A project's file also holds `[project]` (`project::Table`, project.rs.md).

- Three files: the user's in `home()` (`~/.ai/ai.toml`, from `$HOME`); the project's, the nearest `ai.toml` at or above the cwd, found as Cargo finds `Cargo.toml`; and `ai.local.toml` beside the project's, one user's overrides, kept out of version control. The search skips the user's file (`nearest`, compared by path, then canonically), so a cwd under `~/.ai` is not in a project. Only the nearest project file and the `ai.local.toml` beside it count; one anywhere else is not read. Each file's value of a key wins over the one before (`Layer`, folded in that order); a key none sets keeps the tool's default.
- `[agents.<name>]` (`Agent`) is the one table keyed by name: the maps merge by name, then each agent key by key, so `ai.local.toml` can move one agent's worktree and keep its instructions. Its paths resolve once, after the fold, against the project's root (the cwd outside a project), whichever file set them: the agents a user defines in `~/.ai/ai.toml` work in every project. `Agent` has no harness or model: an agent is tied to neither (ai/research/20261024T084514--agents.md).
- `File` is one file as written, `[project]` included; `Settings` is what the files set together. `[project]` in the user's file or in `ai.local.toml` is an error: the project's id and name are its identity, the same for everyone. `Project::find` reads only `ai.toml`, so such a table is reported by the commands that read settings.
- A missing file sets nothing. An unreadable one, a TOML error, an unknown table or key, or a bad value fails the command with the file's path before the TOML error, which shows the line and the key (`main` prints only the outermost message, so the path is part of it, not a context).
- Only `ai init` writes `ai.toml`, and only `[project] id` (project.rs).
- `Settings::find` is the CLI's; `Settings::load` takes the user's file as an argument, for tests.
- Who loads it: `ai memory` and `ai view` at the command's start (`memory::Runtime::config`), `ai notes` at the command's start for `[summariser]` (`notes::Runtime::summariser`), `ai files build` for `[summariser]`, `ai chat` when a command needs its settings (`Chat::settings`, from the directory the store was found from), and `Project::find` for `[project]`.
