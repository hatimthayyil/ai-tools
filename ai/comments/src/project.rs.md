# project.rs

The project at a directory, for agents. Design: the Projects section of `ai/research/20261021T194314--ids-handles-and-paths.md`; ids: `20261021T194500--durable-id-alternatives.md`.

- A project is the directory of the nearest `ai.toml` at or above a directory, never the user's (`config::project_file`). A git repository is not needed, and nothing of `ai` goes in a repository's `.git`.
- `[project] id`: a TypeID of type `project` (`mti`, the UUID in Crockford base-32), minted as UUIDv7 by `ai init`. An id of another type or not a TypeID fails, naming the file. A committed `ai.toml` makes every clone and worktree the same project.
- `[project] name`: the project's slug, else the directory's name.
- `home`: where the project keeps its private store and the `ai.local.toml` link. In a linked git worktree it is the same directory in the main checkout, found read-only through gix (`discover`, then `main_repo`, the worktree's `.git` file to the common dir); elsewhere, git or not, it is `dir`. A main repository with no checkout (bare) leaves `dir`. The private settings are read from here (`config::Settings::load`), so all worktrees share one copy.
- `STORE` is `.ai/local`, the private store: one user's agents (`agents/`) and private settings (`ai.toml`). The rest of `.ai/` is the project's, hidden but tracked, so a tool whose files the team shares (such as comments) can live there; `ai/` stays the agents' visible workspace. `Project::store` is the one place the store's path is built; the agent store sits below it.
- `find` is `None` without a project file or with one holding no id: chat's hook sync then does nothing. `require` is the CLI's: the error says to run `ai init`, naming the file when it lacks only the id.
- `init` mints into the given directory's `ai.toml`, the cwd's from the CLI, so a subdirectory of a project becomes a project of its own. With an id there it changes nothing and prints it again. It refuses the user's own file. `toml_edit` keeps the file's comments, order and formatting; `[project]` is added as a table at the end, or the id appended to the table there. The file is parsed with `config::read` first, so a bad file is reported before anything is written, and written by rename (`NamedTempFile::persist`).
- `commit` keeps the private store's history (repo.rs.md). Before the store exists it does nothing. `ai init` makes the store's folder for the private settings, so the repo comes with the first write after it, and its first commit holds those settings. The first commit writes `.ai/local/.gitignore` (`*.lock`, `*.log`; kept if one is there, so the user may edit it) and makes the repo; the commit is the whole store, fallback committer `ai`. A failure names the store and the cause in one line, since the binary prints only an error's top message.
- `committing` wraps a command: the command runs, then the commit, whatever the command returned, so a build that stops at a failed call keeps its paid summaries in history. The command's error wins; a commit failing after it goes to stderr.
- `init` also adds `/ai.local.toml` and `/.ai/local/` (`UNTRACKED`) to the `.gitignore` in that directory, creating the file if needed, skipping each that a line there already names with or without its slashes (`.ai/local`, `/.ai/local/`). It runs on every `ai init`, so an existing project gets the lines too. A wider pattern that already covers them, such as `/.ai/`, is not recognised; an added line is then redundant, not wrong.
- `init` then makes the private settings, `.ai/local/ai.toml` in the home, empty if missing, and the link `ai.local.toml` to them (relative, `.ai/local/ai.toml`), so a human finds them beside `ai.toml` and edits through the link. A link already there is kept, wherever it points. An `ai.local.toml` that is a file of its own is refused before anything is written (`config::check_link`): it predates the private store, and reading neither it nor the store's file silently would drop settings. No migration: the error says to move it. From a linked worktree, the link and the file go in the main checkout, where they are read.
