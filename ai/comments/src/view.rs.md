# view.rs

`ai view [THREAD]`: what an agent reads to start or after `/ai`. `# Memory`, the memory's whole view at one state (`memory::Cli::view_whole(mark)`, run through `run_with`, so it is logged as `view` with `--at <commit> --whole` and counts in `stats` as a view), then `chat::thread_view`: the thread named, else the one the session is attached to (synced, its branch's view); outside an agent session, the chat commands' rule (cli.rs.md, `pick`). An unattached session, or a repository with no threads, gets the memory alone. The thread is resolved first, so a picker or an error comes before the memory is read.

- Paging (page.rs.md): whole on a terminal or with the hidden `--whole`; otherwise in parts, because an agent reads it through the Bash tool, whose output is cut at 30,000 characters. `/ai` passes `--whole`: it hands the text to Claude Code as the compaction's one message, which has no such cap (register.ts.md, Seed size).
- One state for every part (`Mark`): the memory's commit, then the thread's name and `chat::Mark`, `<commit>:<thread>:<items.lines.sessions>`, or the commit alone when no thread is shown. Notes and syncs between parts would otherwise shift the page boundaries. The first read takes the memory's head before reading the view at it, so the text and the mark agree; a later part reads both states unsynced. A state without a thread shows none, even if the session has since been attached.
- Read-only: it writes no summary line (spec: reading never calls the model). `/ai` first runs `ai chat compact-session`, which writes the lines the thread's view needs and fails visibly; then `ai view --whole`, whose thread part now has them.
- The memory and chat modules stay unaware of each other: this module composes them.
