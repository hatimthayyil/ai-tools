# page.rs

One paging rule and one part size for every paged output: `ai view`, and the views, zooms and greps of `ai memory` and `ai agent`; and `ai page`, which prints the parts after the first.

- `PART` = 20,000 bytes: under Claude Code's 30,000-character cap on a command's output, with room for a header and a `Next` line. A constant, not a knob: an agent harness's cap does not vary per machine.
- Whole on a terminal (`IsTerminal` on stdout, checked only in each `exec`, so tests and library callers default to parts): a person reads the whole view in the terminal; an agent's Bash tool output is never a terminal. Output that fits one part prints as is, with no header and nothing saved.
- Saved views: the first read renders once and saves every part, so later parts print exactly as the first read cut them, whatever notes, syncs or summaries land in between. The continuation is one short id, `Next: ai page <view>:<part>`: small numbers an LLM copies reliably, unlike a commit hash or byte offsets. No state of the stores is pinned and nothing is re-rendered.
- Each part's first line names the command it came from and `part k of n` (`header`), so a page number that now belongs to another view shows itself; there is no command check.
- Where: `cache()`, `$XDG_CACHE_HOME/ai/views` (absolute only, per the XDG spec), else `~/.cache/ai/views`: throwaway rendered output belongs in the cache folder, not in a store. Created `0700`; `tempfile` makes each file `0600`.
- Numbers: `save` deletes expired views, then takes the lowest number not in use. The file is written in full to a temporary file and moved into place with `persist_noclobber` (create-new), so two sessions saving at once never share a number and no reader sees half a view; on a clash it tries the next free number.
- Expiry: `LIFE` = 10 minutes after the last read. `show` refreshes the file's mtime on each read, so a view being paged through stays; one left alone frees its number. A view past `LIFE` is gone even before a save deletes it. A missing or expired view fails: "View 17 is gone: run the command again."
- A view is a JSON array of its parts (header and body each); `put` adds `Next: ai page <v>:<k+1>` when printing, since the number is known only once the file is in place.
- `pages` cuts after the last line end in a part when that keeps at least half of it, else at a character boundary.
- Searches page by whole matches, not bytes of text, and newest first: the newest matches are what an agent most often wants, so part 1 holds them (`newest_first`: each part the newest left that fit in `PART`, at least one). Each part still prints its matches oldest first. `search` takes `render`, the caller's lines for a range of matches: whole or in one part, the matches then `n matches.` (or `Newest k of n matches.` when `-m` kept only k); else each part's header adds `newest first: j of n matches`.
