# plugins/claude/hooks/register.ts

The Claude Code side of `ai agent` (design: `ai/research/20261014T002322--chat-design.md`; mod findings: `20261014T202206--chat-launch-attach.md`). Claude Code 2.1.300; the mods API is early access.

- Install: from the marketplace at `share/ai/plugins` (README, Claude Code plugin); in development, per process, `claude --plugin-dir plugins/claude`. The flake installs it at `$out/share/ai/plugins/claude`; with `nix profile`, `~/.nix-profile/share/ai/plugins/claude`. `ai` is resolved from the session's `PATH`.
- Managed route: under a Team or Enterprise `/login`, or with managed settings, the built-in `cc-plugin-sec-default@builtin` runs first and withholds `classic.*`, `session.compact`, `prompt.*`, `settings.read` and some `session.append` routes from user-tier plugins (Claude Code 2.1.310's binary). It delivers everything to the append tier, which holds only managed plugins named in managed `appendPlugins`. A plugin counts as managed only from a managed `directory` marketplace that lists it by a `./relative` path inside the marketplace's real path, hence the marketplace in the package.
- Plugin name `ai`: the command is `/ai`, the tool `mcp__ai__compress`, the state keys `ai.transcript`, `ai.view` (the view `/ai` built, for the one compaction it queues) and `ai.compress` (the agent asked for a compaction at turn end).
- `/ai <sub>` is one command: `command.run` hands the rest of the line as `e.args`; `/ai` alone compacts.
- The plugin runs plumbing (`compact-session`, `sync-session`: exit 3 silent when unattached) and three porcelain commands (`new`, `attach`, `detach`). `/ai new <name>` runs `ai agent new`, then attaches as `/ai attach` does; a failed `new` shows its stderr and attaches nothing. `/ai attach` and `/ai detach` show `ai agent`'s stdout, else its stderr, which porcelain words as a sentence (`This session is not attached to a thread.`).
- Transcript path: `$` has the session id but not the transcript path. `classic.SessionStart` (startup, resume, clear, compact) carries it; it goes to `$.state`, which outlives a module reload. `classic.Stop` carries both, so sync reads them from `e`.
- Seed: on `classic.SessionStart` with `source: startup`, `ai agent compact-session` for the new session; its stdout is appended to the hooks' `additionalContext`. The launcher (`ai agent resume` when it starts a new session) binds a session before it starts, with no item of its own, so `compact-session` prints the view of the thread up to the session's graft; an unattached session exits 3, a session on a new thread prints nothing, and either starts as it would. Other sources never seed: `resume` replays the seed from the transcript (it is stored there as a `hook_additional_context` attachment, which the adapter drops, so sync never ingests it), `clear` is an unattached session, `compact` already carries the view. A compaction drops the seed with everything else.
- Seed size: a mod's `additionalContext` is not cut at the 10,000 characters a settings hook's output is: 250,000 characters were stored whole, and a 130,000-character seed reached the model whole (haiku answered markers from both ends; 47,182 input tokens). The view is at most 128,000 bytes, so one entry, no paging.
- One meaning per command: `/ai` is ours and `/compact` is Claude Code's. `/ai` builds the view (`ai agent compact-session`) before any compaction starts, then reads `ai view --whole` (in one piece, never in parts: the whole memory, then that thread's view; src/view.rs.md) as the text to compact into, and queues `/compact` only once it has it; a failure of either, or an empty thread, compacts nothing and says why. An unattached session is no failure: `compact-session` exits 3, and `ai view --whole` gives it the memory alone, which it compacts into. The startup seed stays the thread's view alone. No way to cancel a compaction from `session.compact` is known, so the view must exist before it starts.
- Organization policy (2.1.310): on a Team or Enterprise account, or a machine with managed settings, the built-in `cc-plugin-sec-default` sits outermost and passes `classic.*`, `session.compact` and the prompt events over every `user`-tier plugin; `ai` installed any way but managed is one. No mod API says so: `$.session.identity` denies every unmanaged mod alike, and the policy sits above the plugin, outside `next.trace`. One rule covers both, so `classic.SessionStart` reaching the plugin (`ai.transcript` set) stands for `session.compact` reaching it. Without it `/ai` and the agent tool refuse before building anything, since `/compact` would summarise natively. A plugin added to a running session refuses the same way. Managed `appendPlugins` delivers both.
- `session.compact` answers `{ messages: [view as one user message] }` without `next` only when `ai.view` holds the view `/ai` built, and clears it, so that view answers one compaction. The summarizer never runs (`compact_boundary`, ~20 ms, no model call). Every other compaction (`/compact`, `auto`, `precompute`, a subagent's own with `agentId`) calls `next(e)`. The view's user entry has no `origin`, so sync drops it; the boundary becomes a compaction marker.
- Flush: Claude Code buffers transcript writes for up to a second (`flushIntervalMs: 1000` in 2.1.300; measured 50–220 ms). A compaction run at turn end (agent tool, `/ai` typed during a turn) started 36 ms after the turn's last entry, and a sync then missed the final reply. `/ai` therefore sleeps `FLUSH_MS` (1,100 ms) before `compact-session`, and the Stop sync runs `FLUSH_MS` later (`$.clock.after`). `session.end` runs `ai agent end-session` after the engine's end step: one more sync, for a session that exits within that second, then the commit of the project's `.ai` store that the turn syncs leave for an event; it also covers `/clear` and `-p`. `session.end` is not a `classic.*` route, so the organization policy passes it to user-tier plugins too, and the transcript path may be missing there (`ai` then finds it from the session id). It runs within the SessionEnd budget (1.5 s by default): a sync and a commit of a store with large changed files can overrun it. Cut short, the commit moves no ref (the lock is an `flock`, released with the process), so what it would have committed waits for the next event.
- Answering without `next` also skips the built-in `cc-plugin-agents-md` hook beneath, which marks nested instruction files for re-attachment after a compaction. After an `ai agent` compaction, nested `CLAUDE.md`/`AGENTS.md` files read before it are not re-attached until something else resets that plugin's state. No mod API lets a user-tier hook run the built-ins but skip core.
- On `auto` the prompt that triggered it is already in the transcript and inside the compacted span: the view must carry the open turn, or the model sees no question.
- `/compact` from the mod: `$.command.run({ command: 'compact' })` from `$.clock.after(0, …)`. Called inside a `command.run` or `tool.call` hook it is refused (it would compact under the turn the hook holds). `$.session.compact()` skips the calling plugin's own `session.compact` hook, so it would compact natively. A `$.command.run` of the plugin's own `/ai` skips its own `command.run` hook the same way (the test engine finds no implementation beneath).
- The agent tool runs `ai agent sync-session`: exit 0 ingests, exit 3 (unattached) has nothing to ingest, and either way it sets `ai.compress`, and the `classic.Stop` hook runs `/ai`'s compaction once the turn ends, writing a failure to the transcript (`$.ui.log`, `ui_log` under `-p`) in place of `/ai`'s reply. It is left deferred (behind ToolSearch) so unattached sessions carry no schema.
- Turn-end sync is a mod `classic.Stop` hook, not a `hooks.json` command hook: it has the session id and transcript path without parsing stdin. It returns at once; the sync runs on the timer.
- `$.process.run` reads the whole output until the child exits: `ai agent sync-session` must detach the background `build` from its stdout and stderr, or it holds the call. Its timeout is 30 s by default; `compact-session` and `attach` get the 10-minute maximum.
- An interactive `--plugin-dir` session writes the engine's type declarations into `.claude-plugin/types/` and a `tsconfig.json` beside `hooks/`; `.gitignore` keeps both out. With them laid, `tsc -p plugins/claude` type-checks the module and tests.
- Tests (`claude plugin test plugins/claude`) stub `process.run` and the clock beneath the plugin; they need no model and no `ai`.

End to end (2026-10-15, Claude Code 2.1.300, haiku, throwaway repo, private tmux; 36 model requests: 19 Claude Code requests (one the seed-size probe), 1 native summary, 16 compactor calls of which 6 were over-limit retries; the summariser was off for the last two steps):
- `ai agent claude t1` on a new thread: no seed. Three tool-use turns (Write, Bash, Read+Edit); each turn-end sync ingested them (sync 20 ms, unattached 12 ms) and the summariser built the closed turns' lines and nodes (haiku, 1.7–2.5 s a call).
- Manual `/compact`: the 2.4 KB view became the context, 46 ms, no model call; the model answered from it and ran `ai agent zoom 0-3` through Bash.
- Agent tool: ToolSearch, `mcp__ai__compress`, `/compact` at turn end, 9.2 s: `compact` built the just-closed turn's line beside the summariser doing the same (two calls for one line), and its view lacked the final reply (the flush race above).
- `/ai detach`, `/compact`: native, 7.2 s, one summarizer call. `/ai attach t1` caught up the 4 entries since. `/clear`: unattached (`/ai detach` says so).
- `ai agent resume t1` from the terminal: `claude --resume` of the attached session, natively, with its full context.
- After the flush fix: `/ai compress` typed during a turn compacted in 1.1 s with the final reply in the view; the Stop sync took the final reply.
- Second `ai agent claude t1`, from the nix-built package and plugin: seeded with the 4,218-character view in ~0.6 s; the model answered from it; a resume of that session answered a question only the seed held.
