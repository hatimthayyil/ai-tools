# tests/agent_cli.rs

`ai agent` as a binary. `Sandbox`: a temporary directory (canonical, as `getcwd` gives it) holding a project (`Project::init`, no git), a `HOME` whose `.ai/ai.toml` switches the background summariser off, a Claude Code config dir (`CLAUDE_CONFIG_DIR`, so transcripts go to `projects/<the project's path, encoded>/`), and a fake `claude` first on `PATH` that writes its arguments to `out/argv` and its working directory to `out/cwd`. `out/` is outside any project, and a second project (`init`) sits beside the first.

Lines are written through the library (`Thread::put_line`), keyed by `turn_ends`, as the roll-up would. `ran_in` stamps a transcript's entries with the `cwd` Claude Code records.

- Plumbing (`sync-session`, `compact-session`) of an unattached session: exit 3, no output, by flags or environment, and outside a project.
- Porcelain without a thread (`view`, `zoom`, `build`; `detach`): a sentence saying what to do, in and out of a session; an unknown `-a` agent; outside a project; an `ai.toml` without an id.
- Help lists the porcelain and hides the plumbing.
- Attach (transcript found from the session id), sync by flags, re-attach, moving threads, detach; errors without a session, with a bad name, outside a repository.
- `compact-session` syncs first, builds the free work lines its recent turns need, then prints the instruction and one list: recent turns with their work lines (a written turn line left out), the ended newest turn whole; a session whose harness cannot be read: exit 1, the reason on stderr.
- `list`: threads with turns, newest time and branches; their sessions newest first, attached or detached, the calling one marked.
- `view` syncs its session and writes no line, its recent turns' unbuilt work shown as placeholders; outside the session it reads without a sync; `compact-session` then writes the lines.
- `view` in three parts whose footers chain (`-a <name> --part --at`), joined equal to `compact-session`'s output, although the session syncs a new turn between parts; in and out of the session alike.
- `ai view`: `--whole` is the memory alone outside a session and memory then thread inside one; piped, it comes in parts whose `--at <commit>[:<thread>:<state>]` footers chain and join to `--whole`; each read logs one memory `view --at`.
- `zoom` of a node, a node with an unbuilt half, a turn, an item, a long item in two parts chained by `--part 2 --at <state>` (`--tool-output` repeated), by session and by `-a`; bad ids. `grep` of 300 matches pages newest first through `--part --at` footers, every match once, oldest first when joined; an unknown part is refused. `grep -a x -a y` labels each line with its agent, thread by thread in the order named, drops a repeated name, fails on an unknown one, and pages two long threads through footers repeating both `-a` and one state per thread (`--at s,t`), every match once; a `--at` with the wrong number of states is refused.
- `resume` of a new agent: argv and directory, binding with the future transcript path, graft of a second session once the first one's transcript is gone; `view` of a thread with nothing yet. The seed: `compact-session` of a launched session prints nothing on a new thread, and the view ending at its graft on an existing one.
- `resume`: unknown thread; the newest session resumed and re-attached in the directory it ran in, with the launcher's args, also from a subdirectory; a session that ran outside the project and one whose transcript is gone start a new session, with the reason on stderr and the same args.
- `ai resume`, run at the top level: the same unknown-agent error, and the newest session resumed in the directory it ran in with the launcher's args.
- Two repositories, each with a `dev` thread: `list`, `zoom -t` and `resume` see only their own.
- `build`: a dry run with `--model` (in the thread's log) stores nothing and keeps a line written by hand; a write, then nothing to write; `--rebuild --dry-run` shows the line it replaces; `--rebuild` rewrites it.
- Failures, through `fake_compactor`: a `claude` that also answers `-p` by its first message (`BAD` fails, `LONG` gets 600 bytes every try, else a short line after a delay, so the failure lands while the other calls run). `build` stops at the first failure: of 10 turns, the 7 running beside it are kept, the last 2 never start. `--background` builds the other 9, and takes no `--rebuild`. A line over 512 bytes after 5 tries fails, unstored. `compact-session` and a `resume` starting a new session fail with the failed lines and the hint (20 closed turns, so the failing first one is past the recent turns, in the fold); `resume` binds and launches nothing.
- The private store's repository (`.ai/local`): a read makes no repository; `new` makes the repo and `.gitignore` and commits as `ai`; `attach` commits; an `attach` that changes nothing commits nothing; locks are on disk but not in the tree; `git status` in the store is clean; a broken repo makes the next write fail with `Cannot commit <store>: <cause>`. A turn's `sync-session`, `ai agent view`, `ai view` and `build --background` write but commit nothing, leaving `git status` dirty; `end-session` then commits it all, as `compact-session`, `build`, `detach` and `resume` each commit the turn synced before them. From a linked worktree, `new` commits in the main checkout's private store, makes no `.ai` in the worktree, and the project's own `git status` stays clean.
- The background summariser for real: the private settings, written through the `ai.local.toml` link, turn it on, `attach` adds turns and starts it, and its log reaching `end` with both closed turns' lines written proves it ran a valid `ai` command line.
