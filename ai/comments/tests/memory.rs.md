# tests/memory.rs

In-process library and CLI tests (`Cli::run_with` with a fake `Runtime`).

- `Fake`: a backend whose reply is a function of the step text and attempt; it asserts what every call must look like (system = COMPACT, cached `<chat>` pieces with no ids or placeholders, unmarked step, retry message asks for a rewrite (ends `never cut it off.`)) and records order and peak concurrency. Summaries are 300 characters so two never merge free.
- View invariants (spec §5, ported from shitty-optchat's selfcheck): 1200 random messages on a 6000-byte budget, nodes built synchronously in rule-3 order: tiles `[0,T)`, size bookkeeping exact, never over budget while a mergeable pair exists, never splits, refold equals the live fold, stays near budget.
- Rule 3, free nodes and cascades, zoom semantics, placeholder rendering, compactor order/concurrency/settle, view under budget while logging, notes from another process picked up, size retries (shortest of 5), failure reported once then retried, the compactor lock, and a CLI life (note limits, import, view resumed by id across parts, build, zoom, show, grep paging and origin/agent/session filters on nodes). Origins: made at init in the `origin` file, kept across opens, stamped on messages and nodes, an explicit one kept, `set_origin`, a file that is not one word refused. `entry-chars` (from `Runtime::config`) bounds notes, with the 40-byte grace capped at 512, and sets the setup block, and `config` prints it beside its default; its cap of 512 is checked where `ai.toml` is read (config.rs.md).
- Lock race: `before_release` appends a note and runs a second summariser while the first still holds the lock; the second must report the lock taken and the first must build the note's nodes before exiting.
- Message timezone rendering and raw zoom paging preserve UTF-8/newlines and reject invalid part numbers.
- `a_summariser_logs_timestamped_events_to_summarise_log`: a summariser writes exactly start, 3 built, end as timestamped INFO lines in the `summarise` span (pid of the test process); a second summariser with a flaky, over-long fake adds WARN `failed` and `over limit` lines.
- Retries: test options use `retry` 20 ms and `retries` 3 (`opts`, also in `runtime`). `failures_are_retried_and_reported_once` fails 3 times then succeeds: recovery exactly at the bound. `a_node_failing_past_its_retries_stops_the_compactor`: an always-failing fake makes `run` return `GaveUp` after 4 calls; a new compactor (lock free) then builds the node. `a_summariser_on_a_dead_backend_gives_up_and_frees_the_lock`: `build` exits 1 with the Failed and Gave up lines on stdout, exactly one ERROR `gave up` line and no `end` in summarise.log, the view still unbuilt, and a following nap builds all 3.
- Metadata: the CLI life checks `view` (header `2020-01-01`, then `0|...`), `view --time -o kind,repo`, `zoom` inline ranges (`0+8|..01-04|` under `2020-01-01`), `zoom -o repo`, `grep --time -o origin,repo`, that `-m 5` keeps the newest 5, and that every one-message id `zoom 0+4` prints is bare and zooms back to itself; `zoom_opens_two_levels` checks `zoom` with a `Meta` (fields, leaf). Notes are bare everywhere (`0|message 0 ...`, a full 512-byte note is its own free leaf); chat kinds keep their tag.
- View states: a short view is one part with no footer; `view --at <commit>` reads that state after a later note; `--part 2` of one part, a malformed and an unknown `--at` are refused. `long_output_comes_in_parts_of_one_state_and_whole_on_a_terminal`: 80 notes of 268 bytes page into two parts whose `--part 2 --at <commit> --time` footer chains and joins to `view --whole --at`, although a note lands between them; `Runtime::terminal` prints the latest whole, unless a part is asked; `zoom` of a 30,000-byte note joins its parts back to the message and prints whole on a terminal; `grep ^note --time` pages the 80 notes newest first into two parts, `--time` repeated, that hold every match once from one state although a note lands between them, and a terminal reads the latest search whole.
- `the_log_is_in_time_order`: `Message::new` is unstamped; an explicit earlier `ts` is refused; a stamp after a future-dated message is raised to it.
- Import: an earlier date than the log's last message is refused by the store; a date going back within the file names its line.
- `stats_count_notes_from_the_store_and_reads_from_the_usage_log`: an empty memory prints `No calls.`; then notes with provenance in the store and a hand-written `usage.jsonl` (a torn line, a summariser, failed grep and note, an ok note line that must not double the store's) give exact tables per day and `--by repo` (the `-` repo row), `--since` cutting earlier calls, `--by session` and `--by agent` rows, the session means and shares, the hook line (`hook` calls not in the table; a failed one not counted), and the `Failed:` line.
- `the_hook_reminds_on_long_prompts_only_and_never_fails`: `hook` helper passes a string as `Runtime::stdin`. 149 `é` (298 bytes) prints nothing; 150 prints the exact JSON; Claude Code's extra fields and a bare `{"prompt"}` both work; empty, non-JSON, no `prompt`, non-string `prompt` exit 0 with no stdout or error; each call is one usage line (`reminded` arg, `ok`/`error`); `stats` counts none of them as calls.
