# Glossary

- `memory`: the store `ai memory` manages; one per user per machine, shared by every repo and session, append-only. A bare git repo at `~/.ai/memory` (override `AI_MEMORY_DIR`); all data lives as objects under `refs/ai/memory`, one commit per mutation.
- `message`: one entry of the log, with a `kind`; its blob is `log/<hi>/<lo>`: `key value` header lines (`ts kind origin repo root head branch agent model session`, empty ones left out), a blank line, then the text. Ids are positions `0, 1, …`, permanent.
- `kind`: `user` (the user's words), `talk` (the agent's replies), `tool` (its tool calls), `echo` (tool results), `note` (`ai memory note`, `import`).
- `node`: one summary line of the tree, ≤ ~512 bytes (`NODE`). `(l, i)` covers messages `[i·2^l, (i+1)·2^l)`; level 0 summarizes one message, level `l` merges its two children. Stored one per line in `tree/<l>/<hi>/<lo>` segments of 256, under a column row (`ts origin agent model session text`).
- `id+n`: how a node is named: first message `id`, `n = 2^l` messages. One message is a bare `id`; `zoom` and `show` take either.
- `free node`: a source that fits `NODE` is its own node, no model call: a short message (`kind: text`), or two lines joined. Built in the same commit that completes its sources.
- `view`: the nodes tiling `[0, T)`, oldest first, under `VIEW` = 128,000 bytes; grows by appending and merging the most due pair, never splits; folded again from message 0 at load. `ai memory view` prints it.
- `placeholder`: `(not summarized yet: zoom it)`, the view line of a message whose level-0 node is not built.
- `compactor`: builds nodes with a model, in rule-3 order (messages one at a time, merges alongside), `JOBS` = 8 at once, size retries, fixed 10 s retry. One per memory (`compact.lock`). Runs as `ai memory build`.
- `rule 3`: a node is built only when every view line before its end is already a summary, so the compactor never sees a placeholder.
- `build` (memory): `ai memory build`: run the compactor until nothing is buildable, then exit. `note` starts one in the background when a node is due.
- `backend`: the compactor's model access (`Backend`/`Conversation`); now only Claude Code (`claude -p`, Sonnet, medium effort).
- `ai memory view`: print the view under date headers: whole on a terminal, else in parts.
- `part`: one page of a view's output when it is not on a terminal: at most `PART` (20,000) bytes, ending with `--part N --at <state>` for the next.
- `state` (`--at`): what a view's parts are read from, so they join up: the memory's commit (`0` while empty), a thread's file lengths (`items.lines.sessions`), or for `ai view` both, `<commit>:<thread>:<items.lines.sessions>`.
- `zoom`: open `id+n` two levels down; a bare `id` gives the original message in bounded pages (`part`, from 1).
- `origin`: a store's random id (6 Crockford base-32 characters), made at `init` and kept in the store's `origin` file; stamped on every message and node the store writes.
- `show`: every field of one message or node.
- `grep`: rg-style regex search over every message's text (smart-case, `-F`, filters `--since`, `--kind`, `--origin`, `--agent`, `--session`, `--repo`; `-t` adds nodes); off a terminal, in parts newest first.
- `snapshot`: the memory as of one commit; every command reads one.
- `knob`: a memory size set under `[memory]` in `ai.toml`, shown by `ai memory config`: `view.lines`, `entry-chars`.
- `ai.toml`: `ai`'s settings, one table per tool (`[chat]`, `[agent]`, `[memory]`, `[summariser]`): the user's in `~/.ai`; the project's, the nearest one at or above the cwd (never the user's); and the project's private one in its private store, linked from `ai.local.toml`; each later one's keys win. A project's also holds `[project]`: its `id` and `name`.
- `provenance`: origin of a data item: who/what produced it, when, from which session, model and commit.
- `attribution`: authorship of work (code, files) as AI-generated, AI-assisted or human.
- `format`: the store's format number, the `format` blob at the tree root (absent: 1). This ai reads and writes only its own (`FORMAT`); it refuses a newer store and upgrades an older one.
- `upgrade`: the pure, automatic rewrite of an older-format store to `FORMAT`, one commit `upgrade format N -> M` on the old head under the compactor's lock; the old head is the rollback.
- `project`: the directory of the nearest `ai.toml` at or above the cwd, never the user's; its id, a TypeID `project_<UUIDv7>`, is minted once by `ai init`. Its agents and private settings live in `.ai/local/` of its main checkout, and a note records its id.
- `private store`: `.ai/local/` in a project's main checkout: one user's agents and private settings for the project, a git repository of its own that the project's git ignores. The rest of `.ai/` is hidden but tracked by the project; `ai/` is the agents' visible workspace.
- `notes`: the store `ai notes` manages: a global knowledge base agents consult deliberately, never loaded at session start. A non-bare repo of Markdown files at `~/.ai/notes` (override `AI_NOTES_DIR`), one commit per change.
- `topic`: a directory of the notes, named by its slug path with dots (`linguistics.syntax`); repo knowledge goes under `projects.<repo>`.
- `leaf`: one note of the notes: one claim, titled (`# <title>`, ≤ 80 characters, the claim in a few words), body ≤ 1024 bytes, file `<id>--<slug of title>.md`; the id is its UTC Denote timestamp, permanent. Frontmatter: `source`, `confidence` (`verified | reported | speculative | assessment`), `checked`, `decay`, `links`, `supersedes`, `invalid_at`.
- `scope`, `gist`: the two parts of a topic's `_summary.md`: one line on what lies below, and its key claims. Written by the compactor model from the topic's children; out of date when the hash of that input changes.
- `breadcrumb`: a topic path as `ai notes grep` prints it: `physics › qm › decoherence`.
- `item`: one normalised harness entry in `ai agent` (`agent::Item`): a user message, work, assistant text, tool call, tool output or marker, with its source id (harness, session, entry), parent and time. Thinking is dropped.
- `marker`: an item that is a harness event, not content: a compaction point, the harness's own summary, an interrupt.
- `branch`: the items from a root of the item tree to one tip. Rewinds, edits and two sessions on one thread add branches; nothing is removed.
- `step`: an assistant text, if any, and the tool calls and results after it, up to the next assistant text.
- `turn`: a user message or work item and the steps that answer it, up to the next one on the branch; closed once one follows. Codex uses the word the same way (thread, turn, item). Stored line records keep the kind name `exchange`.
- `human prompt`: a user entry that opens a turn: one the user typed or sent (mid-run included) or a subagent's task. Tool results, hook context, `isMeta` entries, local commands and their output, task notifications are not.
- `work`: an item that is a message from another agent, with its sender: a subagent's hand-back, a fork's report (from its description), a peer's report, a coordinator's instruction. It opens a turn (OptChat's name).
- `agent`: a name in a project with one thread, created only by `ai agent new`. Every thread is an agent's.
- `thread`: an agent's history: a directory `threads/<name>` of the project's agent store, `.ai/local/agents` in its main checkout, so its linked worktrees share it. Holds items, session tracks, subagents and lines as append-only JSON Lines, and copies of its sessions' files; format 3.
- `sequence number`: an item's position in its thread, from 0, permanent. Parents and line keys are sequence numbers. A subagent's items are numbered apart, beside the main tree.
- `binding`: a harness session's record in a thread (`sessions/<harness>/<session>`): transcript path, graft, tip, attach and detach times. Attached until detached; a session is attached to at most one thread of a repository.
- `graft`: the item a session's roots hang on: the thread's newest item when the session was first attached; none on a new thread.
- `tip` (of a session): the item of its transcript's newest entry, the end of its branch.
- `line` (chat): a summary in a thread, keyed by its level and the last item it covers (`level@last`), of kind chunk (a work line), turn or node; written once.
- `sync` (chat): ingest an attached session's new entries into its thread, writing nothing if nothing is new; an unattached session is reported as such.
- `view` (chat): what `ai agent compact-session` and `ai agent view` print for a session: an instruction, then one list of every turn of its branch once, oldest first: the fold (at most `[agent.view] lines` lines, default 64), the recent turns, the newest turn. Computed fresh each time; nothing about it is stored.
- `level` (chat view): how much of a turn the view shows, least first: oldest (in a merged line), older (its turn line), recent, newest. Never decreases toward the present.
- `recent turns`: the turns before the newest, back from it, whole while they fit `RECENT` (16,000 bytes) at their worst: message and final reply word for word, work lines between.
- `newest turn`: a branch's last turn, closed or open: the view lists its every item as `ai agent zoom` does, and builds no line for it.
- `fold` (chat): the turns of a session's branch before the recent ones, in lines, oldest coarsest: from one line per turn, the most due aligned pair merges first, due = (T − last)/2^l, until at most `[agent.view] lines` (default 64) are left. An unbuilt line shows what is built under it, else a placeholder.
- `id` (chat): how a line or item prints, on a branch: `12` turn 12, `8+4` turns 8 to 11 (a node when aligned), `12.3` item 3 of turn 12 (item 0 opens it), `12.3+7` items 3 to 9 of turn 12 (a work line, or a chunk of the work). Turns count from 0 along the branch; past a fork, the same id names a different turn on each branch. What `ai agent zoom` takes. Store keys stay `level@last`.
- `place` (chat): an item's turn and number in it, from its branch (`model::Place`); fixed by the path from the root, so the same on every branch through the item.
- `open turn`: a branch's last turn, not yet closed: no message follows it and the harness has not ended it.
- `placeholder` (chat): `8+4|(not summarised yet)`, a line the roll-up has not built.
- `launcher`: `ai agent resume <name> [-- args]` when the thread has no session to continue: a new session id bound to the thread with its future transcript, then `exec claude --session-id`.
- `seed` (chat): the view a launched session of an existing thread starts with, its only context: the plugin's `SessionStart` (`startup`) context, from `ai agent compact-session`. Kept in the transcript, so a resume replays it; a compaction replaces it.
- `roll-up`: a thread's lines and what each is made from (`agent::Rollup`), over every branch: work lines (level 0), turn lines of closed turns from their message, work lines and final reply (1), binary nodes over aligned pairs of closed turns along the branch (1+k). Built by the chat compactor.
- `final reply`: the item that ends a turn when it is the assistant's text (Claude Code's `end_turn`), the reply that tells the user what came of the work. A turn cut short by a message or an interrupt has none.
- `work` (of a turn): its steps between its message and its final reply; all its steps when it has no final reply. Summarised in its own work line, `t.1+n`. Not the `work` item kind.
- `chunk`: consecutive steps of a turn's work, at most `INPUT` (48 KB), cut greedily at step boundaries (an over-budget step before its tool calls); final once another chunk follows it. Work that fits is one chunk, its work line. Its call reads the turn's message as context.
- `free line` (chat): a line whose input fits its limit (512 B per 50 words asked) is that input without item ids, flattened, with no model call.
- `grep` (chat): `ai agent grep <regex>`: matches on a thread's branch in items' words and tool calls, tool output with `--tool-output`, and built lines; off a terminal, in parts newest first.
- `build` (chat): `ai agent build -a <name>`: the thread's summariser, one per thread (its lock), building every ready line until none is; `sync-session` starts it in the background unless `ai.toml` sets `chat.background` false. `--rebuild` drops every line and writes them again; `<id>` writes one line, and with `--rebuild` rewrites it and drops the lines above it for the next run; `--dry-run` prints what it would write and stores nothing; `--model` picks the model for the run.
- `porcelain`: a command for users and agents (git's term): listed in help, errors worded as what to do.
- `plumbing`: a command for harness glue, at least two words, hidden from help: `ai agent sync-session`, `ai agent compact-session`, `ai agent end-session`, `ai memory prompt-hook`.
