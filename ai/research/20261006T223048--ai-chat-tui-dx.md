# ai chat TUI: live feedback and streaming DX

Research note. Author: @claude-code (claude-opus-5-5), 2026-10-06. Input to the next TUI layer. Spec: `20261004T194110--ai-chat.md` (TUI as built, 0.4.0).

## What ai chat shows today (0.4.0)

- Text deltas stream already (`--include-partial-messages`), but only the unfinished line shows, raw, in the bottom pane; complete lines go to scrollback as markdown. A reply that is mostly thinking or tool input looks frozen.
- During a turn the status bar shows only `◐ working Ns` (spinner steps once a second).
- Thinking: one `∴ thought for ~N tokens` line after the block ends.
- Tool calls appear when the `assistant` event carries the whole input; a running tool has no cell, no elapsed time.
- Usage is shown after the turn only.

## What Claude Code's stream offers (probed, CC 2.1.292, sonnet/opus)

| Event | Use |
|---|---|
| `system/status: requesting` | phase "waiting for model" (TTFT) |
| `system/thinking_tokens` (`estimated_tokens`, `_delta`), several per block | live "thinking ~N tokens" counter |
| `content_block_start` `tool_use` (name, id) then `input_json_delta` | show the tool cell before its input finishes (Write/Edit of big files stream for seconds) |
| `system/task_started` (`description`, `tool_use_id`, `task_type: local_bash`) / `task_notification` | running Bash with its description, done/failed |
| `message_delta.usage.output_tokens` | output token count per message |
| `rate_limit_event` (`five_hour`/`seven_day` utilization, `resetsAt`) | subscription headroom in the status bar |
| `tool_progress` (heartbeat for long tools, per SDK changelog) | not seen in a 7 s Bash; treat as optional |

Thinking text is never available: `thinking_delta.thinking` is empty, also with `--settings '{"showThinkingSummaries":true}'` (sonnet and opus). Bash output does not stream; only start/finish.

## How others do it

- **codex-rs/tui** (Rust, ratatui, inline viewport; ai chat's model):
  - Newline-gated markdown commit to scrollback, plus a bounded *prose preview* of the unfinished line rendered (not raw), never committed (`streaming/prose_preview.rs`).
  - Commit animation: a queue of committed lines drained by a tick, one line per tick in "smooth", whole backlog in "catch-up" (hysteresis) (`streaming/chunking.rs`, `commit_tick.rs`). Gives typewriter feel without lag.
  - Table holdback: a table stays in the mutable live tail until its block ends, so rows reflow (`streaming/table_holdback.rs`).
  - Status row above the composer: shimmering header (`Working`, or the first bold heading of the reasoning summary), `(12s • esc to interrupt)`, inline suffix (background processes). Shimmer is whole-grapheme brightness, reduced-motion fallback (`status_indicator_widget.rs`, `summary_shimmer.rs`, `motion.rs`).
  - Active cell: the running tool is a live cell (`• Running cmd` + tail of output), committed as `• Ran cmd ✓ 5ms`; consecutive reads/searches group as "Explored" (`exec_cell/`).
  - Ctrl-T transcript overlay (full detail incl. live tail); Esc-Esc backtrack to edit an earlier prompt; queued messages previewed and editable (`pending_input_preview.rs`); persistent composer history.
- **pi** (TS, pi-tui, main screen with differential rendering): the whole transcript is a component tree re-rendered each frame and diffed by line; only lines inside the viewport can change, so the streaming message renders as full markdown live. Thinking blocks toggle, tool cells show partial output and expand (Ctrl-O), retry countdown indicator, footer `↑in ↓out $cost (sub) ctx%`. Enter while streaming *steers* (delivered mid-turn), Alt-Enter queues a *follow-up* (after the turn).
- **opencode** (TS, opentui/Solid): alt-screen, sticky-bottom scrollbox, 80 ms braille spinner, thinking shown inline as `_Thinking:_` with a toggle. Alt-screen gives full live re-render but loses native scrollback/selection.
- **Claude Code**: `✻ Verb… (1m 3s · ↓ 1.2k tokens · esc to interrupt)`; verbs configurable; Ctrl-O verbose transcript; todo list pinned above input.
- **Toad** (Textual): streaming markdown re-parses only the last block, updates regions as small as a character; tables and fenced code highlighted while streaming. ai chat already re-renders from the last top-level block.

## Recommendation (layered, each step ships)

1. **Live status row** (smallest, biggest effect): phase + counters from events already in the stream: `◐ thinking ~1.2k tok · 14s`, `◐ writing ↓ 340 tok`, `◐ Bash: Sleep 7 seconds… 5s`, `◐ waiting for model`. Smooth spinner (~80–100 ms frames, codex-style shimmer optional, reduced-motion fallback). Session maps new events to new `Show` variants; plain renderer ignores them.
2. **Live tool cells**: show `• Write path` at `content_block_start`, with input bytes while it streams; keep the running cell in the bottom pane with elapsed time; commit `✓`/`✗` + duration on result.
3. **Rendered live line**: render the unfinished line as markdown (codex prose preview) instead of raw; table holdback.
4. **Commit pacing**: codex smooth/catch-up drain so bursts scroll evenly.
5. **Status bar**: rate-limit utilization (5 h / 7 d) from `rate_limit_event`; context size of the view.
6. Later: transcript overlay (Ctrl-T) of the current turn incl. full tool output; persistent input history; edit/cancel queued messages.

Keep the inline-viewport + scrollback model (codex). pi's full re-render and opencode's alt-screen give fully live markdown but trade native scrollback, and the codex preview gets most of that benefit.
