# Data correctness, parsing, persistence and lifecycle

## Are sync and session lifecycle changes atomic and consistent?

### Takeaway
Three reproducible correctness bugs survive the existing concurrency tests: an older source read can move a session's tip backwards; concurrent attaches can leave one session attached to many threads; and a failed move can leave it attached nowhere. Per-thread Git compare-and-swap protects item appends but does not cover either read freshness or the repository-wide binding invariant. [Source](</hatimthayyil/code/ai-tools/src/chat/sync.rs:79>), [CAS](</hatimthayyil/code/ai-tools/src/git.rs:143>), [Probe results](<core-probe-output.txt>)

### Cited Findings
- **Confirmed, high priority: stale sync regresses the session cursor.** `Chat::sync` reads the entire source before entering the mutation closure. `Snapshot::ingest` then unconditionally sets `b.tip` to the last item of that read, even when a newer sync has already appended later items. The mutation retries recompute against the latest store, but reuse the old transcript. [Read outside mutation](</hatimthayyil/code/ai-tools/src/chat/sync.rs:85>), [Unconditional tip assignment](</hatimthayyil/code/ai-tools/src/chat/store.rs:583>), [Retry loop](</hatimthayyil/code/ai-tools/src/git.rs:151>)
- **Same-path, append-only reproduction:** bind a one-item transcript; append ignored complete records to widen parsing; start a child sync and pause that child during parsing; append the remaining three fixture items to the same file; sync from the parent, observing `tip=Some(3)`; resume the older child. Final store has all four items but `tip=Some(0)`. This uses process scheduling to expose an ordinary possible interleaving; no source/store mutation is injected into production code. All files and Git stores are temporary. [Probe](<core-probes.rs:88>), [Output](<core-probe-output.txt>)
- **User consequence:** the current session's branch loads from `b.tip.or(b.graft)`, so newer stored history disappears from its zoom/grep/view branch until a subsequent fresh sync repairs the tip. A stale sync that lands between compaction's sync and branch read can therefore remove recent context from the supplied view. Commands that sync first often repair this automatically, so this is not deletion of the immutable items. [Branch selection](</hatimthayyil/code/ai-tools/src/chat/cli.rs:321>), [Binding tip consumption](</hatimthayyil/code/ai-tools/src/chat/view.rs:165>), [View sync/read sequence](</hatimthayyil/code/ai-tools/src/chat/cli.rs:576>)
- **Confirmed: concurrent attachment violates uniqueness and makes detach incomplete.** `attach` first scans refs, then later updates a target ref independently; two operations can both observe no current binding and each create an attached binding. `attached` selects the latest attachment, hiding the other claims. `detach` changes only that winner, exposing another claim as current. [Lookup](</hatimthayyil/code/ai-tools/src/chat/sync.rs:64>), [Attach check/mutation](</hatimthayyil/code/ai-tools/src/chat/sync.rs:125>), [Detach](</hatimthayyil/code/ai-tools/src/chat/sync.rs:176>)
- **Concurrent attach reproduction:** 12 threads, each opening its own `Chat`, wait on one barrier and attach the same session ID to distinct thread names with an absent future transcript. All 12 calls succeed, leaving 12 attached bindings. One `detach` still leaves `Chat::attached` returning an attached thread. The test passed repeatedly; 12 is a stress fixture, while the same race needs only two calls. [Probe](<core-probes.rs:18>), [Output](<core-probe-output.txt>)
- **Confirmed: a failed move destroys the previous active attachment.** The old thread is detached before target `mutate` is attempted. Pre-create the target ref's `.lock` file, then move the session: target reference update errors after 0.10s, the command returns failure, the session is now attached nowhere. A second probe induces an ingest-validation failure with a malformed subagent filename and gets the same result. [Detach before target mutation](</hatimthayyil/code/ai-tools/src/chat/sync.rs:134>), [Target mutation](</hatimthayyil/code/ai-tools/src/chat/sync.rs:143>), [Ref-lock probe](<core-probes.rs:68>), [Validation probe](<core-probes.rs:3>), [Output](<core-probe-output.txt>)
- Existing same-thread stress tests verify deduped items and parent links after concurrent syncs, but do not assert the resulting binding tips and do not exercise cross-thread attach/move transactions. [Existing concurrency test](</hatimthayyil/code/ai-tools/tests/chat.rs:571>)
- `detach` does no final ingest. Any complete source entries since the last sync stay outside the thread if the session never reattaches. This is direct behavior, not a concurrency inference; whether it is acceptable depends on the intended detach boundary. [Implementation](</hatimthayyil/code/ai-tools/src/chat/sync.rs:187>), [Documented rationale](</hatimthayyil/code/ai-tools/ai/comments/src/chat/sync.rs.md:10>)

### Inferences
- Make source freshness part of the state transition: carry a source generation plus read watermark/prefix identity and refuse an older observation over a newer binding. A blanket `max(tip)` is less explicit and can be wrong once a harness supports rollback or a source replacement. Alternatively serialize each session's read-and-sync operation, accepting its throughput cost. The chosen fix should be tested with the same-file interleaving above. [Current tip contract](</hatimthayyil/code/ai-tools/src/chat/record.rs:35>)
- Session membership needs one repository-wide transactional authority. Options are an atomic reference transaction spanning old and target refs, or a repository/session lifecycle lock covering lookup, move and detach. A separate authoritative session catalog also permits direct lookup and explicit versions, instead of repeatedly scanning per-thread claims. Merely choosing the newest duplicate is not invariant enforcement. [Current lookup](</hatimthayyil/code/ai-tools/src/chat/sync.rs:62>)
- Complete all validation and construction before detaching, then commit both sides atomically; preparing first alone cannot make the two commits crash-safe. [Current order](</hatimthayyil/code/ai-tools/src/chat/sync.rs:133>)

### Gaps
- No production failure frequency was measured. Existing checks may usually finish quickly enough to mask these races; the probes demonstrate permitted interleavings rather than frequency. [Probe source](<core-probes.rs>)
- Final ingest on detach is a product-contract decision. Normal Stop hooks may already have flushed the latest completed turn, but explicit detach during an active turn can still leave a gap. [Stop wiring](</hatimthayyil/code/ai-tools/plugins/claude/hooks/register.ts:85>), [Detach wiring](</hatimthayyil/code/ai-tools/plugins/claude/hooks/register.ts:106>)

## Does the normalized tree preserve source identity and enough evidence for future correctness?

### Takeaway
The core tree is small and coherent, and the parser has useful fixtures for parallel tools, rewinds, compaction and interjections. The persistence contract is narrower than a transcript archive: it stores selected normalized items plus their original source lines, loses skipped events entirely, and has no independent projector version or source observation ledger. This is a design concern before adding harnesses, not evidence that the existing Claude fork dedupe is broken. [Tree](</hatimthayyil/code/ai-tools/src/chat/model.rs:76>), [Parser tests](</hatimthayyil/code/ai-tools/src/chat/claude.rs:476>), [Raw assignment](</hatimthayyil/code/ai-tools/src/chat/claude.rs:197>)

### Cited Findings
- `Tree` resolves parents only to earlier items, preventing cycles, and precomputes tips and turn/item places. `turns` splits at `User` and `Work`, with assistant-text boundaries making steps. This is a readable separation of tree structure from transcript parsing. [Tree construction](</hatimthayyil/code/ai-tools/src/chat/model.rs:84>), [Turn splitting](</hatimthayyil/code/ai-tools/src/chat/model.rs:165>)
- The Claude parser explicitly stitches tool results into write order using `tool_use_id`, chains through dropped entries, handles `logicalParentUuid`, and makes rewinds branches. Tests cover out-of-order parallel results, rewind paths, compaction and append-prefix stability. I found no additional reproduced defect in those fixture-supported cases. [Parent/tool rules](</hatimthayyil/code/ai-tools/src/chat/claude.rs:182>), [Tip/settle](</hatimthayyil/code/ai-tools/src/chat/claude.rs:253>), [Tests](</hatimthayyil/code/ai-tools/src/chat/claude.rs:528>)
- **Identity inconsistency, intentional today:** public `SourceId` contains harness, session and entry, and `Tree` hashes the whole identity. Store dedupe uses only normalized harness and entry, excluding session. Fork tests require this because Claude forks copy UUIDs under a new session. Stored copied items retain the first-import session and raw line. No actual within-Claude collision was demonstrated; do not report this as a present data-loss bug. [Public ID](</hatimthayyil/code/ai-tools/src/chat/model.rs:6>), [Storage key](</hatimthayyil/code/ai-tools/src/chat/store.rs:96>), [Append key map](</hatimthayyil/code/ai-tools/src/chat/store.rs:649>), [Fork test](</hatimthayyil/code/ai-tools/tests/chat.rs:267>)
- **Raw preservation is selective.** Each recognized item keeps its source line. Entries that produce zero kinds have no raw blob: thinking-only entries, injected context and unknown event types disappear. The existing `plain.jsonl` fixture contains all three, including `future-entry`, while its normalized shape has only four items. Thus `raw/` cannot reconstruct the full source after the harness files disappear. Dropping thinking is an explicit design choice; the broader future reprocessing limitation remains. [Parser emit/drop](</hatimthayyil/code/ai-tools/src/chat/claude.rs:172>), [Kind filter](</hatimthayyil/code/ai-tools/src/chat/claude.rs:274>), [Stored raw](</hatimthayyil/code/ai-tools/src/chat/store.rs:697>), [Fixture](</hatimthayyil/code/ai-tools/tests/fixtures/claude/plain.jsonl>), [Expected shape](</hatimthayyil/code/ai-tools/src/chat/claude.rs:477>)
- Parsing complete malformed JSON, missing UUIDs and bad timestamps silently drops their contents. Unknown kinds are treated the same as intentionally excluded known events. Only an incomplete last line is deliberately held for the next read. The API returns just items, with no diagnostics or counts of excluded/invalid records. [Read boundary](</hatimthayyil/code/ai-tools/src/chat/claude.rs:81>), [Silent returns](</hatimthayyil/code/ai-tools/src/chat/claude.rs:172>), [Invalid time](</hatimthayyil/code/ai-tools/src/chat/claude.rs:189>)
- Unknown parents are replaced with the previous chain entry; ordinary anchors pass through omitted entries. This allows damaged/unpersisted Claude parents to remain connected but also means corrupted input can silently change ancestry. The comment rationale reports old Claude logs with unpersisted parents; it does not remove the need for diagnostics. [Fallback](</hatimthayyil/code/ai-tools/src/chat/claude.rs:182>), [Rationale](</hatimthayyil/code/ai-tools/ai/comments/src/chat/claude.rs.md:20>)
- Existing normalized items never update on re-ingest. A parser correction that changes content or parent under the same source ID is ignored. The store has a format version and rejects a newer format, but no adapter/projection version; reprojecting old history requires an explicit rebuild design and source preservation. [Immutable ingest](</hatimthayyil/code/ai-tools/src/chat/store.rs:577>), [Format](</hatimthayyil/code/ai-tools/src/chat/store.rs:30>), [Readable check](</hatimthayyil/code/ai-tools/src/chat/store.rs:251>)
- Subagents have their own sequences and cannot become main-thread tips. Their persisted record points back to the main Agent call; this is a useful structural separation. However the generic `Transcript` directly embeds `claude::Subagent`, and that struct lacks an independent source session identity beyond its items. [Subagent storage](</hatimthayyil/code/ai-tools/src/chat/store.rs:607>), [Generic type imports](</hatimthayyil/code/ai-tools/src/chat/store.rs:14>), [Transcript](</hatimthayyil/code/ai-tools/src/chat/store.rs:116>), [Claude subagent](</hatimthayyil/code/ai-tools/src/chat/claude.rs:98>)
- Subagent directory discovery suppresses all directory-open/enumeration failures, and metadata read/parse failures become empty metadata. A later sync can therefore overwrite a previously informative Agent record with an empty type/description and no call when the metadata file is temporarily absent or malformed. This is static inference from the default-and-replace paths, not a fixture probe. [Discovery/defaults](</hatimthayyil/code/ai-tools/src/chat/claude.rs:110>), [Metadata replacement](</hatimthayyil/code/ai-tools/src/chat/store.rs:623>)

### Inferences
- Separate canonical event identity from the session/file in which the event was observed. Let each adapter define canonical identity and fork aliases; do not silently make every future harness promise globally unique entry IDs because Claude does. Preserve observation provenance separately if fork membership matters. [Current identity split](</hatimthayyil/code/ai-tools/src/chat/store.rs:96>)
- A source observation layer that captures complete records before filtering makes parser improvements recoverable and makes source diagnostics auditable. If full raw capture is unwanted, explicitly define what `ai chat` promises to preserve and keep a projector version plus a supported rebuild path for retained evidence. Store schema versioning already exists and should be retained. [Selected raw contract](</hatimthayyil/code/ai-tools/src/chat/model.rs:57>), [Store format](</hatimthayyil/code/ai-tools/src/chat/store.rs:31>)
- Return a parse outcome with recognized items, intentional exclusions, invalid records and unresolved parents, instead of treating all omitted events as identical. Error policy should distinguish an expected incomplete tail from a malformed complete line. [Current parse result](</hatimthayyil/code/ai-tools/src/chat/claude.rs:89>)
- Move provider-neutral transcript/subagent output types into the model layer before adding Codex/Pi. Keep provider path discovery, identity, source decoding and hook context outside the storage layer. [Current coupling](</hatimthayyil/code/ai-tools/src/chat/store.rs:14>)

### Gaps
- This review did not touch real user stores or inspect private transcripts. Comments describe prior validation on 206 Claude transcripts and 132 subagents, but that is author-reported history, not independent verification by this reviewer. [Rationale](</hatimthayyil/code/ai-tools/ai/comments/src/chat/claude.rs.md:3>)
- No confirmed real-Claude global UUID or agent-ID collision was found. The identity criticism concerns the abstraction boundary for additional harnesses, not an existing demonstrated collision. [Current assumptions](</hatimthayyil/code/ai-tools/ai/comments/src/chat/store.rs.md:28>)

## What are the storage integrity and growth tradeoffs?

### Takeaway
The current Git layout provides immutable item content, snapshot reads, per-thread atomic commits and readable small metadata records; changing databases is not necessary to repair the bugs above. Its important growth costs are repeated full-source parsing, repeated accumulated-thread index reads and loading all raw content even for structural views/counts. These should be addressed through data access boundaries and measured workload targets before deciding whether Git remains the primary store. [Layout](</hatimthayyil/code/ai-tools/src/chat/store.rs:27>), [Snapshot](</hatimthayyil/code/ai-tools/src/git.rs:220>), [Append](</hatimthayyil/code/ai-tools/src/chat/store.rs:649>)

### Cited Findings
- One thread is one Git ref. Mutations write a full tree over the old tree and compare-and-swap the ref, retrying the supplied closure when another writer moved it. Content/raw are per-item blobs, structure is segmented into 256-item index blobs. A snapshot pins a commit for all its reads. These are actual implemented strengths. [Refs](</hatimthayyil/code/ai-tools/src/chat/store.rs:225>), [CAS](</hatimthayyil/code/ai-tools/src/git.rs:143>), [Tree write](</hatimthayyil/code/ai-tools/src/git.rs:174>), [Layout constants](</hatimthayyil/code/ai-tools/src/chat/store.rs:32>), [Append](</hatimthayyil/code/ai-tools/src/chat/store.rs:669>)
- Loading all heads verifies dense sequence numbers and rejects a parent that is not earlier. Loading items verifies present kind/raw blobs. The format check rejects unknown newer store formats. These are meaningful integrity checks; there is no evidence of an ordinary append losing items in the targeted probes. [Head validation](</hatimthayyil/code/ai-tools/src/chat/store.rs:384>), [Blob validation](</hatimthayyil/code/ai-tools/src/chat/store.rs:409>), [Format check](</hatimthayyil/code/ai-tools/src/chat/store.rs:251>)
- Even a no-op sync reads/parses the whole main transcript and every subagent transcript, scans all thread refs to resolve attachment, and reconstructs the dedupe map from every head accumulated in the destination sequence. No source cursor or persistent canonical-ID index is used. The cost grows with current source size plus the total accumulated thread size, not just the new records. [Session scan](</hatimthayyil/code/ai-tools/src/chat/sync.rs:64>), [Main/subagent reads](</hatimthayyil/code/ai-tools/src/chat/sync.rs:44>), [Full file read](</hatimthayyil/code/ai-tools/src/chat/claude.rs:81>), [Full index reconstruction](</hatimthayyil/code/ai-tools/src/chat/store.rs:649>)
- `Snapshot::tree` materializes `items`, which fetches both normalized and raw blobs for every item. `Branch::load` loads the full tree plus every summary line. `Chat::list` does this for every thread merely to count turns on the newest branch. Large original tool outputs and image-bearing raw lines are therefore read for queries whose results need only structure/kinds. [All-item/raw read](</hatimthayyil/code/ai-tools/src/chat/store.rs:409>), [Tree](</hatimthayyil/code/ai-tools/src/chat/store.rs:460>), [Branch loading](</hatimthayyil/code/ai-tools/src/chat/view.rs:154>), [List](</hatimthayyil/code/ai-tools/src/chat/store.rs:185>)
- Multiple normalized items from one source entry each point to the same raw line contents. Git content addressing deduplicates the raw blob, so this is not automatically duplicate blob storage, although path entries and eagerly materialized raw Strings still repeat. [Source raw cloning](</hatimthayyil/code/ai-tools/src/chat/claude.rs:213>), [Blob writing](</hatimthayyil/code/ai-tools/src/git.rs:174>), [Raw materialization](</hatimthayyil/code/ai-tools/src/chat/record.rs:252>)
- Metadata records are a custom header/body format and indexes are custom space-delimited segments. They are simple and readable, but header newlines are normalized to spaces and index whitespace to underscores; decoders often default missing semantic string fields to empty. These are deliberately lossy metadata encodings, distinct from verbatim item bodies and source lines. [Record encoding](</hatimthayyil/code/ai-tools/src/record.rs:1>), [Index word](</hatimthayyil/code/ai-tools/src/chat/record.rs:106>), [Kind decoding defaults](</hatimthayyil/code/ai-tools/src/chat/record.rs:220>)
- The author's notes report no-op sync at roughly 70 ms and full item reads at 154 ms for one 3,669-item transcript in release, and explicitly justify full reparsing because measured cases were under 200 ms. Those measurements are useful context but do not establish bounds for a long-lived multi-session thread. [Author measurements](</hatimthayyil/code/ai-tools/ai/comments/src/chat/store.rs.md:40>)
- Targeted probes were isolated in a temporary worktree at commit `47a7aa9`; no production implementation changes or commits were made. Six selected probe tests passed, with 15 included baseline tests filtered out. The coordinator separately ran the baseline suite. [Probe source](<core-probes.rs>), [Captured output](<core-probe-output.txt>)

Reproduce in an isolated checkout at `47a7aa9`: copy `core-probes.rs` to `tests/core_review_probe.rs`, then run `cargo test --test core_review_probe core_probe_ -- --nocapture --test-threads=1`. The file includes the existing `tests/chat.rs` helpers. The same-file stale-read test uses Unix signals and temporary files, so it should run on the project's Linux environment. [Probe source](<core-probes.rs>)

### Inferences
- Introduce a structural tree/head representation carrying the few fields needed for tips, turn numbering and branch selection. Load normalized content only for selected ranges and raw source only when requested. This removes avoidable bulk reads while preserving the existing Git layout. [Current eager boundary](</hatimthayyil/code/ai-tools/src/chat/store.rs:460>)
- Source checkpoints must include parser state, source identity/generation and incomplete-tail handling; a bare byte offset is insufficient for this parser's parent/call reconnection. Benchmark long-lived threads and many subagents, including no-op sync, list and current-session compaction, before choosing the checkpoint implementation. [Parser state](</hatimthayyil/code/ai-tools/src/chat/claude.rs:143>)
- An indexed transactional store could make uniqueness/cursors/range reads simpler, while Git keeps snapshot/history ergonomics and no additional runtime service. The concrete choice is for the architecture reviewer; fixing transaction boundaries, projection identity and eager loading is necessary in either storage system. [Current mutation boundary](</hatimthayyil/code/ai-tools/src/git.rs:143>)

### Gaps
- No independent release performance benchmark, storage-growth experiment or crash/power-loss test was run. Growth costs above are source-derived complexity statements, not invented timing claims. [Relevant read paths](</hatimthayyil/code/ai-tools/src/chat/store.rs:649>)
- Corrupt-store fuzzing and malformed-input fuzzing were not performed. Current head checks were read and ordinary fixtures were exercised by the baseline suite; the targeted probes focus on lifecycle/read freshness. [Checks](</hatimthayyil/code/ai-tools/src/chat/store.rs:384>), [Probe source](<core-probes.rs>)
