## Shape

`ai chat` keeps named, repo-local **threads**: conversations that outlive harness sessions and harnesses. Coding agents (Claude Code, pi, Codex) run in their own harness; `ai chat` copies their sessions into the thread, rolls the thread up into a zoomable summary tree, and compresses the agent's context into a view of the whole thread when the session compacts.

A user keeps a few long-lived threads per repo, one per role (`developer`, `reviewer`, `researcher`). Sessions outside any thread are untouched.

## Threads and sessions

- A thread belongs to the repository containing the current directory. Every command resolves names in that repository's store only, so two repos can each have a `develop` thread.
- A session is tracked only while **attached** to a thread.
- An attached session always compacts with `ai chat`: `/compact`, auto-compaction and `/ai compress` all produce the `ai chat` view. `ai chat detach` returns `/compact` to the harness.
- `/clear` keeps its meaning: a new, unattached session. The cleared session's turns stay in the thread.
- Compaction happens only when the user or agent asks for it, or the harness auto-compacts. Starting or resuming never compacts a running context.
- A thread spans harnesses. Each harness keeps its own session files; the thread holds the turns of all of them.

## Commands

Porcelain, for users and agents. Errors are sentences. `-t <name>` names a thread; inside an attached session it defaults to the session's thread.

| Command | Effect |
|---|---|
| `ai chat start <name> [-- args]` | New Claude Code session attached to `name`, creating the thread if new. An existing thread seeds the session with its view. |
| `ai chat resume <name> [-- args]` | Continue the thread's newest session (`claude --resume <id>`), run in that session's directory. If it cannot be resumed (transcript gone), a new session seeded with the view. |
| `ai chat list` | This repo's threads: name, turns, last activity; under each, its sessions: agent, session id, attached or detached, last activity. |
| `ai chat view [-t <name>]` | Print the view. |
| `ai chat zoom [-t <name>] <id> [--tool-output]` | Open a line (see Ids, Zoom). |
| `ai chat grep [-t <name>] <regex> [--tool-output]` | Search messages, replies, tool calls and summary lines; tool output only with the flag. |
| `ai chat attach <name>` | Inside a session: attach it to `name`, creating the thread if new; its whole history is ingested, grafted onto the thread's tip. |
| `ai chat detach` | Inside a session: stop tracking; `/compact` is native again. Re-attaching catches up from the transcript. |
| `ai chat summarise [-t <name>] [<id>] [--rebuild] [--model <m>] [--dry-run]` | Write every line that is ready, or line `<id>`. `--rebuild` rewrites lines already written: line `<id>`, or every line of the thread. `--model` picks the model for this run. `--dry-run` prints each line it would write beside the line it replaces, and stores nothing. |

Inside a Claude Code session the mod adds `/ai compress`, `/ai attach <name>`, `/ai detach`, and an agent tool that queues a compaction for when the turn ends.

Plumbing, for harness glue: two-word names, hidden from help, contract below. `ai chat sync-session`, `ai chat compact-session`.

The same split holds across `ai`: `ai memory nap` and `ai notes nap` become `summarise`; `ai memory hook` (prompt reminder, run by harness hooks) becomes plumbing `ai memory prompt-hook`.

Subagents share the parent's session id in Claude Code and cannot be told apart; the attach instruction says only the main agent attaches.

## Data model

- **Item**: one normalised source entry: user message, assistant text, tool call, tool output, or marker. Records harness, session, source entry id, parent item, time, content, and the raw source lines verbatim. Thinking is dropped. Harness-injected user entries (tool outputs, hook context, `isMeta`, AGENTS.md echoes) are not user messages.
- Items form a **tree** by parent links. A branch is a path from the root. Rewinds, edits, pi `/tree`, Codex rollback and two sessions on one thread all add branches; nothing is removed.
- **Step**: assistant text, if any, plus the tool calls and outputs that follow it, up to the next assistant text. A final text-only reply is a step.
- **Turn**: a user message (or another agent's message) and the steps that answer it, up to the next one on the branch. A message sent mid-run opens a new turn. A turn is closed once a message follows it. Codex uses the word the same way (thread, turn, item).
- Ingest is idempotent by source id: a resumed session, a compacted one (same file) and a fork (copied prefix, same ids) add only new entries.
- Claude Code parallel tool calls branch the transcript's uuid tree; the adapter reattaches outputs by `tool_use_id`. Only a new user or assistant entry on an older parent is a branch.
- Native summaries (`compact_boundary`/`isCompactSummary`, Codex `compacted`, pi `compaction`) are markers, never content. Compaction does not end a session's chain: the adapter follows `logicalParentUuid`.

## Ids

Turns are numbered from 0 along the branch from the thread root. A fork shares the numbers of its common prefix; past the fork, a number is read on the session's own branch, and outside a session on the thread's newest branch.

| Id | Names |
|---|---|
| `12` | turn 12 |
| `8+4` | turns 8 to 11; a node when `n` is a power of two and `t` a multiple of it, as in `ai memory` |
| `12.3` | item 3 of turn 12; item 0 is the message that opens it |
| `12.3+7` | items 3 to 9 of turn 12: a chunk line |

The store keys lines by level and last item; ids are how they print.

## Roll-up

All summaries are written by the summariser (Sonnet via `claude -p`, as in `ai memory`); code only segments and clips.

1. **Turn line** (≤512 B): one call over the whole turn, when its clipped rendering fits the input budget. A rendering that fits 512 B is its own line, no call.
2. **Chunks**, only for a turn over the budget: its steps are cut into consecutive chunks, greedily from the turn start, each up to the budget, cut only between steps. One call per chunk writes a chunk line (≤512 B); one more call over the chunk lines writes the turn line. A single step over the budget is cut between tool calls.
3. **Binary tree over turns**: aligned pairs along a branch, `0+2`, `2+2`, then `0+4`, up.

- Clipping: each tool output to its head and tail. Raw stays whole and zoomable.
- Levels: 0 chunk line, 1 turn line, 1+k node over 2^k turns.
- Lines over a shared prefix are the same record for every branch; lines past a fork belong to their branch. Summaries never merge across branches.
- A line is written once and rewritten only by `summarise --rebuild`. Rewriting a line drops the lines above it; the next `summarise` writes them again.
- Prompt (prose, OptChat's priorities): user words near verbatim; then lasting effects, decisions and failures; then findings; least of all tool steps. Copy paths, commands, hashes and errors exactly. For file reads, say what was examined and found, with paths and line numbers, never the code. A finding names the item that holds its detail.
- **Background summariser**: `sync-session` starts `ai chat summarise` detached when it adds items. One per thread (lock). `compact-session` waits for that lock, then writes only the lines the view still needs.

## Zoom

- A node `t+n` opens two levels down: the four lines of `n/4` turns each; `t+2` its two turn lines.
- A turn opens into its chunk lines, or its items when it has none.
- Items print whole: user messages, agent messages and replies. A tool call prints on one line (`tool Bash: <command>`); its output prints only its size, unless `--tool-output`.
- Any range zooms, aligned or not: the fewest written lines that tile it.

## View

What `ai chat view` and `compact-session` print:

1. A short instruction: what the view is, how to zoom.
2. **Fold** over the closed turns of the current branch: the corrected OptChat fold (due = (T−last)/2^l), at most 64 lines. Computed fresh each time; no fold state is kept.
3. **User rail**: the newest user messages verbatim (8 KB).
4. **Open turn**: its chunk lines, its last steps (16 KB). A seeded session has no open turn of its own: the thread's last turn is headed as the previous session's last turn.

Worst case about 56 KB (14,000 tokens). Unbuilt lines fall back to their children or a placeholder.

Format: each line is `id|text`. An item's text continues on lines indented by two spaces, so text inside it (another tool's output, Markdown headings) never reads as a view line or section. Item kinds: `user`, `ai`, `agent <name>`, `tool <name>`, `output`, `error`.

## Storage

- Repo-local git: one ref per thread, `refs/ai/chat/<name>`, in the repo's common git dir. Moves with the repo, shared across worktrees, never pushed automatically.
- Same machinery as `ai memory`: commit per mutation, CAS on the ref, `format` blob (format 1), named headers, a summariser lock per thread.
- Contents: items (append-only, thread-local sequence numbers, parent links), raw source lines, lines keyed by level and last item (each records its model), session bindings (harness, session id, transcript path, graft item, attached or detached).
- Harnesses delete transcripts (Claude Code after 30 days); the thread keeps its own copy.
- Raw items carry tool output and may carry secrets. Sharing a thread is a later explicit command with redaction.

## Contract: harness glue ↔ `ai chat`

Plumbing takes `--harness <claude|pi|codex> --session <id> [--transcript <path>]`; without them it reads the harness's environment. Exit 3 means the session is not attached, with no output.

- `ai chat sync-session`: ingest new entries; start the background summariser. Fast; called on every turn end. Unattached: exit 3 at once.
- `ai chat compact-session`: sync, write the lines the view needs (waiting for the summariser's lock), print the view on stdout. The Claude mod answers `session.compact` with it. On any failure exit non-zero with the reason on stderr; the mod then falls back to native compaction and shows the reason.
- `ai chat attach <name>` / `ai chat detach`: the mod passes the session explicitly.

## Harness integration

**Claude Code**: one plugin (installed globally, e.g. `CLAUDE_CODE_PLUGIN_DIRS`, shipped by the flake):
- Mod `session.compact` (manual and auto): attached → answer with `compact-session`; unattached (exit 3) → native.
- Mod command `/ai <compress|attach <name>|detach>`; `compress` runs `/compact` deferred (`$.clock.after` + `$.command.run`).
- Mod tool for the agent: queue `/compact` for the end of the turn.
- `sync-session` on turn end (mod `classic.Stop`).

**pi** (layer 3): a global extension. Attached sessions: `session_before_compact` returns the view; `/ai compress`, `/ai attach`, `/ai detach` commands. Launch with `pi --session-id <id>`.

**Codex** (layer 3): no way to replace the native summary. Global hooks: Stop syncs; SessionStart(`compact`) injects the view after Codex's own summary (`additionalContextLimit` raised). No session-id flag: the launcher starts Codex with the prompt "Run `ai chat attach <name>`".

## Layers

1. Claude Code end to end (built): Claude adapter, thread store and sync, roll-up, view, CLI, plugin with mod.
2. Turn ids, zoom, `grep`, view format, commands (this revision); then a prose pass over every string an agent reads (view, help, prompt, errors, README), and `summarise --rebuild` of existing threads.
3. pi extension; Codex adapter and hooks.
4. Evaluation on the user's logs: probe questions after compaction (Factory method), `ai chat` view against native compaction and digest-only masking. Prompt, clip and budget changes follow the data.
