# ai notes: design

Global knowledge store for agents. Budgeted access to a growing body of facts across subjects. Prior art: `20261013T222410--notes-prior-art.md`. Storage choice: `20261012T180851--storage-landscape.md`.

## Store

Git repo of Markdown files at `~/.ai/notes`. Files are the source of truth; every change is a commit.

```
linguistics/
  _summary.md
  syntax/
    _summary.md
    minimalism/
      _summary.md
      20261013T221500---merge-is-binary.md
projects/
  ai-tools/
    ...
```

- **Directory = topic node.** Readable slug path (`linguistics.syntax.minimalism`). One global tree; repo-specific knowledge under `projects/<repo>`.
- **Leaf = one claim**, ~1 KB max. File name `<id>---<slug>.md`.
  - `id`: Denote timestamp of creation (`YYYYMMDDThhmmss`), permanent, unique across the store (bump a second on collision). It lives only in the file name, so `mv` keeps it and `grep` finds it. Links and summary hashes use the ID; the path is where the note sits now.
- Leaf frontmatter:
  - `source` (URL, file, session)
  - `confidence`: `verified | reported | speculative | assessment`
  - `checked` (date last verified), `decay` (subject half-life class)
  - `invalid_at` (set when superseded or refuted; absent = valid)
  - `links`: weak `[[id]]` references; `supersedes: <id>`
- **Hub note**: a leaf whose body is a curated list of links into other branches (Luhmann's hub cards). Feeds its parent summary like any leaf.
- **`_summary.md`**: derived. `scope` line (what is below) + `gist` (key valid claims). Frontmatter holds the hash of its children; a mismatch marks it dirty.

## Links

- **Strong**: placement in the tree. Exactly one parent. Only strong children feed a summary.
- **Weak**: `[[id]]` from any node to any node. Cross-topic structure lives here.
- **Supersedes**: new note points to old; old gets `invalid_at`. Invalid notes are excluded from summaries and hidden from views by default.

## Access

- `ai notes grep <regex>` — primary entry. Flat search over leaves and summaries, every hit with its breadcrumb (`physics › qm › decoherence: …`).
- `ai notes [view]` — top of the tree within a fixed budget (scope lines).
- `ai notes zoom <path>` — children's scope + gist.
- `ai notes show <id>` — full leaf, resolved by ID wherever it sits.

Notes are never loaded at session start. Agents consult them deliberately.

## Write

- `ai notes add <path>` — writes a leaf, then the curator (cheap model, separate from the working agent) sees the candidate and its siblings and returns one of `new | duplicate | supersedes | contradicts`. Every outcome keeps all files: duplicates link, contradictions link both and leave both valid, supersedes sets `invalid_at`. Each decision is one revertible commit.
- `ai notes mv <path> <path>`, `ai notes link <id> <id>`.
- Summaries recompute bottom-up for dirty nodes only.

## Maintenance (off the write path)

- **Fan-out bound** ~8–12 children; overflow yields a split proposal.
- **Lint**: orphans (no inbound weak links, Luhmann's "black holes"), stale (`checked` + `decay` exceeded, computed in code), dirty summaries.
- **Reorganisation**: proposals the user approves; on approval, `mv` + resummarise.

## Layers

1. Store, frontmatter, `add` (no curator), `mv`, `link`, rollup summaries, `grep`/`view`/`zoom`/`show`.
2. Curator on `add`; `supersedes`/`invalid_at`; staleness lint.
3. Split/merge proposals; import of existing `ai/research` notes into atomic leaves.
4. Full-text/embedding index (derived SQLite) when grep stops scaling.
