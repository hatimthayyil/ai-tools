# ai chat CLI, lifecycle and Claude integration

## Are commands consistent, fresh and safe to compose?

### Takeaway

The CLI has a coherent small command vocabulary, good sentence-level errors, bounded output and a useful explicit unattached exit code. The largest DX problems are hidden side effects of reads, different freshness rules between commands, and branch-dependent identifiers whose continuation commands do not preserve their meaning.

### Cited Findings

- **Baseline: 180 Rust tests passed, 1 ignored, 0 failed** using `CARGO_TARGET_DIR=/hatimthayyil/code/ai-tools/target cargo test --all-targets` at `47a7aa9` / version 0.9.0. Breakdown: 80 library unit tests passed and 1 ignored, chat 15, chat_cli 16, CLI 17, memory 23, notes 13, rollup 16. No source fixes were made. Chat CLI tests already cover errors, hidden plumbing, lifecycle happy paths, free summaries and paging on an unchanged branch. [CLI tests](/hatimthayyil/code/ai-tools/tests/chat_cli.rs:300), [chat tests](/hatimthayyil/code/ai-tools/tests/chat.rs:1), [rollup tests](/hatimthayyil/code/ai-tools/tests/rollup.rs:1)

- **P2 correctness: view, zoom and grep use inconsistent freshness.** `view` syncs an attached current session before rendering; `zoom`, `grep`, `list` and `summarise` read only persisted data. The plugin sync happens on a timer 1,100 ms after Stop and at session end, so an agent querying its own current turn before Stop or during the delay gets stale results. Exact isolated probe: attach a 2-turn transcript, replace it with a 3-turn version; `ai chat grep 'question 2'` prints `No match.` (exit 0), `ai chat zoom 2.0` prints `This branch has no 2.0.` (exit 1). Run `ai chat view`; both then find the new turn immediately. Help says `grep` searches a thread and `zoom` opens a turn; it does not disclose a stale-snapshot contract. Suggest one consistent acquisition step: resolve session, sync where appropriate, freeze a snapshot, then execute a pure query. Alternatively explicit sync and snapshot modes, with freshness shown, but avoid making users learn incidental command ordering. [view](/hatimthayyil/code/ai-tools/src/chat/cli.rs:568), [zoom](/hatimthayyil/code/ai-tools/src/chat/cli.rs:611), [grep](/hatimthayyil/code/ai-tools/src/chat/cli.rs:646), [summarise](/hatimthayyil/code/ai-tools/src/chat/cli.rs:711), [Stop timer](/hatimthayyil/code/ai-tools/plugins/claude/hooks/register.ts:85)

- **P2 correctness: even view's commit-pinned continuation can switch branches.** Branch resolution is derived again from the current attachment/environment. The emitted next command carries `-t` and `--at`, but no session or branch tip. Exact probe: session `pages1` has 64 fixture turns; session `pages2` is attached afterwards and grafts one new turn. View `paging` as pages1 with `CLAUDE_CODE_SESSION_ID=pages1`; part 1 ends `Next: ai chat view -t paging --part 2 --at <commit>`. Execute that exact next command in pages1 versus outside any session. Both exit 0, both use the same commit, but the results differ (15,823 versus 15,525 characters); the outside result includes `64.0|user: NEW-PAGE question 0` whereas the session result ends at the old turn `63.1`. This also affects scripts using explicit `--session` when the next command drops it. `zoom` and `grep` do not even pin a commit and also omit session/branch. Suggest a cursor binding thread identity + commit + branch tip + query options; expose an explicit branch selector for ordinary commands. [pick](/hatimthayyil/code/ai-tools/src/chat/cli.rs:291), [read_branch](/hatimthayyil/code/ai-tools/src/chat/cli.rs:321), [view continuation](/hatimthayyil/code/ai-tools/src/chat/cli.rs:589), [zoom continuation](/hatimthayyil/code/ai-tools/src/chat/cli.rs:624), [grep continuation](/hatimthayyil/code/ai-tools/src/chat/cli.rs:682)

- **Design issue, confirmed execution: `view` is a model-running write operation presented as a read.** First view calls `fresh_view`, which builds missing summary lines through a Claude backend and commits them. `ai.chat.summarise=false` stops only background workers; it does not stop the view from invoking Claude. Exact fake-executable probe: disable summarisation in a temporary repository; attach two turns with about 4 KB of text each; `ai chat view -t modelread` invokes `claude -p --model sonnet --effort medium --input-format stream-json ... --safe-mode`. No live model was used. A user inspecting an existing chat can therefore consume plan/API usage, wait up to the build deadline, write git history, or fail for lack of a Claude executable. Help only promises “print a thread's view.” Suggest pure `view` over stored summaries with the existing fallback rendering; make summary construction an explicit `summarise` operation, and reserve sync/build/wait orchestration for compaction. If on-read generation remains, disclose it in help and provide an explicit no-model mode. [help](/hatimthayyil/code/ai-tools/src/chat/cli.rs:72), [fresh_view](/hatimthayyil/code/ai-tools/src/chat/cli.rs:342), [background-only switch](/hatimthayyil/code/ai-tools/src/chat/summarise.rs:63), [backend](/hatimthayyil/code/ai-tools/src/chat/summarise.rs:54)

- **The read can silently degrade after model failure.** With the fake Claude above returning exit 0 without a valid result, view still exits 0 and writes no stderr; its output uses unsummarised fallback. `build` returns failures in `Built`, but `fresh_view` discards this result. This can be a deliberate available-output policy, but callers cannot tell whether the promised build completed; default compaction will accept this partial view. Suggest surface completeness/failure metadata separately, and define when compact-session should fall back to native compaction. [discarded build result](/hatimthayyil/code/ai-tools/src/chat/cli.rs:348), [Built failures](/hatimthayyil/code/ai-tools/src/chat/summarise.rs:79), [plugin accepts any nonempty success](/hatimthayyil/code/ai-tools/plugins/claude/hooks/register.ts:28)

- **`summarise --dry-run` runs models too.** It means “generate but do not persist,” not “preview planned work.” Exact fake probe executed Claude and then reported `Dry run: 0 lines, 0 by the model; nothing stored.` plus `Failed 0: claude exited (code Some(0)) before its result: no error output`, exit 1, stdout only. No real model requests occurred. Help says it prints each line it would write, so generation is arguably allowed, but spending in a flag commonly used for planning deserves explicit wording or distinct `--plan` and generated-preview modes. [dry-run help](/hatimthayyil/code/ai-tools/src/chat/cli.rs:136), [dry-run execution](/hatimthayyil/code/ai-tools/src/chat/cli.rs:767), [dry_run implementation](/hatimthayyil/code/ai-tools/src/chat/summarise.rs:280)

- **Stored branches are insufficiently addressable.** List reports only a branch count. Normal read commands offer a thread and session selector, but `pick` retains the named/current session only if it is currently attached to the thread. Passing a detached historical session's id therefore reads the newest branch rather than that binding. A rewind's old branch is retained in storage but has no ordinary CLI branch/tip selector. This limits recovery and makes ids such as `12.3` unsuitable as permanent citations outside a branch. Add explicit branch/session-history selection and a branch list with stable tips; retain short turn coordinates as display addresses within a pinned branch. [list output](/hatimthayyil/code/ai-tools/src/chat/cli.rs:447), [session filtering](/hatimthayyil/code/ai-tools/src/chat/cli.rs:298), [branch policy](/hatimthayyil/code/ai-tools/src/chat/cli.rs:319), [branch-local ids](/hatimthayyil/code/ai-tools/src/chat/model.rs:303)

### Inferences

- A small structured output option would help agents and scripts: list sessions with paths/tips, query results with ids and branch/snapshot identity, cursor, completeness and warnings. Current human prose and exit 3 are usable, but depend on ambient environment and contain no self-describing snapshot identity. Keep shared rendering and command business logic separate rather than forking two implementations. [current interface](/hatimthayyil/code/ai-tools/src/chat/cli.rs:49), [current pick policy](/hatimthayyil/code/ai-tools/src/chat/cli.rs:291)
- The proven happy-path tests are useful, but the next test layer should cross command boundaries: read after transcript growth, continuation after session-context changes, detach before delayed Stop sync, missing plugin/executable, and model failure during view. Most current fixtures use `ai.chat.summarise=false` and free short lines, so they do not expose model side effects. [sandbox setup](/hatimthayyil/code/ai-tools/tests/chat_cli.rs:38), [view tests](/hatimthayyil/code/ai-tools/tests/chat_cli.rs:450)

### Gaps

- Persistent [probe source](evidence/cli-probes.mjs) and [representative output](evidence/cli-probes-output.txt) are retained beside these notes. It uses `/tmp/ai-chat-review-cli-binary`, copied immediately after the unmodified baseline build; reproduce after copying a baseline `target/debug/ai` to that path and running Node. All transcripts, HOME/Claude config, git config and fake Claude were temporary. No real stores or sessions were accessed by probes.
- I did not live-test Claude model behaviour, auto-compaction under sustained load, non-Claude harnesses, enormous repositories or external pagers. Known Codex/Pi absence is intentionally not a defect in this review.

## Do start, resume, attach and detach preserve lifecycle intent?

### Takeaway

The existing launcher cleanly delegates argv and uses the original session directory on resume. Lifecycle changes need a precise contract for what gets synced and which session “newest” means before adding more harnesses.

### Cited Findings

- **P2 correctness: detach can omit conversation that occurred before detaching.** The detach command only updates binding state; it never ingests the latest transcript. Exact probe: attach s1 with two turns, let view sync a third, append a fourth complete turn to the transcript, then `ai chat detach` succeeds. `ai chat sync-session --session s1` subsequently exits 3 silently, and `ai chat grep -t dev 'question 3'` reports `No match.` The transcript data is recoverable by reattaching, but the detached thread permanently lacks it unless reattached. A real trigger is `/ai detach` within the 1,100 ms Stop-sync delay, or detaching during an in-progress turn. Suggest flush/ingest what exists before marking detached, plus define a detach boundary for late transcript writes; do not depend on later Stop sync after the binding is inactive. [CLI detach](/hatimthayyil/code/ai-tools/src/chat/cli.rs:514), [store detach](/hatimthayyil/code/ai-tools/src/chat/sync.rs:175), [inactive sync](/hatimthayyil/code/ai-tools/src/chat/sync.rs:79), [delayed Stop](/hatimthayyil/code/ai-tools/plugins/claude/hooks/register.ts:85)

- **P2 edge-case: resume ignores a newly started session until it ingests an item.** It selects `max_by_key((b.tip,b.attached))`, so every populated session beats every newer empty session. Probe: attach/populate s1, `ai chat start dev` creates a new UUID binding, leave its transcript empty, `ai chat resume dev` launches `--resume s1`, not the newer session. This matters after starting/exiting a session before its first retained user message, and potentially after failure to start. The README promises the thread's “newest session.” Decide whether that means most recently launched, attached, active, or most recently ingested source item; store/use an explicit relevant timestamp. [resume selection](/hatimthayyil/code/ai-tools/src/chat/cli.rs:416), [README contract](/hatimthayyil/code/ai-tools/README.md:49), [start binds before exec](/hatimthayyil/code/ai-tools/src/chat/cli.rs:393)

- **Failure recovery/design: start and resume mutate before executable success.** Launch records an attached binding with a predicted future transcript, then `exec`s `claude`; failure to find/execute it leaves the thread/binding behind. Resume similarly reattaches the selected session before exec succeeds. Fake executable probes verify that the caller's exit status is Claude's status because the process is replaced. A readiness check before mutation avoids common missing-executable failures; fully handling startup failure may require a launched/pending state or a spawned supervisor. Do not make every launch complicated solely to chase a rare immediate runtime failure, but expose pending/failed state if bindings remain. [exec](/hatimthayyil/code/ai-tools/src/chat/cli.rs:383), [start](/hatimthayyil/code/ai-tools/src/chat/cli.rs:393), [resume](/hatimthayyil/code/ai-tools/src/chat/cli.rs:425)

### Inferences

- A reusable lifecycle service should expose resolve/launch/attach/sync/detach independently of clap and Claude. Session identity, transcript path, launch cwd and branch tip belong in a shared typed structure; harness-specific discovery and launch syntax belong in adapters. This is a straightforward boundary for Codex/Pi work, rather than extending the CLI's repeated Claude matches. [Current and Session](/hatimthayyil/code/ai-tools/src/chat/cli.rs:160), [transcript adapter switch](/hatimthayyil/code/ai-tools/src/chat/cli.rs:206), [reader switch](/hatimthayyil/code/ai-tools/src/chat/sync.rs:39)
- Define whether attach moves are atomic and whether delayed callbacks may update an old attachment. The core reviewer owns the stronger confirmed concurrent attach, failed transfer and stale-tip findings; these interact directly with CLI branch resolution and should precede cosmetic DX refactors. [attach sequencing](/hatimthayyil/code/ai-tools/src/chat/sync.rs:125)

### Gaps

- The empty-session resume edge is confirmed; the intended definition of newest is a product question, so do not present timestamp sorting as an unquestionable universal fix.
- `start` intentionally does not inject/load the plugin. This is a documented prerequisite; report installation DX, not an unconditional start bug. [README plugin prerequisite](/hatimthayyil/code/ai-tools/README.md:60)

## Is Claude integration installable, independently testable and robust?

### Takeaway

The plugin is a supported stock Claude mod and its offline tests pass. Packaging and operational visibility need attention; an already documented instruction-restoration defect needs current-version revalidation before relying on custom compaction.

### Cited Findings

- **Plugin suite: 13 tests passed, 0 failed** with `claude plugin test plugins/claude`, Claude Code 2.1.302. `claude plugin validate plugins/claude` passed with warnings: missing author, user-installed lifecycle hooks bypassed for managed orgs, and gating hooks without `.catch`. The tests mock `process.run` and clocks; no API/model was called. Initial sandbox run failed before loading tests (`its run ended without a report (exit code 0)`); rerunning outside the sandbox passed in 0.54 s, so this was environment-related rather than a plugin defect. [test code](/hatimthayyil/code/ai-tools/plugins/claude/tests/ai.test.ts:26), [plugin entry](/hatimthayyil/code/ai-tools/plugins/claude/hooks/register.ts:52)

- **P2 distribution correctness: Cargo installation does not ship the required plugin.** Cargo.toml's include list excludes `plugins`, verified by `cargo package --list --allow-dirty` (no plugin entries). There is no binary installer/export command or Cargo build installation step for the asset. README presents `cargo install ai-tools` and then says the plugin is in `share/ai/plugins/claude` “of the package”; that path exists only for the Nix package, whose postInstall copies the plugin. Cargo users therefore cannot follow that installation path without obtaining repository assets separately. Suggest ship plugin bytes and an explicit `ai ... install/export` path, or a standalone versioned plugin package/marketplace with clear Cargo instructions. Merely adding `plugins` to Cargo include would make sources available but would not cause cargo install to copy them into share/. [Cargo manifest](/hatimthayyil/code/ai-tools/Cargo.toml:8), [README install](/hatimthayyil/code/ai-tools/README.md:12), [README plugin path](/hatimthayyil/code/ai-tools/README.md:60), [Nix install](/hatimthayyil/code/ai-tools/flake.nix:35)

- **Runtime is stock-supported, with a version requirement missing from README.** Official docs say terminal mods are on by default in Claude Code v2.1.287 and later, and support TypeScript modules under `hooks/hooks.json`; current local version 2.1.302 validates and runs this plugin's tests. This is not private-fork-only functionality. State the tested/minimum version and caveat applicable org policy in troubleshooting. [Official mods overview](https://code.claude.com/docs/en/plugins/mods/overview#turn-mods-on-or-off), [Official module layout](https://code.claude.com/docs/en/plugins/mods/reference#files), [local manifest](/hatimthayyil/code/ai-tools/plugins/claude/.claude-plugin/plugin.json:1)

- **Known instruction-restoration gap, requiring revalidation.** `register.ts` returns replacement messages directly from `session.compact`, skipping `next`. The project's own comments record an end-to-end observation on Claude 2.1.300: this skips the built-in agents-md compaction handler, so nested CLAUDE.md/AGENTS.md files disappear from context and are not reattached when subsequently read. That can make the agent violate local instructions after compaction. HOWEVER latest upstream agents-md source no longer registers session.compact; it clears delivered sets in prompt.context. I did not reproduce this on installed 2.1.302, so don't claim it is freshly confirmed there. Require an offline real-engine integration probe or bounded live test on the supported version: read nested instructions, custom-compact, read same directory, inspect effective context. If broken, adapt integration or keep native compaction until restoration is preserved; avoid duplicating all Claude instruction-loading logic in this plugin. [replacement hook](/hatimthayyil/code/ai-tools/plugins/claude/hooks/register.ts:77), [recorded consequence](/hatimthayyil/code/ai-tools/ai/comments/plugins/claude/hooks/register.ts.md:14), [upstream current implementation](https://github.com/anthropics/claude-code/blob/main/mods/agents-md/hooks/register.ts)

- **The 1,100 ms sleep is a source-format flush assumption, not synchronization.** Local comments measured a 1-second Claude transcript buffer and chose 1,100 ms; plugin tests advance an artificial clock, without a real writer. The final end sync runs after `next(e)` but still within Claude's total session.end hook budget (official default 1.5 seconds); large or lock-contended sync can exceed it. This is a bounded current implementation rather than proof that every last transcript record was ingested. Prefer a documented flush/append signal or stable file barrier when available; adapter-specific sync policy should be explicit and tested. [flush timer](/hatimthayyil/code/ai-tools/plugins/claude/hooks/register.ts:3), [session.end](/hatimthayyil/code/ai-tools/plugins/claude/hooks/register.ts:91), [measured assumption](/hatimthayyil/code/ai-tools/ai/comments/plugins/claude/hooks/register.ts.md:13), [official hook budgets](https://code.claude.com/docs/en/plugins/mods/reference#limits)

### Inferences

- Add a small doctor/status command reporting current harness/session/thread/branch, transcript path and last sync, detected plugin/runtime version, summariser status/failure log path, and whether model calls are enabled. This addresses today's opaque background failures and will be more useful once three harnesses exist. Existing errors already provide good human guidance, and the narrow hidden plumbing surface should remain. [list](/hatimthayyil/code/ai-tools/src/chat/cli.rs:447), [thread logging](/hatimthayyil/code/ai-tools/src/chat/store.rs:279), [background spawn](/hatimthayyil/code/ai-tools/src/chat/summarise.rs:63)
- The generated Claude API typings and tsc setup are absent from a fresh checkout/devenv; comments instruct an interactive plugin session to generate them. The flake's normal check runs Rust tests, not plugin tests. Make offline plugin validation/test commands and type-check prerequisites reproducible in devenv/checks; keep live paid tests opt-in. [type-check instructions](/hatimthayyil/code/ai-tools/ai/comments/plugins/claude/hooks/register.ts.md:20), [devenv](/hatimthayyil/code/ai-tools/devenv.nix:20), [Nix checks](/hatimthayyil/code/ai-tools/flake.nix:39)

### Gaps

- Managed-org restrictions, host context restoration, actual transcript flush timing and model-result semantics were not live-tested. Do not infer a broken installed plugin merely from validate warnings.
- Official docs reference can lag the installed version (it labels itself v2.1.290), and the latest agents-md source differs from the project's recorded 2.1.300 implementation; the exact supported-version types and a targeted integration test should settle the compaction contract. [reference version caveat](https://code.claude.com/docs/en/plugins/mods/reference)
