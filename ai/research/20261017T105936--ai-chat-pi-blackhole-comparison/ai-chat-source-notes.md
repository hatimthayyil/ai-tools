# Current ai chat for the pi-blackhole comparison

Scope: source at `a0b8691b00040fd840a1dbb8d4c317991fc0a4f6`; README, accepted design, current implementation and the existing review. Source links below point to the main checkout's matching files. No LLM calls or new correctness probes were run.

## What does ai chat actually preserve and expose?

### Takeaway

`ai chat` is a persistent, named conversation layer over Claude sessions, with a branch-aware archive and a binary summary tree. Its distinctive product capability is continuing a repo-local thread across sessions, then recovering detail with branch-relative addresses and search.

### Cited Findings

- README promises named conversations spanning agent sessions; `start`, `resume`, `list`, `view`, `zoom`, `grep`, `summarise`, attach/detach and replacement compaction are implemented. Accepted design additionally describes cross-harness threads, but Pi/Codex are future work: the live transcript dispatcher accepts only Claude, and launching calls `claude`. — [README](/hatimthayyil/code/ai-tools/README.md:46), [accepted design](/hatimthayyil/code/ai-tools/ai/research/20261014T002322--chat-design.md:135), [dispatcher](/hatimthayyil/code/ai-tools/src/chat/sync.rs:39), [launch](/hatimthayyil/code/ai-tools/src/chat/cli.rs:383)
- Threads are independent Git refs under `refs/ai/chat/<name>`, with separate normalised items, raw source lines, session bindings and summary records. Every mutation publishes a Git commit using per-ref compare-and-swap. New session roots graft onto the thread's newest item; copied prefixes deduplicate by harness plus event id. Branches remain in the graph rather than being overwritten. — [layout](/hatimthayyil/code/ai-tools/src/chat/store.rs:27), [graft](/hatimthayyil/code/ai-tools/src/chat/sync.rs:145), [ingest](/hatimthayyil/code/ai-tools/src/chat/store.rs:567), [Git publication](/hatimthayyil/code/ai-tools/src/git.rs:143), [graph](/hatimthayyil/code/ai-tools/src/chat/model.rs:84)
- Preservation is narrower than a complete transcript backup. Recognised content keeps the original JSON source line; thinking-only, injected context and unknown events that emit no item leave no raw record. Malformed JSON/missing UUIDs also silently disappear. Native compaction summaries become markers rather than recursively summarised content. — [raw assignment](/hatimthayyil/code/ai-tools/src/chat/claude.rs:172), [recognised kinds](/hatimthayyil/code/ai-tools/src/chat/claude.rs:274), [injected content filtering](/hatimthayyil/code/ai-tools/src/chat/claude.rs:310), [existing review](/hatimthayyil/code/ai-tools/ai/research/20261016T212002--chat-review.md:41)
- A turn is one user/agent message plus its response; steps start at assistant text. Addresses are `12` (turn), `8+4` (turn range), `12.3` (item), `12.3+7` (item range). These are relative to a branch, not globally unique citations. Inside an attached session commands choose its branch; outside they choose the newest branch. Zoom opens summary nodes two levels down, turns into chunks/items, and single items whole; tool output requires `--tool-output`. Grep searches normalised content, tool calls and summaries on that selected branch, not every retained branch. — [turns](/hatimthayyil/code/ai-tools/src/chat/model.rs:152), [ids](/hatimthayyil/code/ai-tools/ai/research/20261014T002322--chat-design.md:63), [branch choice](/hatimthayyil/code/ai-tools/src/chat/cli.rs:291), [zoom](/hatimthayyil/code/ai-tools/src/chat/view.rs:197), [grep](/hatimthayyil/code/ai-tools/src/chat/view.rs:237)

### Inferences

- Preserving thread identity and cross-session detail is a stronger capability than merely supplying a better summary for one running session. Whether Pi-blackhole addresses that separate problem must be judged from its source.
- The graph and retrieval are worth retaining even if compaction scheduling, budgets or storage change. The existing review supports preserving the parser/planner/executor/view boundaries. — [review](/hatimthayyil/code/ai-tools/ai/research/20261016T212002--chat-review.md:39)

### Gaps

- No evidence that ordinary Git push/clone backs up custom chat refs; accepted design explicitly says refs are not pushed automatically. A reliable backup/share contract remains a product choice. — [design](/hatimthayyil/code/ai-tools/ai/research/20261014T002322--chat-design.md:113), [review](/hatimthayyil/code/ai-tools/ai/research/20261016T212002--chat-review.md:53)

## What reaches the model after compaction, and what does it cost?

### Takeaway

Attached Claude compaction replaces the whole conversational context with one rendered user message: an older summary fold, a recent-user rail and the latest turn. It does not retain a configurable untouched suffix of recent assistant/tool messages, and its sizes are byte/line targets rather than token budgets.

### Cited Findings

- The view folds closed turns to at most 64 lines, prioritising detail by recency; it adds approximately 8,000 bytes of newest user messages and approximately 16,000 bytes of the latest turn. Item words are clipped to 8,000 bytes, tool input/output to 2,000 bytes; latest items have keep-at-least-one exceptions. Older omitted latest-turn units receive an addressable `(not shown)` marker. Design's approximately 56 KB/14K-token estimate is an estimate, not measured token accounting. — [constants](/hatimthayyil/code/ai-tools/src/chat/view.rs:18), [fold](/hatimthayyil/code/ai-tools/src/chat/view.rs:61), [rail](/hatimthayyil/code/ai-tools/src/chat/view.rs:465), [open turn](/hatimthayyil/code/ai-tools/src/chat/view.rs:486), [item clips](/hatimthayyil/code/ai-tools/src/chat/view.rs:568), [design estimate](/hatimthayyil/code/ai-tools/ai/research/20261014T002322--chat-design.md:98)
- The newest turn remains structurally open until another user/agent message follows. Consequently, at automatic compaction the triggering prompt is in the open turn and the preceding assistant work may already be in the summary fold. Missing summaries fall back through built children; where none exist, a closed turn can become only `(not summarised yet)`. — [turn closure](/hatimthayyil/code/ai-tools/src/chat/model.rs:160), [view closure](/hatimthayyil/code/ai-tools/src/chat/view.rs:323), [fallback rendering](/hatimthayyil/code/ai-tools/src/chat/view.rs:396), [auto prompt observation](/hatimthayyil/code/ai-tools/ai/comments/plugins/claude/hooks/register.ts.md:15)
- Normal turns get one summary line; turns over a clipped 48 KiB rendering become step-aware chunks, then one turn line over chunk lines; adjacent closed-turn lines merge in aligned binary pairs. Tool data is clipped to 4 KiB for summarisation. A source fitting 512 bytes is copied without a model call. Summary lines target 512 bytes; five length attempts choose the shortest even if it still exceeds the target. — [input/clip](/hatimthayyil/code/ai-tools/src/chat/rollup.rs:14), [chunking](/hatimthayyil/code/ai-tools/src/chat/rollup.rs:39), [binary nodes](/hatimthayyil/code/ai-tools/src/chat/rollup.rs:187), [free lines](/hatimthayyil/code/ai-tools/src/chat/rollup.rs:372), [length retries](/hatimthayyil/code/ai-tools/src/memory/compact.rs:86)
- Summaries prioritise user wording, lasting decisions/effects/failures, findings, then tool steps; paths/hashes/errors should survive exactly and findings cite source items. This is an intentional recoverability policy, not demonstrated fidelity. — [summary prompt](/hatimthayyil/code/ai-tools/src/chat/prompts/compact.txt:27)
- The summariser is a separate `claude -p` process, default `sonnet` (also influenced by `AI_MEMORY_MODEL`), selected by Git `ai.chat.model` or per-command `--model`. It runs up to eight independent lines concurrently, persists completed lines and records model provenance. A background worker runs after sync, while compaction/view can wait/build for up to 60 seconds. Disabling `ai.chat.summarise` disables background work only: `view` can still call Claude and write summaries. — [config/backend](/hatimthayyil/code/ai-tools/src/chat/summarise.rs:27), [default](/hatimthayyil/code/ai-tools/src/memory/claude.rs:39), [parallel jobs](/hatimthayyil/code/ai-tools/src/chat/summarise.rs:537), [stored provenance](/hatimthayyil/code/ai-tools/src/chat/record.rs:97), [on-read build](/hatimthayyil/code/ai-tools/src/chat/cli.rs:339), [60 seconds](/hatimthayyil/code/ai-tools/src/chat/cli.rs:36)
- `summarise --rebuild` removes/rebuilds summaries; rebuilding one line invalidates its ancestors. `--dry-run` generates real model previews and stores nothing. Build failures are recorded by the executor, but `fresh_view` discards its `Built` report and can return exit 0 with fallback/placeholders; the plugin treats nonempty successful output as complete. Thus model failure need not trigger native compaction fallback. — [rebuild](/hatimthayyil/code/ai-tools/src/chat/summarise.rs:187), [single-line invalidation](/hatimthayyil/code/ai-tools/src/chat/summarise.rs:244), [dry-run](/hatimthayyil/code/ai-tools/src/chat/summarise.rs:300), [discarded result](/hatimthayyil/code/ai-tools/src/chat/cli.rs:351), [plugin success](/hatimthayyil/code/ai-tools/plugins/claude/hooks/register.ts:28)

### Inferences

- Once background work is complete, replacement compaction can be cheap; it still waits 1.1 seconds for transcript flushing. If summaries are missing, it can spend time/model calls during the read. These are different operating regimes and should not be presented as one constant latency. — [flush wait](/hatimthayyil/code/ai-tools/plugins/claude/hooks/register.ts:77), [on-read generation](/hatimthayyil/code/ai-tools/src/chat/cli.rs:342)
- A recent-message suffix, token-aware cap, clear build completeness/failure status and separate plan-versus-generated-preview commands are plausible improvements. Compare Pi-blackhole's actual mechanisms before calling them direct borrowings.

### Gaps

- No head-to-head fidelity/cost/latency benchmark with Pi-blackhole. Existing cost research estimates calls/input bytes for alternative schemes on old logs, excludes prompt bytes, uses characters/bytes rather than billed tokens, and is not a benchmark of the final policy. Existing plugin notes contain small version-specific end-to-end observations (e.g. ready-view compaction), not general performance evidence. — [cost methodology](/hatimthayyil/code/ai-tools/ai/research/20261014T200729--step-compaction-cost.md:29), [limitations](/hatimthayyil/code/ai-tools/ai/research/20261014T200729--step-compaction-cost.md:168), [plugin observations](/hatimthayyil/code/ai-tools/ai/comments/plugins/claude/hooks/register.ts.md:23)

## Which caveats should affect the practical verdict?

### Takeaway

The current product is a working Claude-specific integration with valuable retrieval, but existing correctness defects should be fixed before expanding harnesses. These defects were reproduced in the existing review and remain visible in current source; this investigation did not rerun its probes.

### Cited Findings

- Claude plugin handles manual/automatic compaction identically for attached main sessions, seeds new starts, syncs at Stop after 1,100 ms and at session end, exposes `/ai attach|detach|compress` and an agent `compress` tool. Unattached/subagent compactions remain native. It returns one `{role: 'user', text: view}` message on replacement. — [start seed](/hatimthayyil/code/ai-tools/plugins/claude/hooks/register.ts:68), [replacement and sync](/hatimthayyil/code/ai-tools/plugins/claude/hooks/register.ts:77), [commands/tool](/hatimthayyil/code/ai-tools/plugins/claude/hooks/register.ts:97)
- Cargo packaging does not ship the plugin assets; only Nix's post-install copies `plugins/claude` into the README's documented `share/ai/plugins/claude` location. The plugin must also be loaded in Claude independently. The review confirmed this distribution gap. — [Cargo include list](/hatimthayyil/code/ai-tools/Cargo.toml:8), [Nix install](/hatimthayyil/code/ai-tools/flake.nix:35), [README setup](/hatimthayyil/code/ai-tools/README.md:60), [review](/hatimthayyil/code/ai-tools/ai/research/20261016T212002--chat-review.md:33)
- Review-reproduced high-priority state defects remain: an older sync observation can regress `binding.tip`; concurrent attach operations can claim the same session in multiple threads; a failed move can leave it detached everywhere. The source still reads before a per-thread mutation, assigns tip unconditionally and detaches the old thread before publishing the target. — [review evidence](/hatimthayyil/code/ai-tools/ai/research/20261016T212002--chat-review.md:9), [read before mutation](/hatimthayyil/code/ai-tools/src/chat/sync.rs:85), [tip assignment](/hatimthayyil/code/ai-tools/src/chat/store.rs:583), [move](/hatimthayyil/code/ai-tools/src/chat/sync.rs:125)
- Review-reproduced summary identity/cache issues remain: chunk keys contain level+last item only, and first source wins; arbitrary forks inside a long step can yield different source spans with the same key. This is a generic graph defect, not evidence that ordinary Claude user-message forks fail. Stored summaries have no exact input/recipe/projection hash, so parser or prompt changes can reuse stale lines until explicit rebuild. — [review](/hatimthayyil/code/ai-tools/ai/research/20261016T212002--chat-review.md:15), [key](/hatimthayyil/code/ai-tools/src/chat/rollup.rs:163), [first writer](/hatimthayyil/code/ai-tools/src/chat/rollup.rs:287), [cache acceptance](/hatimthayyil/code/ai-tools/src/chat/summarise.rs:425)
- Query consistency defects remain: `view` syncs the current transcript first; `zoom`/`grep`/`list`/`summarise` read stored state. View pagination pins a Git commit but omits branch/session; zoom/grep continuations also omit snapshot identity. Ambient session therefore changes what an identical short id or emitted continuation means. Detached sessions are not selectable as historical branches through `--session`. — [review reproductions](/hatimthayyil/code/ai-tools/ai/research/20261016T212002--chat-review.md:23), [view](/hatimthayyil/code/ai-tools/src/chat/cli.rs:568), [continuation](/hatimthayyil/code/ai-tools/src/chat/cli.rs:589), [stored-only zoom/search](/hatimthayyil/code/ai-tools/src/chat/cli.rs:611), [attached-only pick](/hatimthayyil/code/ai-tools/src/chat/cli.rs:291)
- README's unqualified "newest session" actually uses maximum `(tip, attached)`, so an older populated session beats a newer empty one. Detach does not perform final ingestion. — [resume](/hatimthayyil/code/ai-tools/src/chat/cli.rs:416), [detach](/hatimthayyil/code/ai-tools/src/chat/sync.rs:175), [existing lifecycle probes](/hatimthayyil/code/ai-tools/ai/research/20261016T212002--chat-review.md:31)

### Inferences

- Useful near-term priorities: reliable unique session ownership and source ordering; stable branch/snapshot retrieval; truthful summary failure/completeness reporting; bounded compaction work; then harness expansion. Existing review already makes this ordering. — [review recommendations](/hatimthayyil/code/ai-tools/ai/research/20261016T212002--chat-review.md:70)

### Gaps

- The plugin's replacement hook skipped nested-instruction restoration on Claude 2.1.300. The later review explicitly did not reproduce that failure on 2.1.302; do not state it as a confirmed current defect. A supported-version end-to-end check remains needed. — [version-specific observation](/hatimthayyil/code/ai-tools/ai/comments/plugins/claude/hooks/register.ts.md:14), [review caveat](/hatimthayyil/code/ai-tools/ai/research/20261016T212002--chat-review.md:35)
