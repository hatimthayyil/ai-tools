# pi-blackhole compared with ai chat

## What does the checked-out pi-blackhole actually do?

### Takeaway
The local project is a Pi extension that manages live context with deterministic structural extraction plus optional model-written facts. It solves a related problem to `ai chat`, but does not build the same binary summary tree or provide the same named, Git-backed archive spanning attached agent sessions.

### Cited Findings
- Comparison target is the clean local checkout `/hatimthayyil/code/pi-blackhole`, main at `9be95be6baf56c42ca88bba139ee9ad0470c4de7`, package version **0.5.9**; origin is the user's fork, upstream `k0valik/pi-blackhole`. Online upstream main currently reports **0.5.13**; do not conflate either with the installed npm package. — [local package](/hatimthayyil/code/pi-blackhole/package.json:3); [current upstream package](https://github.com/k0valik/pi-blackhole/blob/main/package.json)
- The normal compaction path is `normalize → filterNoise → buildSections → formatSummary`, then merge with the prior summary and append recall instructions. It extracts goals, changed files, commits, outstanding context, preferences, and a short chronological brief using regex/structural rules; **no model call is required for this path**. This is a rolling summary with optional immutable append segments, not a recursively navigable binary abstraction tree. — [compiler](/hatimthayyil/code/pi-blackhole/src/core/summarize.ts:372); [pipeline docs](/hatimthayyil/code/pi-blackhole/docs/vcc-compaction.md:1)
- `tailBehavior:"minimal"` is the default: retain the last user turn and subsequent entries, subject to Pi's later safe split boundary for an oversized current turn. `tailBehavior:"pi-default"` instead uses Pi's recent-context cut, normally about 20k tokens. So raw recent assistant/tool activity can remain in model context. — [cut selection](/hatimthayyil/code/pi-blackhole/src/hooks/before-compact.ts:170); [defaults](/hatimthayyil/code/pi-blackhole/src/core/unified-config.ts:284); [tail docs](/hatimthayyil/code/pi-blackhole/docs/vcc-compaction.md:218)
- Historical retained tool text has a default 20k estimated-token budget, with omitted outputs replaced by `recall #N` references; unconsumed trailing outputs are protected. This is a context projection: original session JSONL remains intact. — [config documentation](/hatimthayyil/code/pi-blackhole/docs/CONFIG.md:240); [projection call](/hatimthayyil/code/pi-blackhole/src/hooks/before-compact.ts:685)
- Observer extracts cited observations, reflector synthesizes stable facts supported by observation IDs, and dropper removes selected observations from active memory. Their ledger entries and tombstones are appended to the Pi session branch; a dropped observation and its evidence remain retrievable. These are additional model agent loops, potentially multiple calls each, rather than free compaction. They persist across compactions within the session. — [worker/ledger contracts](/hatimthayyil/code/pi-blackhole/docs/observational-memory.md:5)
- Global config currently has `memory:true`, `sessionFallback:true`, **no worker/base model overrides**, `tailBehavior:"minimal"`, `compactAfterTokens:750000`. Therefore workers resolve to the selected main session model, using Pi registry auth (including OAuth/custom-provider auth where configured). Say **additional model calls/quota usage**, not necessarily API-dollar billing; actual billing depends on the provider/account. Settings installs `npm:pi-blackhole`, not this source checkout. — [global config](/home/hatim/.pi/agent/pi-blackhole/pi-blackhole-config.json:1); [settings](/home/hatim/.pi/agent/settings.json:1); [session model/auth resolution](/hatimthayyil/code/pi-blackhole/src/om/runtime.ts:493)

### Inferences
- `ai chat` has the more suitable foundation for the user's stated archive/recovery product: named threads, original recognized content in Git, and binary drill-down. Blackhole has stronger live Pi context-management policies. These are architecture judgments, not evidence of superior recall accuracy.
- A deterministic floor is useful for ai-chat lines whose LLM summary is not built: extract exact user request snippets, file/tool names, result status and IDs immediately, then optionally enrich asynchronously. This borrows the compiler's always-available structural path without replacing the binary tree.

### Gaps
- Installed npm package version was not resolved. The source clone's 0.5.9 is verified, and online main's 0.5.13 is verified separately.
- No measured quality, latency, token savings, or cost comparison was performed. Deterministic extraction can miss semantics and heavily truncates material; the maintainer labels the project experimental. — [upstream README](https://github.com/k0valik/pi-blackhole/blob/main/README.md)

## How does it bound context, recover source evidence, and handle failures?

### Takeaway
The best transferable details are bounded/paged retrieval, explicit preservation of raw evidence and recent context, context-window-aware triggers, and failure isolation. Its source also contains limitations that should not be copied.

### Cited Findings
- `recall` accepts free-text/regex search, `#N` expansion, `#N:path` file drill-down, `#N:text` message windows, offsets/limits, and 12-hex memory IDs that follow provenance to original entries. Search defaults to active lineage; `scope:all` covers alternate branches. Search pages default to five hits. This is source retrieval, not ai-chat tree zooming. — [recall docs](/hatimthayyil/code/pi-blackhole/docs/recall.md:1)
- The **tool** response has a hard character cap (default 48,000); line/entry shares, whole-entry truncation and continuation pointers keep source reachable. Local `/blackhole-recall` is deliberately outside this total cap and sends messages with `triggerTurn:true`; its comment says TUI-only but actual code delivers custom messages to the agent. Do not claim every local retrieval path is capped. — [budget](/hatimthayyil/code/pi-blackhole/src/core/recall-budget.ts:16); [drill-down docs](/hatimthayyil/code/pi-blackhole/docs/recall.md:35); [command](/hatimthayyil/code/pi-blackhole/src/commands/vcc-recall.ts:7)
- Auto-compaction's fixed token threshold wins over ratio, reserve, and preset. Ratio uses context window; reserve subtracts headroom. The global **750k fixed pin stays 750k on both 1M and smaller models**: it is not clamped to fit their windows. On 1M it is roughly 75%; on a 128k model this extension's proactive threshold is unreachable before overflow, leaving Pi's separate overflow mechanism to intervene. — [threshold function](/hatimthayyil/code/pi-blackhole/src/om/model-budget.ts:80); [trigger](/hatimthayyil/code/pi-blackhole/src/om/compaction-trigger.ts:397)
- Default run-end triggering can miss pressure during long tool loops; `midRunCompaction` defaults `off` and offers `resume`/`pause` behavior. Worker triggers default to 15k tokens for observer and 25k for reflection, with separate pool/input budgets. — [defaults](/hatimthayyil/code/pi-blackhole/src/core/unified-config.ts:284); [mid-run trigger](/hatimthayyil/code/pi-blackhole/src/om/compaction-trigger.ts:182)
- These are **not model-tokenizer hard limits**. String estimation counts CJK codepoints approximately as one token and other UTF-16 units at roughly 4/token; Pi usage helpers read provider-reported context usage where valid. Rendered observation/reflection selection enforces its estimated budget including separators, even if high-priority facts must be omitted. The recall tool character cap is hard; model token size is approximate. — [estimator](/hatimthayyil/code/pi-blackhole/src/om/tokens.ts:18); [pool selection](/hatimthayyil/code/pi-blackhole/src/om/ledger/render-summary.ts:40)
- Blackhole validates worker output shape and provenance: observations lose unknown source IDs and records with no valid citations are rejected; reflections reject unknown supporting observation IDs and multiline/empty text. These checks do **not** validate that the statements are true or complete. The deterministic compiler has section/brief caps (brief 120 lines), not an LLM summary quality judge. — [observer validation](/hatimthayyil/code/pi-blackhole/src/om/agents/observer/agent.ts:145); [reflection validation](/hatimthayyil/code/pi-blackhole/src/om/agents/reflector/agent.ts:98); [brief cap](/hatimthayyil/code/pi-blackhole/src/core/format.ts:34)
- Empty compiler output **and** empty OM projection causes the extension to decline ownership, letting Pi's native model summarizer run. This is protection against footer-only replacement, distinct from worker-model fallback. Ordinary deterministic compaction does not need LLM fallback or cooldown. — [native fallback](/hatimthayyil/code/pi-blackhole/src/hooks/before-compact.ts:727)
- Worker fallback order is stage model → ordered stage fallbacks → shared base model → session model if enabled. Configured model failures persist cooldowns (default one hour); exhausted consolidation has a 30-second retry gate. Worker wall-clock deadlines are optional and unset by default. — [resolver](/hatimthayyil/code/pi-blackhole/src/om/runtime.ts:405); [failure handling](/hatimthayyil/code/pi-blackhole/src/om/consolidation.ts:959); [cooldown](/hatimthayyil/code/pi-blackhole/src/om/cooldown.ts:171); [gate](/hatimthayyil/code/pi-blackhole/src/om/runtime.ts:714); [defaults](/hatimthayyil/code/pi-blackhole/src/core/unified-config.ts:328)

### Inferences
- Apply budgets across **every path that enters model context**, with stable continuation references; cap after rendering, and preserve the underlying records. Use pressure-aware view size and reserve enough recent raw content rather than treating a byte/line target as a reliable token budget.
- For ai-chat's model-written summaries, separate transient failure from successful output; retain deterministic fallback plus previous valid summary, validate size/shape and IDs, retry with bounded attempts, and cool down broken workers. These recommendations combine blackhole's separate protections; blackhole does not supply a general semantic correctness validator.

### Gaps
- No proof that either tool's selected summary conveys everything needed for successful continuation; source retention makes recovery possible, not automatic.

## What should ai chat borrow or avoid?

### Takeaway
Borrow operational safeguards, not the full observer/reflector/dropper subsystem. Improve the existing archive and tree with immediate structural coverage, bounded retrieval, fresh-context retention, and honest failure reporting before adding another memory store.

### Cited Findings
- The local observer chooses a newest-first suffix under its 40k input cap, keeps even one oversized entry, and advances to the last included entry. Thus older unobserved material can be skipped. It only throws a stream error when **zero** observations were accumulated, allowing partial output to count as coverage. These are source-visible limitations in the checked-out version, not recommended patterns. — [capping](/hatimthayyil/code/pi-blackhole/src/om/consolidation.ts:104); [coverage marker](/hatimthayyil/code/pi-blackhole/src/om/consolidation.ts:717); [partial-error behavior](/hatimthayyil/code/pi-blackhole/src/om/agents/observer/agent.ts:341)
- Online 0.5.13 documents oldest-first bounded backlog draining and cited-prefix checkpointing after capped runs. This illustrates a stronger coverage invariant than local 0.5.9: never claim coverage beyond examined source; store partial work separately when needed. It was verified online, not in the requested checkout. — [upstream README](https://github.com/k0valik/pi-blackhole/blob/main/README.md)

### Inferences
1. **First:** replace unbuilt summary placeholders with bounded structural source-derived lines; make a summary failure visible and avoid resetting context to empty/placeholder-only content. Keep raw original transcript the authority.
2. **Next:** add total output budgets and paging to view/zoom/grep; include omitted-count and exact continuation hints. Support retaining a recent raw suffix independently of the summary view.
3. **Next:** expose context pressure, summarization backlog and worker failure state. Derive live context budgets from the active model window and reserve, keeping archives independent of context pruning.
4. **Then:** add bounded worker retry/fallback/cooldown only where summary construction needs model calls. Require provenance and output contracts, while recognizing they do not prove truth.
5. **Avoid:** automatically introducing three additional model loops or a second authoritative observation ledger alongside `ai memory`; copying a 750k fixed trigger to smaller models; newest-first coverage cursors that silently skip source; unbounded command paths; treating lossy recap as primary storage.

### Gaps
- Detailed ai-chat implementation findings are in the [ai-chat source notes](ai-chat-source-notes.md). These recommendations use its verified binary summary archive and current missing-summary/failure/retrieval behavior.
