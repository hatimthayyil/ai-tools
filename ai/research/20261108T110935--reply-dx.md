# /reply: developer experience

`/reply` quotes the assistant's answers into the prompt box (`ai reply`, `src/agent/reply.rs`; plugin `plugins/claude/hooks/register.ts:136-143,279-282`). This note covers what got in the user's way and what would make it obvious. Claude Code 2.1.319. API citations are to its plugin types (`claude-code.d.ts`, which the plugin-authoring skill writes; a loaded mod's copy is `.claude-plugin/types/claude-code/index.d.ts`) and to its docs (`~/.claude-code-docs/docs`).

## What the user hit

In an emx session on 2026-11-06 (Claude Code 2.1.318, first-layer build), the user wanted two bullets from the latest answer's last reply, under "Still waiting on you". They tried five references, all refused, then quoted the bullets by hand and answered "Yes".

To reproduce, run the feat/reply build (`ffe9e56b`, installed) on a copy of that transcript, cut before the first attempt:

| Typed | First layer said | feat/reply does | Cause |
|---|---|---|---|
| `-1 -2` | Not a reply reference: -1 -2 | quotes both whole answers: 71 lines, 6,346 chars | `-N` names whole answers; nothing names part of a reply |
| `1 2` | Not a reply reference: 1 2 | Turn 1 is the report "Audit emx Elisp configuration", not your message, and it has no reply. | bare numbers are turn ids, counted from the session's first turn |
| `1,2` | Not a reply reference: 1,2 | the same | the plugin splits on whitespace only (`register.ts:280`) |
| `"1,2"` | Not a reply reference: "1,2" | the same | plugin arguments are not shell-parsed, so the quotes are literal |
| `2` | 2 reads as a thread id… | Turn 2 is the report "Assess Elisp package management"… | as `1 2` |

The first layer passed the whole argument string as one reference, so every multi-word attempt failed there.

By "row" the user meant a list item of the reply: here the first two bullets of its last list. No reference names part of a reply. The nearest is `#2`, the whole second reply: 18 lines, of which the user wanted 2.

## Constraints

- A slash command is recognised only at the start of the message, and the rest is its arguments (`commands.md:13`). So a second `/reply` can't be typed below a draft. Ctrl+S stashes the draft, but restores it only on an empty box (`interactive-mode.md:31`). Several pieces must therefore come from one run, or from something that works mid-draft.
- The model also reads a command's `{ text }` output (plugin reference, `CommandOutput`). A listing printed that way costs context, so show numbers in a pane, a toast or the typeahead.
- The user runs `"tui": "fullscreen"` and `"editorMode": "vim"` (`~/.claude/settings.json`).

## Enhancements, by value against cost

1. **Quote the mouse selection.** Bare `/reply` quotes what the user last selected, and the latest answer when nothing is selected. Given references win over a selection.
   - API: `$.ui.selection()` (`claude-code.d.ts:2635-2648`) returns `{ text, requestId? }` (`:15927`). The plugin reference's own example for it is a `/quote` command that fills `> ` lines with `$.prompt.fill` insert.
   - Prior art: GitHub "Quote reply" (the selection, else the whole comment; key `r`), Zed "add selection to thread", Cursor "Add to Chat".
   - It solves the user's case with one drag. Cost: about 15 TypeScript lines and a plugin test.
   - Limits: fullscreen only (otherwise `undefined`); one piece per run; the selection lasts only until the next prompt or command has run.
   - `text` is "as a copy would take it", which may drop Markdown such as backticks. `requestId` names the message, so a later layer can recover the source.
2. **Forgiving references, and errors that say what to type.**
   - Accept commas between references, and one pair of surrounding quotes, so `1,2`, `"1,2"` and `'#2'` (copied from the CLI help) work.
   - When a bare `N` fails (a report turn, or a turn with no reply), add: "To quote part of an answer, select it and run /reply."
   - Cost: about 20 Rust lines in the reference parsing (`reply.rs:59`, `cli.rs` `reply`) plus tests. The CLI shares it.
3. **Pieces and a picker.**
   - `ai reply --pieces [REF] --json` splits each reply into blocks: paragraph, list item, heading, code block, table row. pulldown-cmark's `into_offset_iter` keeps the source exact. There is no Markdown dependency yet.
   - Typed form: `:p` after any reference: `:2`, `:2-3`, `-2:4`, `597#2:3`.
   - Picker: a dialog pane listing the pieces of the latest answer, opened with `$.ui.open({ id, title, focus, closeOnEscape, holdToasts, rows })` (plugin reference, panes). Each piece is a Button with `hotkey` 1-9, a-z (`claude-code.d.ts:1085-1123`) that toggles it; Enter quotes the chosen pieces in order.
   - Several pieces in one run follow mail's convention: quote everything first, then answer between the quotes.
   - Cost: medium to high. About 120 Rust lines for the splitter and JSON, about 100 TSX lines, and tests.
4. **Typeahead for references and pieces.**
   - API: `prompt.autocomplete` (`claude-code.d.ts:4363-4374`, `:8644-8700`). While the user types `/reply :`, `#` or `-`, rows such as `:3  - Should I make the gpg warning fix?…` and `#2  All 12 commits…` show what each number quotes.
   - The plugin caches the latest answer's pieces in `$.state` at turn end; `classic.Stop` already runs there (`register.ts:262`).
   - Mid-draft: when the user takes a row for a token such as `>:3`, the row writes the quoted piece over the token. It is the only way found to add a quote to an existing draft.
   - Cost: medium; it shares item 3's Rust.
5. **Row labels (change 4).**
   - A `ui.render` hook on `AssistantMessage` with `isFirstOfReply` (`claude-code.d.ts:10610-10650`) draws a dim `612#2` before each final reply.
   - A hook on `UserMessage` with `origin.kind` `task-notification` (`:10541-10600`, with `task` and `from`) draws `614 · fork "Build ai agent rename"`.
   - The plugin keeps a map from message id to reference, from `ai reply --labels --json` at turn end, in an atom that renders read.
   - The labels show the numbers to type where the user reads, and mark reports by fork name. Today the live transcript shows no turn numbers, so `N` is guesswork outside `ai view`.
   - Cost: medium.
6. **Quote a fork's own report.** `/reply 614` on a report turn quotes the report (`Kind::Work.text`, `src/agent/model.rs:22-25`) under `Fork "Build ai agent rename" reported:`. Today it errors and points at the assistant's reply (`reply.rs:221` `not_yours`). Cost: about 25 Rust lines plus tests.
7. **Attribution.** Mail attributes every quote ("On … X wrote:"); GitHub's quote reply attributes none. Attribute only text that isn't the assistant's (fork reports), so the model doesn't read a fork's words as its own. The cost is tiny, built with item 6.
8. **A key binding: rejected.**
   - A plugin can't declare a keybinding action. A Button's `action` must be an existing engine action, and only fires while no engine handler of it is mounted (`claude-code.d.ts:1124-1131`). `keybindings.md` lists no plugin actions.
   - Borrowing an unbound action such as `app:toggleDiffNoiseFilter` (`keybindings.md:315`) needs a band drawn above the prompt all the time, and breaks when the diff panel opens.
   - `/re` then Tab is three keys.
9. **`$.ui.ask` as a picker: rejected.** It takes only 2-4 options (`claude-code.d.ts:692-705`), too few for pieces.

## Recommended first layer

Items 1 and 2 together:

- `/reply` quotes the selection, else the latest answer.
- `/reply 597 -1`, `/reply 597,-1` and `/reply '#2'` all work.
- A failed bare `N` tells the user how to quote part of an answer.

That covers the user's case, a drag then `/reply`, for about 35 lines and their tests. Layer 2 adds pieces (items 3 and 4 share the splitter). Layer 3 adds labels, report quoting and attribution (items 5-7).

## Check live before building

None of these were probed: each needs a person at a fullscreen terminal.

- Whether herdr forwards mouse drags to fullscreen Claude Code.
- What `$.ui.selection().text` holds for a bullet with inline code: rendered (bullet glyph, no backticks) or source Markdown.
- Whether the engine raises `prompt.autocomplete` inside a slash command's arguments. The binary computes the token for any text, with no sign of skipping commands. Also whether a row's multi-line `text` arrives whole. It passes the same sanitizer as `prompt.fill`, which keeps newlines.
- Whether `requestId` on a message row equals the transcript entry's `uuid` or its `message.id`.

## Open questions

1. Bare numbers: keep them as turn ids, as in `ai view` and `ai agent zoom`, with pieces as `:p`? Or make them pieces of the latest answer, as the user first expected, and put turns behind a prefix?
2. With no selection and no references, should `/reply` keep quoting the whole latest answer, or open the picker?
3. Should pieces count across the whole answer (`:16`), or within each reply (`#2:3`)?
4. Change 4: should `/reply <report turn>` quote the fork's report?
