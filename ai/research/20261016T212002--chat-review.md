# Stabilise chat invariants before adding harnesses

`ai chat` has a useful foundation: a conversation graph, separate summary planning and execution, and branch views with exact zooming. I would preserve those boundaries. **Pause Codex/Pi integration until session transactions, source freshness and summary identity have clear invariants.** The review reproduced cursor rollback, competing active attachments, failed moves that leave a session unattached, and queries whose results depend on command order or ambient session state. These problems affect which conversation an agent receives during compaction. The largest maintainability gains will come from explicit identities, one transaction authority and predictable read operations. A storage change could simplify the implementation, but either Git or SQLite can support the product once those contracts are clear.

Reviewed revision: `47a7aa9ef7827909e0ab91fa135993338c7ef575`, version `0.9.0`. Author: Codex / GPT-6. This is an independent review; no implementation changes or commits accompany it. Confirmed defects below come from isolated probes against the implementation. Other findings identify source-confirmed behavior, design tradeoffs or version-dependent integration gaps. Codex/Pi support is planned scope, rather than a defect counted against the current implementation.

## Session state and summary identity need stronger guarantees

**High priority, reproduced: an older sync can roll back the session cursor.** `sync` reads the transcript before entering the Git mutation/retry closure. Ingestion then assigns the binding's tip from that read's last item without checking source freshness. In a same-file, append-only probe, a newer sync stored four items and set `tip=3`; an older paused sync resumed and left all four items stored but reset `tip=0`. Current-session branch selection follows that tip, so zoom, search and compaction can omit the newer context until another fresh sync repairs it. All stored items remain intact; the visible session tip regresses. Preserve an observed source generation/checkpoint and reject stale observations, or serialize each session's read-and-sync operation. A numeric `max(tip)` would conceal the missing source contract and complicate genuine rewinds or source replacement. ([Read before mutation](/hatimthayyil/code/ai-tools/src/chat/sync.rs:85), [tip assignment](/hatimthayyil/code/ai-tools/src/chat/store.rs:583), [probe and output](<20261016T212002--chat-review/core-probes.rs>), [captured result](<20261016T212002--chat-review/core-probe-output.txt>))

**High priority, reproduced: attach/move/detach lack a repository-wide transaction.** Attachment lookup scans threads; each target thread then commits its own attached flag. Twelve barrier-synchronised attaches of one session to distinct threads all succeeded, leaving twelve active claims. One detach removed the selected claim and exposed another as active. Two concurrent calls suffice for the underlying race. A separate failure probe locked the destination ref before moving a session: the command detached the old binding, failed to publish the target, and left the session attached nowhere. An ingestion-validation failure produced the same outcome. ([Lookup and transfer](/hatimthayyil/code/ai-tools/src/chat/sync.rs:64), [detach before target mutation](/hatimthayyil/code/ai-tools/src/chat/sync.rs:134), [probe output](<20261016T212002--chat-review/core-probe-output.txt>))

Give `(harness, session)` one authoritative binding and publish transfer changes together. Validate and prepare ingestion before publication; preparation alone cannot make separate commits crash-safe. With SQLite, a unique binding constraint and one transaction express this contract. With Git, one authoritative repository-state ref containing the session registry and thread manifests gives readers a consistent state and writers one compare-and-swap boundary. Existing per-thread CAS protects appends within a thread; choosing the latest timestamp across competing claims does not enforce uniqueness. Git and the installed `gix` dependency support multi-reference edits, but Git warns that concurrent readers can observe a subset of ref updates. Retaining per-thread refs therefore still requires a consistent authority for membership and reads. ([Current CAS](/hatimthayyil/code/ai-tools/src/git.rs:143), [Git reference transactions](https://git-scm.com/docs/git-update-ref), [gix API](https://docs.rs/gix/0.88.0/gix/struct.Repository.html#method.edit_references))

**High priority before arbitrary harness forks, reproduced: summary keys can identify different source spans.** Chunk keys contain only `(level, last item)`. Two branches can end a chunk at the same shared item while starting it at different items, because later continuation changes whether an assistant step fits the chunk budget. The exact-library probe produced spans `[1..10]` and `[2..10]` under the same key `0@9`; `Rollup::add` retained the first source. The view can then duplicate preceding material or omit it, and turn summaries inherit the error. Existing rationale acknowledges this restriction and says observed Claude forks occur at user messages. **This proves a defect in the supported generic graph, not that ordinary Claude user-message forks fail.** Use exact source-span/input identity for chunks, then derive parent identities from their children. ([Key construction](/hatimthayyil/code/ai-tools/src/chat/rollup.rs:163), [first source retained](/hatimthayyil/code/ai-tools/src/chat/rollup.rs:287), [reproducer](<20261016T212002--chat-review/chunk-identity.rs>), [documented restriction](/hatimthayyil/code/ai-tools/ai/comments/src/chat/rollup.rs.md))

Related cache invalidation needs an explicit recipe. A stored summary records model provenance and text, but no exact input hash, projection version or summary recipe version. Existing keys count as valid after changes to parsing, clipping, rendering or prompts. Adding a chunk start fixes the demonstrated collision but leaves stale recipes and children unchecked. Reuse the existing notes feature's pattern of hashing input and validating it before publication; chat needs its own span/dependency rules. Keep model selection policy separate: changing the preferred model need not invalidate otherwise valid summaries unless the user requests it. ([Stored line](/hatimthayyil/code/ai-tools/src/chat/record.rs:97), [cache acceptance](/hatimthayyil/code/ai-tools/src/chat/summarise.rs:425), [notes input validation](/hatimthayyil/code/ai-tools/src/notes/cli.rs:506))

These races demonstrate permitted interleavings, not measured production frequency. Existing concurrent-sync tests check item deduplication and parent links, which explains why they passed while binding tips and cross-thread membership remained untested. ([Existing concurrency test](/hatimthayyil/code/ai-tools/tests/chat.rs:571))

## Read commands need predictable freshness, branches and effects

**Reproduced: command order changes query results.** `view` syncs the current attached session; `zoom`, `grep`, `list` and `summarise` read persisted state. After adding a third turn to an attached transcript, `grep` returned `No match.` and `zoom 2.0` failed. Running `view` made both queries succeed. Claude's Stop hook delays sync by 1,100 ms, so this affects inspection before Stop and during that delay. Resolve the target, acquire fresh state where the command promises it, freeze a snapshot, then perform the query. Share this acquisition step across commands. Explicit historical queries should preserve their requested snapshot. ([View](/hatimthayyil/code/ai-tools/src/chat/cli.rs:568), [zoom/search](/hatimthayyil/code/ai-tools/src/chat/cli.rs:611), [probe output](<20261016T212002--chat-review/cli-probes-output.txt>))

**Reproduced: commit-pinned pagination can switch branches.** The `view` continuation includes thread and Git commit but omits session/branch. Running the same emitted continuation inside the original session and outside a session returned different content from the same commit; one result included a later session's turn. Zoom/search continuations lack commit pinning as well. A continuation must bind thread, snapshot, branch tip and relevant query options. An opaque cursor or explicit arguments can carry those values. The same branch identity should support ordinary historical queries: current `--session` selection discards detached bindings, and list reports branch count without usable branch selectors. Retain short coordinates such as `12.3` for display, with a stable branch/tip identity for citations and navigation. ([Target/branch selection](/hatimthayyil/code/ai-tools/src/chat/cli.rs:291), [view continuation](/hatimthayyil/code/ai-tools/src/chat/cli.rs:589), [zoom/search continuation](/hatimthayyil/code/ai-tools/src/chat/cli.rs:624), [captured branch difference](<20261016T212002--chat-review/cli-probes-output.txt>))

**Source-confirmed and exercised with a fake model: `view` invokes models and writes summaries.** Missing summaries cause it to launch Claude and commit results. `ai.chat.summarise=false` disables background work only; the probe still observed a `claude -p --model sonnet …` invocation from `view`. A failed model result produced exit 0, no stderr and an unsummarised fallback because `fresh_view` discards the build's failure report. That fallback preserves availability, but the caller cannot distinguish a completed summary view from degraded output. ([On-read build](/hatimthayyil/code/ai-tools/src/chat/cli.rs:342), [background-only setting](/hatimthayyil/code/ai-tools/src/chat/summarise.rs:63), [fake-model evidence](<20261016T212002--chat-review/cli-probes-output.txt>))

I recommend a pure `view` over stored summaries and existing fallback rendering, an explicit `summarise` operation, and compaction-specific orchestration that syncs, builds, waits and chooses a fallback policy. If on-read generation remains a product preference, disclose the effects and offer a mode that forbids model calls. Report completeness and build failures so the compaction hook can decide whether native compaction should run. `summarise --dry-run` also invokes the model by intent: it generates previews without storing them. Describe that spend behavior in help and distinguish a cheap work plan from a generated preview. The current wording is confusing, rather than an unequivocal violation of its documented preview contract. ([Dry-run help](/hatimthayyil/code/ai-tools/src/chat/cli.rs:136), [execution](/hatimthayyil/code/ai-tools/src/chat/summarise.rs:280), [hook success policy](/hatimthayyil/code/ai-tools/plugins/claude/hooks/register.ts:28))

Lifecycle boundaries need two smaller decisions. Detach does no final ingest: complete transcript records since the last sync remain outside the thread, and later `sync-session` returns unattached. They remain recoverable by reattaching; the consequence depends on whether detach promises to preserve conversation up to invocation. Define that boundary and late-write policy, then flush the available prefix if that is the contract. Resume ranks bindings by `(tip, attached)`, so an older populated session beats a newer empty session, contrary to the README's unqualified “newest session.” Choose the intended meaning of newest and record it. Launch also mutates bindings before `exec`; check executable availability first and make any remaining pending state visible. ([Detach](/hatimthayyil/code/ai-tools/src/chat/sync.rs:175), [resume](/hatimthayyil/code/ai-tools/src/chat/cli.rs:416), [launch](/hatimthayyil/code/ai-tools/src/chat/cli.rs:383), [lifecycle probes](<20261016T212002--chat-review/cli-probes-output.txt>))

**Cargo installation has a confirmed packaging gap.** Cargo's package excludes `plugins`; the documented `share/ai/plugins/claude` asset comes from Nix's post-install step. Cargo users cannot follow that path without obtaining assets elsewhere. Ship a versioned plugin package or an explicit asset export/install path; adding files to Cargo's source archive alone would not install them under `share/`. Document the supported Claude runtime version. Official terminal-mod support exists in stock Claude from v2.1.287; local v2.1.302 ran the plugin tests. ([Cargo manifest](/hatimthayyil/code/ai-tools/Cargo.toml:8), [installation instructions](/hatimthayyil/code/ai-tools/README.md:60), [Nix installation](/hatimthayyil/code/ai-tools/flake.nix:35), [official runtime support](https://code.claude.com/docs/en/plugins/mods/overview#turn-mods-on-or-off))

Custom compaction also needs a supported-version integration check. Project notes record nested instruction loss on Claude 2.1.300 because replacing `session.compact` skipped built-in instruction restoration. Current upstream instruction handling has changed; **this review did not reproduce that defect on 2.1.302**. Test reading nested instructions, custom compaction and reading the same directory again before relying on the hook. The 1,100 ms transcript delay and session-end timing likewise need an adapter-specific flush contract; a timer is an observation about the current writer, not a synchronisation guarantee. ([Replacement hook](/hatimthayyil/code/ai-tools/plugins/claude/hooks/register.ts:77), [recorded version-specific issue](/hatimthayyil/code/ai-tools/ai/comments/plugins/claude/hooks/register.ts.md:14), [current upstream handler](https://github.com/anthropics/claude-code/blob/main/mods/agents-md/hooks/register.ts), [official hook limits](https://code.claude.com/docs/en/plugins/mods/reference#limits))

## Preserve raw evidence and keep the useful module boundaries

The graph and planner are worth retaining. `Tree` enforces earlier parents and derives turns/steps; Claude decoding handles dropped entries, parallel tool results, rewinds and compaction; `render` formats items; `rollup` plans without I/O; `summarise` executes through an injected backend; `view` selects detail. The fixture coverage around Claude's awkward ordering is useful. A rewrite that merges these concerns would reduce readability. ([Graph](/hatimthayyil/code/ai-tools/src/chat/model.rs:84), [parser tests](/hatimthayyil/code/ai-tools/src/chat/claude.rs:476), [planner](/hatimthayyil/code/ai-tools/src/chat/rollup.rs), [executor](/hatimthayyil/code/ai-tools/src/chat/summarise.rs))

**The current store preserves selected parsed records.** Recognised items retain source lines; thinking-only entries, injected context and unknown event kinds that emit no items leave no raw record. Complete malformed JSON, missing UUIDs and invalid timestamps also disappear without diagnostics. Re-ingestion ignores existing item identities, so a parser correction cannot update their content or parents; store-format versioning does not identify projection semantics. Archive complete source events before filtering if future reprojection matters, and return parsing diagnostics that distinguish intentional exclusions, malformed records and unresolved ancestry. Otherwise document the narrower preservation contract and provide a rebuild path for the evidence that remains. ([Filtering/raw assignment](/hatimthayyil/code/ai-tools/src/chat/claude.rs:172), [immutable ingestion](/hatimthayyil/code/ai-tools/src/chat/store.rs:577), [fixture with excluded/unknown entries](/hatimthayyil/code/ai-tools/tests/fixtures/claude/plain.jsonl))

Separate canonical event identity from observation provenance. Public `SourceId` contains harness, session and entry, while store deduplication excludes session to recognise UUIDs copied by Claude forks. That policy serves existing Claude tests; no real UUID collision was demonstrated. Another harness should not inherit it as an implicit promise. Its adapter should define canonical identity/fork aliases while the core retains which session/file observed an event. Replace `store::Transcript`'s `Vec<claude::Subagent>` with provider-neutral `Transcript`/`AgentRun` types. Keep source discovery, decoding and launch syntax in a small harness module; put attach/sync/detach invariants in an application service below clap. A closed harness enum and direct dispatch suffice for the known integrations. ([Identity types](/hatimthayyil/code/ai-tools/src/chat/model.rs:6), [dedupe key](/hatimthayyil/code/ai-tools/src/chat/store.rs:96), [provider coupling](/hatimthayyil/code/ai-tools/src/chat/store.rs:116), [fork test](/hatimthayyil/code/ai-tools/tests/chat.rs:267))

Extract shared LLM/process/text helpers from `memory` into modules named for their responsibilities. Chat and notes import backends, line writing, pattern matching, shell quoting and pagination through permanent memory today. Keep transcript ingestion independent of summary-model selection: importing Codex logs should not require using Codex to summarise them. There is repeated worker bookkeeping in memory/chat, but their retry and lifetime policies differ; extract only a small proven common helper. The three fold/cover implementations also apply different policies. Conversely, `rollup::branch` and `Rollup::branch` already share their cutter, so their similar names do not justify another abstraction. ([Chat imports](/hatimthayyil/code/ai-tools/src/chat/summarise.rs:18), [CLI imports](/hatimthayyil/code/ai-tools/src/chat/cli.rs:26), [memory worker](/hatimthayyil/code/ai-tools/src/memory/compact.rs:181), [shared cutter](/hatimthayyil/code/ai-tools/src/chat/rollup.rs:225))

Read growth deserves a separate data-access boundary. No-op sync reparses whole sources and reconstructs dedupe indexes. `list` loads complete normalised and raw histories just to count turns; branch views also load raw content they do not display. An actual-library synthetic probe with a 65.7 MB source measured warm `heads()` at about 5 ms, `tree()` at 76–84 ms and one-thread `list()` at 80–94 ms. This compressible fixture is an eager-read demonstration, not a representative database benchmark. Keep a cheap topology/kind index, load selected content on demand, and load raw evidence only for inspection/reprojection. Source checkpoints must retain parser state and incomplete-tail handling, rather than using a byte offset alone. ([Eager reads](/hatimthayyil/code/ai-tools/src/chat/store.rs:409), [list](/hatimthayyil/code/ai-tools/src/chat/store.rs:185), [probe](<20261016T212002--chat-review/read-growth.rs>))

The fold planner repeatedly scans and splices a shrinking vector, giving quadratic work in closed turns despite a fixed output target. A copied, unchanged function compiled with optimisation took 2.81 ms at 1,000 turns, 332 ms at 10,000 and 1.31 s at 20,000. Preserve its selection policy with an efficient priority structure if that policy matters; the existing faster memory cover has different semantics. Context budgets also need an explicit contract: the line writer can return over 512 bytes after five attempts, and long-turn reduction concatenates all chunk summaries without a recursive input bound. Budget actual rendered bytes/tokens or enforce limits with an explicit fallback. Give summary runs a work plan and budget; successful line counts omit failed attempts and length retries. No model-fidelity or billing benchmark supports the current summary policy yet. ([Fold](/hatimthayyil/code/ai-tools/src/chat/view.rs:61), [timing probe](<20261016T212002--chat-review/fold-growth.rs>), [line retries](/hatimthayyil/code/ai-tools/src/memory/compact.rs:89), [chunk reduction](/hatimthayyil/code/ai-tools/src/chat/rollup.rs:356))

## Choose storage for history and transactions, then simplify records

You are undecided about retaining Git history; **no backend choice is assumed here**. Git already provides content-addressed blobs, immutable snapshots and commit-pinned reads. Worktrees share ordinary refs and the common directory. Those are useful features, and the reproduced defects do not require abandoning Git. Reachable parent commits also retain superseded derived summaries. Custom chat refs need explicit refspecs, mirrors or exports for transport; ordinary code clone/fetch/push does not imply chat backup. ([Current Git publication](/hatimthayyil/code/ai-tools/src/git.rs:174), [worktree refs](https://git-scm.com/docs/git-worktree#_refs), [reachable history](https://git-scm.com/docs/git-gc#_notes), [fetch mapping](https://git-scm.com/docs/git-fetch#_configured_remote_tracking_branches))

SQLite fits local embedded application state, with constraints, indexed queries and transactions. A database in the common Git directory can serve local worktrees without a server. WAL permits readers alongside one writer, with same-host and checkpoint/backup considerations. It would replace custom fanout/index parsing, reference retry plumbing, cross-thread scans and timestamp arbitration with a schema and short transactions. It would still need correct event identities, projection versions and summary invalidation. ([Appropriate uses](https://www.sqlite.org/whentouse.html), [transactions](https://www.sqlite.org/lang_transaction.html), [WAL](https://www.sqlite.org/wal.html))

| Choice | Main benefit | Cost or missing product behavior |
|---|---|---|
| Git authority, typed records and topology indexes | Existing persistent OID snapshots, object deduplication and inspectable history | Application must define consistent repository transactions, lookup indexes, maintenance and explicit export |
| SQLite authority in the common directory | Clear binding constraints, atomic moves and indexed/range reads | Historical `--at` across CLI invocations needs versioned rows or persisted view snapshots; backup/export needs a contract |
| Append-only JSONL plus indexes | Readable event stream and straightforward raw capture | Writer locking, crash tails, transaction grouping and index consistency require application database work |
| Git archive plus rebuildable SQLite projection | Immutable source history with indexed derived queries | Two systems and rebuild logic; justify with demonstrated need, keep one authority |

**My conditional recommendation:** choose SQLite if local operation, readable application code and transactional state are the main priorities, and historical Git-addressable snapshots are incidental. Keep Git if persistent OID snapshots/history/transport are product features you want to maintain; give it one authoritative transaction state and cheap graph reads. Conversation forks and raw retention work in either system. A hybrid adds more moving parts than current evidence justifies. This review contains no Git-versus-SQLite throughput or space comparison. SQLite FTS5 also does not preserve arbitrary regex search semantics by itself, and live WAL backup requires a consistent backup procedure. ([FTS5](https://www.sqlite.org/fts5.html), [backup API](https://www.sqlite.org/backup.html))

Simplify the record codec independently of that choice. Current headers flatten newlines, positional index fields rewrite whitespace, and decoders default several missing semantic fields to empty strings. These rules add custom parsing work and obscure validation. With Git, use serde-tagged JSON for typed items, bindings and summaries, keeping topology indexes separate where needed. With SQLite, use typed indexed columns for identity/parent/binding fields and JSON for variable item payloads. Preserve raw bytes untouched. JSON's verbosity is a tradeoff, not a measured storage advantage; its value here is named fields, established tooling and explicit required values. ([Shared codec](/hatimthayyil/code/ai-tools/src/record.rs:3), [index rewriting](/hatimthayyil/code/ai-tools/src/chat/record.rs:107), [kind decoding](/hatimthayyil/code/ai-tools/src/chat/record.rs:220))

## Fix the contracts before expanding the integration surface

First, turn the reproduced cases into regression tests and fix source observation ordering, unique session ownership and failure-atomic moves. Then make summary keys/versioning correct across branches and parser changes. These are useful invariants under either storage choice, so storage deliberation need not block that design work. Decide the history/backup contract before substantial persistence implementation; an early refactor can replace obsolete paths without building a selectable-backend framework or compatibility layer.

Next, unify query acquisition and branch identity, make continuations reproducible, and separate viewing from model execution or disclose the chosen effects. Define detach's boundary and summary failure/budget behavior. Add a small status surface for resolved harness/session/thread/tip, source path/checkpoint and summariser failures; structured query output should carry snapshot/branch identity and completeness alongside text. Resolve plugin distribution and revalidate nested instruction restoration on the supported Claude runtime. Only then add the provider-neutral transcript/lifecycle boundary and implement Codex/Pi against those contracts.
