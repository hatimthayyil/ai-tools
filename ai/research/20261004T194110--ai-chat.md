# ai chat

Spec note. Date: 2026-10-04. Follows the OptChat spec (`/hatimthayyil/code/optchat/optchat.md`, "§N" below) except where stated. Background: `20261004T172045--shitty-optchat.md`, `20261004T171431--optchat-cache-claude-code.md`. Supersedes the nap/cover/sync parts of `20261003T091838--memory-git-ref.md` and `20261004T152738--memory-user-level.md`.

## Decisions (user, 2026-10-04)

1. One store: the chat log is `ai memory` (`refs/ai/memory` in the bare repo `~/.ai/memory`, `AI_MEMORY_DIR`). Messages have a kind: user, talk, tool, echo, note. `ai memory note` appends a `note`, from any session.
2. Pure binary tree (§3): a level-0 node per message, merges of two children, free nodes, `NODE` = 512 bytes. The view is the incremental fold (§5): append, merge the most due built pair, never split, refold at load; `VIEW` = 128,000 bytes. `id+n` addressing and zoom per §3/§7.1. Raw-16 blocks and the alpha-bisection cover are gone.
3. Variable-size messages: one blob each (below). One commit per mutation.
4. Single machine. Sync, merge, fingerprints, renumbering and the remote are gone; ids are permanent positions. Provenance stays, origins included (user, 2026-10-05): nothing the old memory recorded is dropped unless keeping it breaks the design. Multi-writer safety stays: CAS on the ref. Multi-machine sync is a backlog item.
5. Compaction: never by agents. The compactor (§4.1 pump, JOBS 8, RETRY 10 s forever, first failure reported once; §4.2–4.3 context block, SCALE, size retries in one conversation, TRIES 5, shortest kept; COMPACT verbatim with agent name "MyAI") runs inside `ai chat` and as `ai memory nap`. One compactor per memory: advisory lock `compact.lock` in the memory dir; a second one exits at once. `ai memory note` spawns a detached `ai memory nap` when a node is due (output to `nap.log`; `AI_MEMORY_NAP=0` disables); `note` prints no prompts.
6. Model access through a pluggable `Backend` (open a conversation with a system prompt; say a message, get text, same context for retries). Only implementation: Claude Code, `claude -p --model sonnet --effort medium`, stream-json in/out, `--verbose --include-partial-messages --no-session-persistence --setting-sources "" --strict-mcp-config --system-prompt-file F --tools "" --safe-mode`, env `CLAUDE_CODE_PROMPT_CACHE_TTL=5m`, `DISABLE_PROMPT_CACHING=1`. Other APIs later.
7. `ai memory` keeps `init`, `wake` (print the view), `note`, `nap`, `zoom`, `show`, `grep`, `config`, `import` (OptMem bootstrap → `note`). `forget` and `sync` are gone.

## Storage layout

Under `refs/ai/memory`, one commit per mutation:

```
log/<i>>8 as %04x>/<i&255 as %02x>        message i: "ts kind origin repo head branch agent model session\n" + text
tree/<l>/<s>>8 as %04x>/<s&255 as %02x>   nodes 256s..256s+255 of level l, one line each:
                                           "ts origin agent model session text" (text flattened, last), empty = not built
```

- `ts` UTC `YYYYMMDDThhmmssZ`. Header fields: whitespace → `_`, empty → `-`. `origin`: the writing store's id (`ai.memory.origin` in its git config, 6 random Crockford base-32 characters, made at `init`); a message appended with an origin keeps it. A node's agent, model and session are the compactor call's (`claude-code`, `sonnet`, the `claude -p` session id); free nodes have `-` for all three.
- Every commit also writes the free nodes it completes (a short message's leaf, a parent whose children fit 512 bytes together), so free nodes never wait for a compactor.
- The view is not stored: `Mem::load` reads every level and refolds.
- Next to the repo: `compact.lock` (compactor lock), `nap.log` (background naps' output).

## Deviations from the spec

- Node text stored flattened; a free merge is `a + " " + b` (spec: `"\n"`), same size, identical everywhere it is shown.
- No process lock for the log (§2 "one writer"): many sessions append notes; CAS serializes commits, and ids are assigned inside the CAS. Only the compactor is exclusive.
- Durability: git objects + ref update, no explicit fsync (§2 asks one per line). Open.
- Dates are UTC; `date(id)` (stage 2) renders local time.
- `wake` prints the view for sessions outside the chat, paged for harness output caps, later parts pinned to the first part's commit.

## Stages

1. Done: store, tree, view fold, zoom, compactor library with the `claude -p` backend, `ai memory nap`, note-triggered background nap. Tested with fake backends (and a fake `claude` script end to end).
2. Done: `ai chat`: fresh `claude -p` per turn, stopped by its stdout reader at the first `result`; mid-run input via a FIFO writer thread, consumed messages logged on replay; unconsumed messages requeued only after a result. Priming before a turn unless that view was primed under 270 s ago, and in the background once per view change after one idle second (never at startup); failure reported once. `ai chat mcp` serves zoom/date. The compactor runs in the chat process, holding `compact.lock`; no turn starts until its view is entirely built.

## Stage 2 as built

- CLI: `ai chat [--model MODEL] [--effort low|medium|high|xhigh|max]`; defaults Opus/high. Read-only stdio server: `ai chat mcp`. Memory must already be initialized.
- Input and output (2026-10-06): the session emits semantic UI events (`ui::Show`: text deltas, tool calls/results with error flag, thoughts, usage, model, priming start/success/failure, compactor reports and running calls, summary wait, pending messages, messages entering the conversation or logged unanswered, turn start, cancel, ready) to a `ui::Render`. Two renderers:
  - Plain (stdin or stdout not a terminal): the former printer, byte-identical output. One message per stdin line; lines arriving together form one message, joined by a blank line. At end of input on a pipe the chat finishes its queued turns first.
  - TUI (both terminals): inline viewport, not alt-screen; finished lines go into the terminal's native scrollback (codex `insert_history` pattern, own diffing terminal over the ratatui backend), a bottom pane holds the streamed line being written, queued messages, the composer and a status bar (model, effort, priming state/age, compactor calls, last turn usage; spinner/elapsed while a turn runs, "waiting for N summaries"). Own multiline soft-wrapping composer: Enter sends, Shift/Alt-Enter or Ctrl-J newline, bracketed paste is exactly one message, session input history, Emacs keys. Ctrl-C (a key in raw mode) cancels as before, Ctrl-D on an empty composer exits; SIGTERM/SIGHUP exit. Typing during a turn sends mid-turn and shows as queued until taken. Assistant text renders as markdown (pulldown-cmark; complete lines only; syntect-highlighted code); tool calls are one line with their telling argument, results 3 lines with error status. Resize follows the cursor the terminal moved; the terminal is restored on every exit path, panics included. Screen tests on ratatui's `TestBackend` cover the pane, history cells, scrollback insertion and markdown streaming in arbitrary pieces; pty tests in the root suite cover a closed terminal and SIGTERM idle, priming and mid-turn.
- Ctrl-C cancels the turn or its summary/priming wait; the cancelled call's remaining events are still logged, untaken messages logged unanswered. No background tasks or subagent tools in v1. Not in the TUI: Ctrl-Z suspend, persistent input history, light-theme code colours, tables.
- Permission mode `dontAsk`; allowlist Bash, Read, Edit, Write, Glob, Grep, WebFetch, WebSearch and memory zoom/date. System prompt freezes MASTER + VIEW_DOC + global CLAUDE.md + repository-root AGENTS.md at startup. COMPACT unchanged.
- Both master and primer share argv, model, effort, tool list and prompt file. Priming marks view blocks at 50k/80k/100k characters and view end; real turns use identical blocks without marks and remove inherited `DISABLE_PROMPT_CACHING`. Usage is printed for turns (input/read/write/output) and priming (read/write).
- `ai memory zoom id+n [part]` pages long results by `PART_CHARS`. MCP zoom pages at at most 29,000 UTF-8 bytes plus its continuation notice, keeping output below CAP. Raw storage and compactor input remain whole.
- The chat waits for `compact.lock` held by a nap. It blocks until an event or the nearest deadline (no polling); compactor jobs wake it, and other sessions' notes are absorbed when a turn is about to start. A note arriving while priming forces a new settled view before the turn. Settling prints "waiting for N summaries". Control characters in model/tool output are dropped before printing.
- Linux Claude children have their own process group and `PR_SET_PDEATHSIG=SIGKILL`. Normal teardown sends group SIGTERM, waits at most 200 ms, then kills/reaps; terminal events kill the group immediately in the stdout reader to prevent same-context follow-up turns. Dropping the compactor closes its child registry and kills existing calls, including a concurrent spawn. Abrupt parent SIGKILL guarantees only the direct Claude child dies; descendants may survive even in the same process group. Normal teardown covers descendants remaining in the owned group.
- `nap` builds a fresh backend each round (a dropped compactor stops its backend for good).
- Verified with fake Claude: fresh turns, stream logging, replay/requeue, priming success/failure/schedule, paging/MCP, external notes during priming, cancelled settling and turns, paste with pipe end, blocked stdin, ignoring SIGTERM, process-group descendants, first-result timing, parent death; recorded real streams replayed through the mapper; a root end-to-end test with a fake `claude` on PATH checks argv parity, env, allowlist, MCP config, prompt order and marks.
- Live smoke (sonnet, temp memory, 60 notes, tree pre-built): one prime (0 read, 13,788 write) then one turn (4 in, 27,371 read, 390 write, 80 out, 2.4 s); the turn called `mcp__memory__zoom` and logged user/tool/echo/talk as `ai-chat`.

## Stage 2 decisions (user, 2026-10-04)

- System prompt = MASTER + VIEW_DOC + the user's global instructions + the AGENTS.md of the repo `ai chat` starts in (none outside a repo). Read once at start, byte-identical for the whole chat; edits take effect on restart.
- `zoom id+1` is capped and paged, like `grep`.
- Child hygiene: `claude` children die with the chat (PR_SET_PDEATHSIG); dropping the compactor kills its running calls.
- No fsync: git objects + ref update suffice on one machine.
- `nap.log` is kept whole: a few lines per run.
- Compactor lock race fixed: after any note commit the memory ends compacted with no further trigger.
- Compaction cost on the subscription: measure in the first week of use.
- MASTER drops the spec's subagent paragraph: v1 has no subagents or background work, and every command ends with the turn (user, 2026-10-05).
- MASTER tells the agent the chat is its memory and not to run `ai memory`: the global CLAUDE.md (included because Claude Code is the harness) says to run `wake` in every session (user, 2026-10-05).
- COMPACT and VIEW_DOC describe `note` as "notes recorded by other agent sessions" (spec: "memories from before this chat"): notes arrive from parallel sessions during the chat.
