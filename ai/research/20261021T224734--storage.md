# Storage

Author: Claude Code (Claude Opus 5.5)

This is a design for review, and nothing in it is implemented. Facts about today's code are from main `ba7e120f`. Ids, handles and project ids are in `ai/research/20261021T194314--ids-handles-and-paths.md`. Points marked **Recommended** await the user's confirmation; the rest is agreed.

## Today

- **Chat:** `~/.ai/chat/<root commit>/` holds plain files with no history: per thread `items.jsonl`, `lines.jsonl`, `sessions.jsonl`, `agents.jsonl`, `calls/`, and `sources/` with byte-exact copies of the session files. Locks and logs sit beside them. The project id is the repo's root commit, cached in the repo's `.git/config` as `ai.root`. `ai.chat.model` and `ai.chat.background` live in the repo's git config.
- **Memory:** `~/.ai/memory` is a bare git repo with one commit per change. Its settings (`viewLines`, `entryChars`) and its id (`origin`) are in that repo's git config. `usage.jsonl`, `calls/`, logs and locks sit loose in its git directory.
- **Notes:** `~/.ai/notes` is a git repo with a worktree and one commit per change.
- **Size:** a long session's transcript copy reaches tens of MB, and it grows on every sync.

## Rules

1. Nothing `ai` stores goes in a repo's `.git`: no config keys, refs or commits. `ai` reads git through `gix`.
2. `~/.ai` is one git repo. Memory and notes are JSONL files in it. Its history is how a corrupted store is reverted.
3. A repo-local `.ai/` holds one user's private data for the repo, in the main checkout: its agents' threads in `.ai/agents/` and its `ai files` summaries in `.ai/files/`. `ai init` adds `/.ai/` to `.gitignore`, so the project's git never tracks it. `.ai/` is its own git repo, for history: each command that writes there commits once.
4. Summaries are not shared. A feature branch's summaries could not be merged with another's. Sharing can come later, as a deliberate export.
5. Memory stays in `~/.ai`, shared by every project.
6. `ai` never commits in a project repo, since commits live in `.git`.

## Layout

```
~/.ai/
  .git/
  .gitignore
  memory/...
  notes/...

<repo>/.ai/             (gitignored by the project; its own git repo)
  .git/
  .gitignore            (*.lock, *.log)
  agents/threads/<thread>/...
  files/summaries.jsonl, calls/
```

`<repo>/.ai/` is built: the first write makes the repo and its `.gitignore`, and each command that writes commits the whole work tree once (`ai agent new dev`, `ai agent sync-session`, `ai files build`), with no commit when nothing changed. A file whose stat matches the index keeps its blob unread, so a commit costs a walk of the store, not a hash of it. It does not split files into segments yet: a sync that grows a 37 MB transcript copy writes the whole copy again as a new loose object, until git packs it.

## Writing to `~/.ai`

**Recommended:**

- **One store lock.** A write takes `~/.ai`'s lock, changes its files, commits, and releases the lock.
- **Commits through `gix`, never git's index.** A write names the paths it changed. The commit edits HEAD's tree at those paths, writes the commit and moves the ref. Concurrent sessions never meet on `index.lock`, and no write hashes the whole store.
- **One commit per write:** each memory note, each chat sync, each note change. Any write can be reverted. The message names the command, such as `memory note 617` or `chat sync ai-chat`.
- **Small files.** Git keeps each version of a file whole until it packs. A commit per sync of one growing 30 MB transcript would add a new 30 MB object each time. So append-only data goes into segments: an append lands in the open segment, and a segment closes at a fixed size (say 1 MB) and never changes again. This covers transcript copies, `items.jsonl` and memory messages. One file per session splits data further.
- **Ignored:** locks, pid files and logs. **Committed:** everything else, summary lines included, since rebuilding them costs model calls. `calls/` and `usage.jsonl` are kept as written.
- **Local only.** A remote for `~/.ai` would carry transcripts and memory alike. `~/.ai` stays local unless the user names a private remote.

## Moving today's stores

**Recommended:** one move, no elaborate migration.

- **Memory:** messages export once to JSONL in `~/.ai/memory/`. The old repo's commit history isn't carried over. Its settings move to `ai.toml`.
- **Memory's id:** `origin` is not a git remote. It is the memory store's id: random, minted when the store is created, never changed, and recorded on every memory note. It lives in `~/.ai/memory/origin`, and `~/.ai` carries it along with the notes. Upgrading means copying it there by hand once.
- **Agents:** `~/.ai/chat/<project>/` moves to `<repo>/.ai/agents/`, unchanged inside.
- **File summaries:** `~/.ai/files/<project>/` moves to `<repo>/.ai/files/`, unchanged inside.
- **Notes:** no live store exists, so nothing moves.
- **Repo git config:** `ai.root`, `ai.chat.model` and `ai.chat.background` move to `ai.toml`. `ai` deletes nothing from a repo's `.git/config`; the user removes the old keys.

## Open questions

1. **`ai.toml`:** at the repo root (like `Cargo.toml`) or inside `.ai/`? The user's own file in `~/.ai` (committed with the store) or in `~/.config/ai/`?
2. **What moves to `.ai/`:** settled by rule 3: `.ai/` is private and gitignored, so no tracked notes move there. Before that: `ai/` has `research/`, `comments/`, `evals/`, `backlog.md`, `glossary.md` and `spec.md`; there is no `ai/analysis`. Does all of `ai/` move, or only the notes? `AGENTS.md` and the global agent instructions name `ai/comments/` and `ai/research/`, so they change with it.
3. **`ai files` summaries:** settled by rules 3 and 4: in the repo's private `.ai/files/`, not shared.
4. **Byte-exact copies:** `ai/spec.md` promises byte-for-byte copies of session files. Segments keep every byte, and joining them gives the original. Does the guarantee need one file per session?
5. **Interrupted writes:** a crash after changing a file but before committing leaves the change uncommitted. Should the next write fail naming it, or commit it?
