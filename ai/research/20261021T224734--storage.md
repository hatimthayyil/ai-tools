## Today

- **Agents:** `~/ai/projects/<project>/agents/`, format 6 (src/agent/store.rs, `Store::root`). A project's folder is the one of `~/ai/projects/` whose `id` file holds the project's id, whatever its name, else `projects/<name>`, made and claimed on the first write (`Project::claim`); a name another id holds is refused. `~/ai` is one git repository, made when `ai` first writes to it; events commit the project's folder alone, through gix, under one lock, editing HEAD's tree at that folder and only that folder's index entries (`repo::commit_paths`); past `[agent] gc-after-mib` of loose objects written since the last one, a commit starts `git gc` in the background (`repo::gc`). Each thread, `threads/<name>/`, holds its items, lines, session tracks, attachment changes (`attachments.jsonl`), subagents, calls and `sources.jsonl`: per session file it read, the harness, the path from the harness's home (`$CLAUDE_CONFIG_DIR` or `~/.claude`, pi's and DSH's homes), the length and git blob id, in place of a copy. A sync fails, naming the file and the backup to restore it from, when a recorded file is gone or the transcript no longer begins with its recorded bytes; a companion file that changed is recorded again. The threads' locks and compactor logs, and the sessions' locks, are in `~/.ai/agents/<project id>/`. The private settings are `~/ai/projects/<project>/ai.toml`, linked from `<repo>/ai.local.toml`. Rule 10 replaces the records of live harness files with pointers into the archive.
- **Moving older stores:** `.ai/local/` in a project's home, where ai up to 0.17 kept the agents (format 4) and private settings, is refused until moved (src/agent/convert.rs). Each file it kept as a directory of 1 MiB segments becomes one file of the same bytes. On a terminal, `ai agent`, `ai resume` and `ai init` offer the move. It locks the old threads' writers, archives `.ai/local/` whole (git history included) in `~/.ai/archive/<project id>/<stamp>--local` and checks the copy byte for byte, moves the private settings and other files (evals) into the project's folder, builds the new store beside its place and renames it in, removes `.ai/local/` and commits. Each copied session file whose harness file still begins with it becomes a record of that file; one the harness lost is restored at its path, and one the harness changed into `<session>/restored/` beside the transcript, which every sync reads. A move cut short is finished by the next, reusing its archive. Rule 14 keeps `.ai/local/`: the move takes only threads and private settings.
- **Memory:** `~/.ai/memory` is a bare git repository with one ref, `refs/ai/memory`: `log/` holds one file per note (1,100 notes, 503 KB), `trees/1` and `trees/2` the summary trees (about 2 MB). The ref has 3,452 commits; the repository's objects take 210 MB. `calls/` (36 MB of summariser calls), `usage.jsonl`, logs and locks sit loose in it. Its id is `~/.ai/memory/origin`.
- **The user's settings:** `~/.ai/ai.toml`.
- **Harness files:** each harness writes its own folders: Claude Code `~/.claude/projects` (`~/.claude` is a link through the Nix store into the config repo), Codex `~/.codex/sessions`, pi, DSH, Gemini, opencode and Hermes their own. `ai harness` (src/harness/) keeps each at `~/.ai/harness/<harness>/<path>`, linked from where the harness looks. `link` makes absent folders as links and never moves data; `move` moves a folder only while no process of its harness runs and none has a file in it open (read from `/proc`), copying it, checking every entry's kind, mode, size and SHA-1 (collision-checked, as git hashes), swapping in the link, and reading it back; the original stays as `<folder>.moved-to-ai` beside a record of every entry's hash, `<place>.move.json`, and goes 14 days later if it still matches that record. ai-tools' Home Manager module (`homeModules.default`, `services.ai-harness`) runs `link` on every switch and `move` from a user unit started at boot, which no login waits for. Nothing has been moved: `~/.ai/harness` does not exist. Rule 9 replaces `ai harness` with `ai archive`.
- **Harness databases:** OpenCode keeps its transcripts in SQLite, `opencode.db` (`session` and `message` tables, 14.5 MB), and so does Hermes, `state.db` (`sessions` and `messages`, 0.5 MB, beside `kanban.db`). Codex writes JSONL sessions in `~/.codex/sessions`, beside `thread_history_1.sqlite` (34 MB), `state_5.sqlite` and `logs_2.sqlite` (63 MB of logs). Claude Code, pi and DSH keep none; the `.db` files in `~/.claude/context-mode/` belong to the context-mode plugin.
- **Config errors:** a broken setting fails only the commands that read its table (src/config.rs, `fix(config)` on this branch). A file that is not TOML, an unknown table name, or `[project]` in the user's or private file still fails every table read from that file, since what the file meant to set is unknown.

## Rules

**Agreed**

1. **Five places, one role each.**
   - `~/ai`: what is the user's on every machine, in a git repository the user keeps as they keep `config`: every thread, user-level and every project's; memory, its notes and summary trees; each project's private settings. Small text. It is what a new machine needs.
   - **The store:** raw bytes, encrypted, off the machine: transcript pieces and database snapshots (rule 11).
   - `~/.ai`: this machine only, never in git: the archive's disk copy, locks, logs, caches, settings that belong to this machine.
   - `<repo>/.ai/local`: one project's private working data, kept beside its code: evals, datasets, experiment output. The project's git ignores it; it is a git repository of its own, and reaches another machine only through a remote the user gives it.
   - `<repo>/ai`: the project's parts that can be public, the agents' visible workspace.

   The test: what is about the user and their agents goes in `~/ai`; what the project's work produced goes in `.ai/local`.
2. **Every transcript is stored in `~/.ai` and stays recoverable**, also for an agent running in a sandbox: the archive holds it (rule 8).
3. **A project repo tracks only what the project shares:** `ai/`, the agents' visible workspace; `.ai/`, hidden, less `.ai/local/` (rule 1); and the tracked `ai.toml`, with the project's own settings and its in-repo hierarchy. User-level details never enter what the project tracks: no threads, no private settings, no address of another project's agent or of a user-level agent.
4. **Agents never touch git.** A sandbox gets its own thread's files read-write and its subordinates' read-only, never `~/ai/.git`. Only `ai` running outside every sandbox commits. One repository per thread is undone: it existed only to hand a sandbox one thread's git.
5. **Nothing `ai` stores goes in a project's `.git`**: no config keys, refs or commits. `ai` reads git through `gix` and never commits in a project repo.
6. **A broken setting fails only the commands that read it**, directly or through others. Nothing guesses past a bad value.
7. **`~/ai/projects/` lists every project.** No separate registry exists.
8. **The archive.** `ai` alone writes `~/.ai/archive`, from outside every sandbox; no sandbox sees it. It only grows. Transcripts go in as 1 MB pieces; a full piece is sealed, named by its hash, and never changes. A harness or agent that deletes or rewrites a file leaves its archived bytes in place. The archive is an object store: the same names on disk and in the store, behind one interface with a local-folder backend and an S3 backend (the `object_store` crate's `LocalFileSystem` and `AmazonS3`), and no local server.
9. **`ai archive` writes the archive.** It replaces `ai harness`: `~/.ai/harness` is dropped, and harness files stay where each harness writes them. A user service outside every sandbox watches each harness home, in its real folders and never through the Nix store, and copies new bytes into the archive as they appear; on start it catches up by comparing each file's length with what is archived. Which harnesses, and which kinds of their data, it archives is harness-specific logic in `ai archive`; its parameterisable parts may become config keys later. A database goes in as a whole snapshot taken with SQLite's backup API, named by its hash; for OpenCode and Hermes that snapshot is the transcript.
10. **Threads point at archive pieces**, never at live harness files and never at copies of their own. `~/ai` stays small and its remote carries no transcript. On a fresh machine, items, summaries and views work from a clone of `~/ai`, and the raw pieces come from the store.
11. **The store.** `ai` has its own S3-compatible store, R2 for now. Each sealed piece and snapshot is encrypted on this machine before upload, uploaded once, and kept by an R2 bucket lock that refuses deletes and overwrites. The key is kept in pass on `eagle`, for now. `ai resume` refuses to start a sandboxed agent unless `ai archive` runs and a store is configured; every other command keeps working without one and shows the upload backlog.
12. **A project's name is unique in `~/ai/projects/`.** A second project with a name another project holds is refused, and told to set `[project] name`.
13. **Memory lives in `~/ai/memory`**, its notes and its summary trees.
14. **The move from `.ai/local` takes only threads and private settings.** The rest of `.ai/local` stays where it is.

## Layout

**Recommended**

```
~/ai/                          git; the user's
  ai.toml                      the user's settings and user-level agents
  memory/                      memory notes and summary trees
  agents/<name>/               user-level threads (root, the companions)
  projects/<project>/
    ai.toml                    the project's private settings
    agents/<name>/             the project's threads

~/.ai/                         this machine only; never git
  ai.toml                      this machine's settings
  archive/                     the archive's disk copy (rule 8)
  locks, logs, caches

<repo>/
  ai/                          tracked; can be public
  .ai/                         tracked
  .ai/local/                   ignored; a git repository of its own; private working data
  ai.toml                      tracked
  ai.local.toml                gitignored link to ~/ai/projects/<project>/ai.toml
```

- `ai init` keeps `ai.local.toml` as a gitignored link, so the project's private settings stay at hand in the repo while their file lives in `~/ai`.
- A thread keeps its items, lines, session tracks, attachment changes, subagents, calls and pointers into the archive (rule 10), each a JSON Lines file. gix stores every version of a file whole, so after a commit `ai` starts `git gc` on `~/ai` in the background once the loose objects written since the last one pass `[agent] gc-after-mib` (32 MiB by default, `repo::gc`), which packs a grown file's versions against each other.

## Writing to `~/ai`

**Recommended**

- **Commits through `gix`.** A commit names the paths it covers, a project's folder; it edits HEAD's tree at those paths, writes the commit, moves the ref, and updates only those paths' index entries, so what the user staged elsewhere stays staged and `git status` stays clean. Built (`repo::commit_paths`).
- **One store lock** serialises commits to `~/ai`. Built.
- **Who commits:** `ai` outside every sandbox: the user's own commands, those the desk runs, and the `ai resume` process that launched a sandboxed agent, which commits what its agent wrote. Inside a sandbox `~/ai/.git` does not exist, and `ai` writes its files without committing.
- **When:** memory notes commit each write. A thread commits on events, as today: `ai agent new`, `attach`, `detach`, `resume`, a build, a session's end. A turn's sync and the background summariser write without committing; the next event carries what they wrote.
- **Ignored:** locks, pid files and logs, which live in `~/.ai` anyway.
- **Remote:** `~/ai` gets whatever remote the user gives it; it carries no transcript (rule 10).

## Moving today's stores

**Recommended:** one conversion, detected and offered with a yes/no prompt, as `ai` offers store upgrades.

- **Threads:** `<repo>/.ai/local/agents/threads/*` move into `~/ai/projects/<project>/agents/`. Built ("Today"), with the old store copied whole to `~/.ai/archive/` (open question 4).
- **Private settings:** `<repo>/.ai/local/ai.toml` moves to `~/ai/projects/<project>/ai.toml`; `ai.local.toml` is relinked. Built.
- **The rest of `.ai/local`** stays (rule 14). Built code still moves it and removes `.ai/local`.
- **Memory:** `~/.ai/memory`'s notes and summary trees move into `~/ai/memory/` (rule 13); its history is open question 1.
- **The user's settings:** `~/.ai/ai.toml` moves to `~/ai/ai.toml`, less any setting that belongs to this machine.

## Open questions

1. **Memory's history.** `~/.ai/memory`'s objects take 210 MB, against 503 KB of notes and about 2 MB of trees today. Measure what fills them before choosing whether `~/ai` carries that history.
2. **Interrupted writes.** A crash after changing a file but before committing leaves the change uncommitted. As built, the next commit takes the folder as it is on disk. Should it instead fail naming the change?
3. **A project folder's name after a rename.** A folder is found by its id, so a project whose `[project] name` changes keeps its old folder, and addresses that use the name drift from it. Rename the folder with the project, or let addresses use the folder's name?
4. **Conversion backups.** The move from `.ai/local` copies the old store whole to `~/.ai/archive/<project id>/<stamp>--local`. With `~/.ai/archive` the archive, that copy needs another place, or becomes archive entries.
5. **Snapshot timing.** Proposed: a database is snapshotted at most every few minutes, and at session end.
6. **Several machines writing at once:** in the backlog (`ai/backlog.md`).
