## Today

- **Agents:** `<repo>/.ai/local/agents/`, format 5 (src/agent/store.rs, `Store::root`). Each thread, `threads/<name>/`, is a git repository of its own, committed on events, holding its items, lines, session tracks (`attachments.jsonl`), subagents, calls, and `sources/`: byte-exact copies of its attached sessions' transcripts, split into 1 MiB segments that join to the original (src/segments.rs). Sessions never attached to a thread are copied nowhere. The project's private settings are `.ai/local/ai.toml`, linked from `<repo>/ai.local.toml`. Stores of format 4 are refused until a conversion lands.
- **Memory:** `~/.ai/memory` is a bare git repository; notes and summary trees live under `refs/ai/memory`. `calls/`, `usage.jsonl`, logs and locks sit loose in it. Its id is `~/.ai/memory/origin`.
- **The user's settings:** `~/.ai/ai.toml`.
- **Harness files:** each harness writes its own folders: Claude Code `~/.claude/projects` (inside the config repo), Codex `~/.codex/sessions`, pi, DSH, Gemini, opencode and Hermes their own. `ai harness` (src/harness/) keeps each at `~/.ai/harness/<harness>/<path>`, linked from where the harness looks. `link` makes absent folders as links and never moves data; `move` moves a folder only while no process of its harness runs and none has a file in it open (read from `/proc`), copying it, checking every entry's kind, mode, size and SHA-1 (collision-checked, as git hashes), swapping in the link, and reading it back; the original stays as `<folder>.moved-to-ai` beside a record of every entry's hash, `<place>.move.json`, and goes 14 days later if it still matches that record. ai-tools' Home Manager module (`homeModules.default`, `services.ai-harness`) runs `link` on every switch and `move` from a user unit started at boot, which no login waits for.
- **Config errors:** a broken setting fails only the commands that read its table (src/config.rs, `fix(config)` on this branch). A file that is not TOML, an unknown table name, or `[project]` in the user's or private file still fails every table read from that file, since what the file meant to set is unknown.

## Rules

**Agreed**

1. **Two homes.**
   - `~/ai` is a git repository the user keeps, as they keep `config`: every thread, user-level and every project's; each project's private settings; memory notes; other data. It is what a new machine needs.
   - `~/.ai` holds what belongs to this machine and never goes in git: `harness/<harness>/`, the raw files each harness writes, linked from the harness's own path; locks; logs; settings that belong to this machine.
2. **Every transcript is stored in `~/.ai` and stays recoverable**, also for an agent running in a sandbox.
3. **A project repo holds only what the project shares:** `ai/`, the agents' visible workspace; `.ai/`, hidden; and the tracked `ai.toml`, with the project's own settings and its in-repo hierarchy. `<repo>/.ai/local` goes away. User-level details never enter what the project tracks: no threads, no private settings, no address of another project's agent or of a user-level agent.
4. **Agents never touch git.** A sandbox gets its own thread's files read-write and its subordinates' read-only, never `~/ai/.git`. Only `ai` running outside every sandbox commits. One repository per thread is undone: it existed only to hand a sandbox one thread's git.
5. **Nothing `ai` stores goes in a project's `.git`**: no config keys, refs or commits. `ai` reads git through `gix` and never commits in a project repo.
6. **A broken setting fails only the commands that read it**, directly or through others. Nothing guesses past a bad value.
7. **`~/ai/projects/` lists every project.** No separate registry exists.
8. **Backup:** restic backs `~/.ai` up to an R2 bucket, run by a timer the config repo declares. Restic encrypts, uploads only what changed (an appended transcript sends only its new chunks), and keeps snapshots, so a file deleted or overwritten can be restored. borg 1.x cannot write to S3 storage such as R2, and borg 2 is still beta (config repo `ai/research/20261008T215024---agent-transcript-preservation.md`). Not started; the user says when.
9. **`ai` keeps the harness files**, as `ai harness`, since `ai` owns `~/.ai`; its boot unit comes from ai-tools' Home Manager module. A move runs at boot only, and never holds up a login.

## Layout

**Recommended**

```
~/ai/                          git; the user's
  ai.toml                      the user's settings and user-level agents
  memory/                      memory notes
  agents/<name>/               user-level threads (root, the companions)
  projects/<project>/
    ai.toml                    the project's private settings
    agents/<name>/             the project's threads

~/.ai/                         this machine only; never git
  ai.toml                      this machine's settings
  harness/<harness>/...        raw harness files
  locks, logs

<repo>/
  ai/                          tracked
  .ai/                         tracked
  ai.toml                      tracked
  ai.local.toml                gitignored link to ~/ai/projects/<project>/ai.toml
```

- `ai init` keeps `ai.local.toml` as a gitignored link, so the project's private settings stay at hand in the repo while their file lives in `~/ai`.
- A thread keeps today's files (items, lines, session tracks, subagents, calls, `sources/` per open question 1), each growing file a directory of 1 MiB segments, so a commit stores at most one open segment per file.

## Writing to `~/ai`

**Recommended**

- **Commits through `gix`, never git's index.** A write names the paths it changed; the commit edits HEAD's tree at those paths, writes the commit and moves the ref. Concurrent `ai` processes never meet on `index.lock`, and no commit hashes the whole repository.
- **One store lock** serialises commits to `~/ai`.
- **Who commits:** `ai` outside every sandbox: the user's own commands, the desk, and the `ai resume` process that launched a sandboxed agent, which commits what its agent wrote. Inside a sandbox `~/ai/.git` does not exist, and `ai` writes its files without committing.
- **When:** memory notes commit each write. A thread commits on events, as today: `ai agent new`, `attach`, `detach`, `resume`, a build, a session's end. A turn's sync and the background summariser write without committing; the next event carries what they wrote.
- **Ignored:** locks, pid files and logs, which live in `~/.ai` anyway.
- **Remote:** `~/ai` gets whatever remote the user gives it. What that remote then carries depends on open question 1.

## Moving today's stores

**Recommended:** one conversion, detected and offered with a yes/no prompt, as `ai` offers store upgrades.

- **Threads:** `<repo>/.ai/local/agents/threads/*` move into `~/ai/projects/<project>/agents/`. Every old commit stays reachable.
- **Private settings:** `<repo>/.ai/local/ai.toml` moves to `~/ai/projects/<project>/ai.toml`; `ai.local.toml` is relinked.
- **Memory:** `~/.ai/memory` moves into `~/ai/memory/` (open question 4).
- **The user's settings:** `~/.ai/ai.toml` moves to `~/ai/ai.toml`, less any setting that belongs to this machine.

## Open questions

1. **Raw transcript copies in `~/ai`.** A thread either:
   - keeps byte-exact copies of its sessions, as `sources/` does today: a clone of `~/ai` is self-contained, but it grows without bound, and every secret pasted into a session goes to `~/ai`'s git remote; or
   - points at `~/.ai/harness` by relative path, byte range and hash: `~/ai` stays small and holds no transcript secrets, but on a fresh machine the raw files resolve only once `~/.ai` is restored from the R2 backup. Items, summaries, views, zoom and grep work from `~/ai` alone; what needs the raw files is rebuilding items from transcripts, and byte-exact recovery. `ai` names a missing or changed raw file, never reads past it.
2. **Two projects with the same name.** Addresses use the project's name (`main@quranics`), and `~/ai/projects/` keys each project. Two repos named alike, such as a second clone, would claim one folder: refuse the second until one is renamed, or key folders by project id and refuse the name only in addresses.
3. **Memory's history.** `~/.ai/memory` is a git repository of its own, with its notes and summary trees under `refs/ai/memory`. In `~/ai` its refs either join `~/ai`'s repository, or memory stays a repository of its own inside `~/ai`, ignored by `~/ai`'s git.
4. **Interrupted writes.** A crash after changing a file but before committing leaves the change uncommitted. Should the next commit take it, or fail naming it?
