# ai chat and pi-blackhole comparison

Author: Codex (GPT-6)

They behave similarly during compaction: both shrink active context and provide routes back to retained evidence. **`ai chat` is the better foundation for persistent, named conversations with hierarchical recovery. Pi-blackhole offers more developed controls for live Pi context.** Borrow its deterministic coverage, retrieval budgets and recent-context policies while keeping chat’s thread graph and summary tree. These are architectural judgments; **no head-to-head benchmark establishes superior continuation quality, latency or cost.** ([Chat product](/hatimthayyil/code/ai-tools/README.md:46), [Blackhole pipeline](/hatimthayyil/code/pi-blackhole/docs/vcc-compaction.md:1), [recall](/hatimthayyil/code/pi-blackhole/docs/recall.md:1))

**Retained evidence and model context have different fidelity.** Pi keeps original session JSONL while projecting shortened tool output and memory into context. Chat stores original JSON lines for recognised items in immutable Git snapshots, but excludes thinking-only, injected and unknown events that emit no item; malformed records can disappear silently. Its archive therefore preserves a selected transcript projection. Both systems’ summaries are lossy, and source availability alone establishes neither automatic recall nor faithful continuation. Chat’s custom refs also need an explicit backup/export contract. ([Pi projection](/hatimthayyil/code/pi-blackhole/docs/CONFIG.md:240), [chat filtering](/hatimthayyil/code/ai-tools/src/chat/claude.rs:172), [archive review](/hatimthayyil/code/ai-tools/ai/research/20261016T212002--chat-review.md:41), [ref transport](/hatimthayyil/code/ai-tools/ai/research/20261014T002322--chat-design.md:113))

Optional Pi memory workers add calls and quota usage; dollar billing depends on the account/provider. They can use the session model and its configured authentication. Blackhole’s deterministic baseline consequently says little about total running cost with memory enabled. ([Model/auth resolution](/hatimthayyil/code/pi-blackhole/src/om/runtime.ts:493))

**Fix chat’s existing state contracts before expanding integrations:** stale syncs can regress tips, attachment moves lack atomic ownership, and continuations can change branch with ambient session state. The previous review reproduced these defects; current source still contains their mechanisms. This comparison adds no new execution probes. ([State findings](/hatimthayyil/code/ai-tools/ai/research/20261016T212002--chat-review.md:9), [query findings](/hatimthayyil/code/ai-tools/ai/research/20261016T212002--chat-review.md:23))

Then prioritise these improvements:

1. **Guarantee useful coverage before summarisation.** Produce bounded structural lines containing user wording, files, tool/result status and source IDs immediately; enrich them asynchronously. Chat currently permits `(not summarised yet)` for closed turns. Blackhole’s compiler demonstrates an always-available structural path, although extraction alone misses semantics. Track examined source explicitly. ([Chat fallback](/hatimthayyil/code/ai-tools/src/chat/view.rs:396), [compiler](/hatimthayyil/code/pi-blackhole/src/core/summarize.ts:372))

2. **Budget every retrieval response and provide stable paging.** Cap rendered `view`/`zoom`/`grep` output, expose omissions and emit continuations bound to thread, snapshot and branch. Blackhole’s recall tool caps output at 48,000 characters and supports drill-down; its local recall command bypasses that total cap, so adopt the bounded tool contract across all context-entry paths. ([Recall budget](/hatimthayyil/code/pi-blackhole/src/core/recall-budget.ts:16), [command caveat](/hatimthayyil/code/pi-blackhole/src/commands/vcc-recall.ts:7), [chat cursor defect](/hatimthayyil/code/ai-tools/src/chat/cli.rs:589))

3. **Preserve a recent raw suffix independently of older summaries.** Keep complete recent assistant/tool exchanges within a budget. Chat’s user-message rail and clipped latest turn can lose immediate working detail when the preceding assistant turn enters the fold. Blackhole exposes useful minimal-tail and Pi-default policies. ([Chat closure/rendering](/hatimthayyil/code/ai-tools/src/chat/view.rs:323), [Pi cut selection](/hatimthayyil/code/pi-blackhole/src/hooks/before-compact.ts:170))

4. **Make pressure and work budgets token-aware.** Derive limits from the active model window and reserved headroom; expose backlog and estimated usage. Chat uses byte/line targets. Blackhole offers ratio/reserve policies, but estimates tokens and lets fixed thresholds override them. Adopt pressure awareness with explicit estimation limits. ([Chat budgets](/hatimthayyil/code/ai-tools/src/chat/view.rs:18), [Pi thresholds](/hatimthayyil/code/pi-blackhole/src/om/model-budget.ts:80), [estimator](/hatimthayyil/code/pi-blackhole/src/om/tokens.ts:18))

5. **Expose model failure and validate summaries before publication.** Report completeness, validate size/shape/source IDs, bound retries and cool down broken workers. Chat can return success after summary failure; Blackhole validates citations and worker structure, which still leaves factual accuracy unproven. Keep your Sonnet policy explicit; changing models through fallback requires agreement. ([Chat failure handling](/hatimthayyil/code/ai-tools/src/chat/cli.rs:351), [Pi validation](/hatimthayyil/code/pi-blackhole/src/om/agents/observer/agent.ts:145), [cooldown](/hatimthayyil/code/pi-blackhole/src/om/cooldown.ts:171))

6. **Strengthen provenance while retaining the archive and tree.** Capture complete source before filtering, key summaries by exact source spans and recipe versions, and advance coverage only over examined input. Local Blackhole’s newest-first observer can skip older material; upstream 0.5.13 documents stronger backlog draining/checkpointing. Borrow those invariants. Keep permanent facts in the existing `ai memory` system; another observational ledger would add overlapping authority and worker complexity.
